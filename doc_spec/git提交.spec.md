# Git 提交规范

## 提交消息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 格式说明

- **type**: 提交类型（必填）
- **scope**: 影响范围（可选）
- **subject**: 简短描述（必填，不超过 50 个字符）
- **body**: 详细描述（可选）
- **footer**: 关联信息（可选）

## 语言与编码

- **提交说明使用中文**：subject、body、footer 均使用中文书写，与项目文档保持一致。
- **避免乱码**：
  - 提交信息文件与终端使用 **UTF-8** 编码。
  - 在 Windows 下若终端直接输入中文易乱码，可用 **从文件读取**：先将提交信息写入 UTF-8 文本文件（如 `doc_spec/.commit-msg.txt`），再执行 `git commit -F doc_spec/.commit-msg.txt`；提交完成后删除该临时文件。
  - 可选：在本仓库配置编码，避免 log 显示乱码：
    - `git config i18n.commitEncoding utf-8`
    - `git config i18n.logOutputEncoding utf-8`

## 提交类型（type）

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | feat: 添加用户登录功能 |
| `fix` | 修复 bug | fix: 修复登录页面样式错乱 |
| `docs` | 文档更新 | docs: 更新 API 文档 |
| `style` | 代码格式调整（不影响功能） | style: 统一代码缩进格式 |
| `refactor` | 重构代码（不是新增功能或修复） | refactor: 优化数据获取逻辑 |
| `perf` | 性能优化 | perf: 优化图片加载速度 |
| `test` | 测试相关 | test: 添加单元测试 |
| `chore` | 构建过程或辅助工具的变动 | chore: 更新依赖包版本 |
| `revert` | 回滚提交 | revert: 回滚上一个提交 |

## 提交示例

### 简单提交
```
feat: 添加用户注册功能
```

### 带范围的提交
```
feat(auth): 添加第三方登录支持
```

### 带详细描述的提交
```
fix(api): 修复用户数据接口返回错误

- 修复用户 ID 为空时的处理逻辑
- 添加错误日志记录

Closes #123
```

### 重构提交
```
refactor(user): 重构用户模块代码结构

将用户相关功能拆分为独立模块，提高代码可维护性
```

## 提交规范要求

1. **Subject 要求**
   - 使用动词开头，使用现在时态（如「添加」而不是「已添加」）
   - 中文 subject 不必区分首字母大小写；若用英文则首字母小写
   - 结尾不加句号
   - 不超过 50 个字符

2. **Body 要求**
   - 使用现在时态
   - 说明「是什么」和「为什么」，而不是「怎么做」
   - 每行不超过 72 个字符

3. **Footer 要求**
   - 可以包含关联的 Issue 或 PR 编号
   - 可以包含 BREAKING CHANGE 说明

## 常见错误示例

❌ 错误示例：
```
添加了新功能
```
✅ 正确示例：
```
feat: 添加用户注册功能
```

❌ 错误示例：
```
Fix bug.
```
✅ 正确示例：
```
fix: 修复登录页面样式错乱
```

❌ 错误示例：
```
update
```
✅ 正确示例：
```
docs: 更新项目文档
```

## Git 忽略文件配置

项目已配置 `.gitignore` 文件，以下文件和目录将被 Git 忽略：

- `.claude/` - Cursor AI 相关文件
- `.idea/`、`.vscode/` - IDE 配置文件
- `node_modules/`、`vendor/` - 依赖目录
- `dist/`、`build/`、`target/` - 构建输出
- `.env`、`.env.local` - 环境配置文件（包含敏感信息）
- `.DS_Store`、`Thumbs.db` - 操作系统文件
- `*.log` - 日志文件

**注意**：如果某个文件已经被 Git 跟踪，需要先从 Git 中移除：
```bash
git rm --cached <文件路径>
git commit -m "chore: 从版本控制中移除敏感文件"
```

## 注意事项

- 提交说明使用中文，并注意 UTF-8 编码，避免乱码（参见上文「语言与编码」）。
- 每次提交应该是一个完整的、可理解的改动
- 避免一次提交包含多个不相关的改动
- 提交前确保代码通过测试和代码检查
- 保持提交历史清晰，便于代码审查和问题追溯
- 默认是生成git提交消息，不需要手动输入
- 提交消息的格式必须是根据当前约束生成的
- 提交消息的内容要简洁明了
- 生成之后只返回提交消息，不需要其他操作，直接复制到提交框中即可
- **不要提交 `.claude/` 目录**，该目录已在 `.gitignore` 中配置忽略

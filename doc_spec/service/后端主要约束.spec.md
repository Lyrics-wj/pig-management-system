# 后端生成代码规范约束

本文档约束 **service/** 目录下 Spring Boot + MyBatis/MyBatis-Plus 后端的代码生成与开发规范，与现有若依风格、分页方式及 Knife4j 文档保持一致。

**必须一起使用**：本文档须与以下文档一起使用，缺一不可，以保持前后端一致与数据/业务对齐：
- [整体规范](../项目整体.spec.md)
- [前端规范](../front/前端主要约束.spec.md)
- [现有数据库说明](../数据库.spec.md)
- [系统业务说明](../现有业务说明.spec.md)

---

## 一、技术栈与版本

### 1.1 固定技术栈

| 类型       | 技术/版本              | 说明 |
|------------|------------------------|------|
| JDK        | Java 8                 | 不得擅自升级 |
| Web        | Spring Boot 2.5.x     | 与父 pom 一致 |
| ORM        | MyBatis + MyBatis-Plus | 以现有 XML Mapper 为主，可渐进使用 MP |
| 分页       | PageHelper             | 保留 startPage() + getDataTable(list) |
| 接口文档   | Swagger3 + Knife4j     | 按环境开关，生产关闭 |
| 数据源     | Druid                  | 配置在 application-druid.yml |
| 安全       | Spring Security + JWT  | 与现有 Token 机制一致 |
| 校验       | javax.validation       | @Valid、@NotNull 等 |
| 日志       | SLF4J + Logback        | 使用 @Slf4j 与 log |

### 1.2 模块划分

- **ruoyi-admin**：启动入口、Swagger/Knife4j 配置、**所有接口入口（Controller 均在此模块）**、application.yml。
- **ruoyi-framework**：MyBatis/MyBatis-Plus 配置、Security、拦截器、AOP 等。
- **ruoyi-system**：系统管理业务（用户、角色、菜单、部门、岗位、字典、参数、通知等）的 Mapper、Service、Domain。
- **ruoyi-common**：分页工具（PageUtils）、BaseController、AjaxResult、TableDataInfo、PageDomain、TableSupport、通用注解、工具类。
- **ruoyi-quartz**：定时任务；**ruoyi-generator**：代码生成。

**约定**：所有 HTTP 接口入口（Controller）均放在 **ruoyi-admin** 中；业务实现（Service、Mapper）在各自业务模块（如 ruoyi-system、ruoyi-quartz、ruoyi-generator），由 admin 依赖并调用。

新增业务优先放在对应模块（如 system），或新建模块并依赖 ruoyi-common、ruoyi-framework。

## 二、分层与包结构

### 2.1 包命名约定

- **Controller**：`com.ruoyi.**.controller` 或 `com.ruoyi.web.controller.**`（如 system、monitor、tool）。
- **Service**：接口 `com.ruoyi.**.service`，实现类 `com.ruoyi.**.service.impl`。
- **Mapper**：接口 `com.ruoyi.**.mapper`，XML 在 `src/main/resources/mapper/**/*Mapper.xml`。
- **实体/DO**：`com.ruoyi.common.core.domain.entity`（公共实体）或 `com.ruoyi.**.domain`（模块内实体）。
- **配置**：`com.ruoyi.framework.config`、`com.ruoyi.web.core.config`。

### 2.2 分层职责

- **Controller**：接收请求、参数校验（@Valid、@NotNull）、调用 Service、返回统一结构（AjaxResult / TableDataInfo）；不写业务逻辑。
- **Service**：业务逻辑、事务（@Transactional）、权限/数据范围校验、调用 Mapper 或其它 Service。
- **Mapper**：数据访问；接口定义方法，复杂 SQL 写在 XML，简单 CRUD 可逐步使用 MyBatis-Plus BaseMapper。

## 三、Controller 规范

### 3.1 类与注解

- `@RestController` + `@RequestMapping("/模块/资源")`，如 `@RequestMapping("/system/user")`。
- 继承 `com.ruoyi.common.core.controller.BaseController`，以使用 `startPage()`、`getDataTable(list)`、`success()`、`error()`、`toAjax()` 等。
- 权限：在类或方法上使用 `@PreAuthorize("@ss.hasPermi('system:user:list')")`，与前端 `v-hasPermi` 一致。
- 操作日志：需要记录时使用 `@Log(title = "用户管理", businessType = BusinessType.XXX)`。

### 3.2 分页列表接口（必须与现有一致）

- 方法内先调用 `startPage()`（内部使用 PageUtils.startPage()，从 TableSupport 读取 pageNum、pageSize、orderByColumn、isAsc）。
- 再调用 Service 查询列表（如 `userService.selectUserList(user)`）。
- 返回 `getDataTable(list)`，得到 `TableDataInfo`（code、msg、rows、total）；total 由 PageHelper 的 PageInfo 提供。
- 不改变入参：前端传 `pageNum`、`pageSize`、`orderByColumn`、`isAsc` 及业务条件，后端用实体或 DTO 接收。

示例：

```java
@PreAuthorize("@ss.hasPermi('system:user:list')")
@GetMapping("/list")
public TableDataInfo list(SysUser user) {
    startPage();
    List<SysUser> list = userService.selectUserList(user);
    return getDataTable(list);
}
```

### 3.3 非分页接口

- 返回 `AjaxResult`：`return success();`、`return success(data);`、`return error("消息");`、`return toAjax(rows);`。
- 新增/修改：使用 `@RequestBody @Valid 实体或DTO`，校验失败由全局异常处理返回 400。

### 3.4 URL 与方法

- 列表：GET `/list`，参数为 query（绑定到实体或 DTO）。
- 详情：GET `/{id}` 或 `"/"` + `"/{id}"`，@PathVariable。
- 新增：POST `""`，@RequestBody。
- 修改：PUT `""`，@RequestBody。
- 删除：DELETE `"/{ids}"`，@PathVariable 或数组。

与前端 API 的 URL、Method、参数名保持一致。

## 四、Service 规范

### 4.1 接口与实现

- 接口：`com.ruoyi.**.service.IXxxService`，方法签名与 Controller 调用一致。
- 实现类：`@Service`，实现接口，方法上可加 `@Transactional(rollbackFor = Exception.class)`（写操作）。
- 数据权限：在需要数据范围的查询方法上使用 `@DataScope(deptAlias = "d", userAlias = "u")`，与现有 XML 中 `${params.dataScope}` 配合。

### 4.2 与 Mapper 的配合

- 分页查询：Service 直接调用 Mapper 的 list 方法（如 `userMapper.selectUserList(user)`），**不在 Service 里改分页逻辑**；分页由 Controller 的 `startPage()` + PageHelper 在 Mapper 执行时生效。
- 其它增删改：调用 Mapper 对应方法，返回影响行数时用 `toAjax(rows)` 返回。

### 4.3 业务校验

- 唯一性、状态、权限等校验在 Service 中做，不通过时抛 `ServiceException` 或返回明确错误信息，由全局异常处理或 Controller 转成 AjaxResult。

## 五、Mapper 与 MyBatis/MyBatis-Plus

### 5.1 现有约定（必须保留）

- Mapper 接口在 `**/mapper` 包下，方法名与 XML 中 `id` 一致。
- XML 位置：`classpath*:mapper/**/*Mapper.xml`，namespace 为 Mapper 全限定名。
- 实体类与表名、字段名映射：表名列名 snake_case，实体驼峰；复杂 resultMap 在 XML 中定义（如 SysUser 的 dept、roles）。
- 分页：不写 limit/offset，由 PageHelper 拦截器在 SQL 后追加；排序由前端传 `orderByColumn`、`isAsc`，在 Controller 中通过 `startOrderBy()` 设置 PageHelper.orderBy。

### 5.2 MyBatis-Plus 迁移约定

- 项目已引入 MyBatis-Plus，SqlSessionFactory 使用 `MybatisSqlSessionFactoryBean`（见 ruoyi-framework 的 MyBatisConfig）。
- **保留现有所有 Mapper XML 与自定义方法**；分页仍使用 PageHelper（startPage + getDataTable），不改为 MP 的 IPage。
- 可选：在部分简单表上，Mapper 接口继承 `BaseMapper<实体>`，实体需与表对应（表名用 `@TableName("sys_xxx")`，主键用 `@TableId`）；新增的简单 CRUD 可用 MP 方法，复杂查询仍用 XML。
- 若使用 MP 逻辑删除：实体字段加 `@TableLogic`，与全局配置 `logic-delete-field`、`logic-delete-value` 一致；现有逻辑删除（如 del_flag=2）可继续用 XML 的 update。

### 5.3 XML 规范

- 与现有风格一致：`<select>`、`<insert>`、`<update>`、`<delete>` 的 id 与 Mapper 方法名一致；parameterType/resultType/resultMap 正确。
- 动态 SQL 使用 `<if>`、`<foreach>` 等；注意 `${params.dataScope}` 等注入由 AOP 设置，不要改动其用法。
- 时间等使用数据库函数（如 `sysdate()`）与现有一致。

## 六、实体与 DTO

### 6.1 实体（Domain/Entity）

- 与表结构对应；继承 `BaseEntity` 时已含 createBy、createTime、updateBy、updateTime、remark、params 等。
- 主键、表名若与默认不一致：使用 `@TableName`、`@TableId`（使用 MP 时）；纯 MyBatis 时靠 XML resultMap。
- 敏感字段（如 password）不入参到前端时，可用 @JsonIgnore 或 VO 隔离。

### 6.2 参数与响应

- 列表查询：可直接用实体接收（如 SysUser），前端传的 pageNum、pageSize、orderByColumn、isAsc 由 TableSupport 从 request 取，不要求实体里必须有这些字段。
- 新增/修改：使用实体或专用 DTO，加 @Valid 与 javax.validation 注解；返回可仍为 AjaxResult，data 根据需要放 ID 或完整对象。

---

## 七、分页（必须保留的约定）

### 7.1 使用方式

- Controller 中：`startPage();` → 调用 Service 得到 list → `return getDataTable(list);`。
- 不要改为 IPage、Page 等 MyBatis-Plus 分页返回类型给前端；前端仍接收 `{ code, msg, total, rows }`。

### 7.2 配置

- application.yml 中保留 pagehelper 配置：helperDialect=mysql，supportMethodsArguments=true，params=count=countSql。
- 排序：Controller 中可调用 `startOrderBy()`，内部从 TableSupport 取 orderByColumn、isAsc 并转成 orderBy 字符串，设置到 PageHelper。

### 7.3 导出等非分页查询

- 导出列表时**不要**调用 startPage()，直接 Service 查全量或条件查询，避免误用分页。

## 八、接口文档（Swagger3 + Knife4j）

### 8.1 环境区分

- 配置项：`swagger.enabled`（application.yml），开发/测试为 true，生产为 false。
- 生产环境由部署时手动设置 `swagger.enabled: false`（无 application-prod.yml）。
- 访问地址：Knife4j 增强页为 `/doc.html`；Swagger UI 为 `/swagger-ui.html`。两者均已放行且配置资源路径。

### 8.2 注解使用

- 在需要暴露的接口方法上使用 `@ApiOperation("接口说明")`，SwaggerConfig 中按 `withMethodAnnotation(ApiOperation.class)` 扫描。
- 类上可使用 `@Api("模块说明")`（如“用户信息管理”）。
- 参数说明可用 `@ApiImplicitParam` / `@ApiImplicitParams`；RequestBody 可用实体上的 `@ApiModelProperty`。
- 与前端对接时，保证文档中的 URL、Method、参数名与真实接口一致。

### 8.3 安全

- 已配置 SecurityScheme（Authorization 头），Knife4j 中可填写 Bearer Token 调试；生产必须关闭文档。

## 九、异常与返回码

### 9.1 统一响应

- 成功：code=200，msg 如“操作成功”，data 或 rows/total 按接口类型返回。
- 业务失败：可抛 ServiceException 或返回 error(msg)；前端根据 code 与 msg 提示。
- 401：未登录或 Token 无效，由 Security 与前端配合跳转登录。
- 500：服务器异常，由全局异常处理返回，不暴露堆栈给前端。

### 9.2 全局异常处理

- 保持现有 GlobalExceptionHandler（或项目中等价类）：处理 ServiceException、MethodArgumentNotValidException、ConstraintViolationException 等，统一返回 AjaxResult 或 TableDataInfo 结构。

---

## 十、命名与注释

### 10.1 命名

- 类/接口：PascalCase；方法/变量：camelCase；常量：大写下划线。
- Mapper 方法：selectXxx、insertXxx、updateXxx、deleteXxx；与 XML id 一致。
- 权限标识：模块:资源:操作，如 system:user:list、system:user:add。

### 10.2 注释

- 公共接口、Service 方法、Mapper 方法应有简要 JavaDoc（功能、参数、返回值）。
- 复杂业务或与前端/数据库约定处加注释说明；TODO/FIXME 按项目习惯使用。

---

## 十一、检查清单（生成或修改后端代码时）

- [ ] Controller 分页接口使用 startPage() + getDataTable(list)，未改为 MP 分页类型返回。
- [ ] 列表 URL、参数（pageNum、pageSize、orderByColumn、isAsc）与前端及 TableSupport 一致。
- [ ] Mapper XML 的 namespace、id 与接口一致；如需数据权限，保留 @DataScope 与 params.dataScope。
- [ ] 新增接口若需文档，加上 @ApiOperation；生产环境 swagger.enabled=false。
- [ ] 写操作 Service 方法加 @Transactional(rollbackFor = Exception.class)。
- [ ] 权限标识与前端 v-hasPermi 一致，且已在权限体系中配置。
- [ ] 不删除或修改现有 PageHelper、TableSupport、PageDomain、BaseController 的分页与返回方式。

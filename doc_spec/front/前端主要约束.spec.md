# 前端生成代码规范约束

本文档约束 **web/** 目录下 Vue 3 + TypeScript 前端的代码生成与开发规范，与后端接口、类型和项目既有实现保持一致。

**必须一起使用**：本文档须与以下文档一起使用，缺一不可，以保持前后端一致与数据/业务对齐：

- [整体规范](../项目整体.spec.md)
- [后端规范](../service/后端主要约束.spec.md)
- [现有数据库说明](../数据库.spec.md)
- [系统业务说明](../现有业务说明.spec.md)

---

## 强制约束

- 生成代码之后，禁止运行npm run dev;
- 生成代码之后，禁止修改任何文件，包括但不限于：
  - 路由配置

- 如果存在api接口对接文档，必须按照接口文档的接口对接，禁止添加接口文档外的接口!

## 二、类型定义规范

### 2.1 通用类型（types/api/common.ts）

必须与后端一致，生成或修改时以现有定义为准：

- **AjaxResult\<T\>**：`code`, `msg`, `data?`。
- **TableDataInfo\<T\>**：`code`, `msg`, `total`, `rows`（列表数据）。
- **PageDomain**：`pageNum?`, `pageSize?`, `orderByColumn?`, `isAsc?`, `reasonable?`。
- **BaseEntity**：`searchValue?`, `createBy?`, `createTime?`, `updateBy?`, `updateTime?`, `remark?`, `params?`。
- **TreeSelect**：`id?`, `label?`, `disabled`, `children`。
- **TableShowColumns**：`label`, `visible`。

### 2.2 业务类型（types/api/ 下各模块）

- 与后端实体、DTO、VO 字段一一对应，使用 TypeScript 接口（interface）。
- 分页查询参数：继承 `PageDomain` 并扩展业务字段（如 `userName`、`status`、`deptId` 等），命名与后端接收参数一致。
- 列表/详情/表单专用类型可单独定义（如 `UserFormDataResult`、`UserAuthRoleResult`），并在 `types/index.ts` 中导出。

### 2.3 类型导出与引用

- `types/index.ts` 统一从 `types/api/*` 汇总导出，供业务代码使用。
- 业务代码通过 `import type { ... } from '@/types'` 引用，禁止在页面中手写与后端不一致的临时类型。

## 三、API 层规范

### 3.1 文件与命名

- 文件路径与后端模块对应：如 `api/system/user.ts` 对应后端 `/system/user` 相关接口。
- 方法名：动词 + 资源，小驼峰，如 `listUser`、`getUser`、`addUser`、`updateUser`、`delUser`。
- 每个方法必须有明确返回类型：`Promise<AjaxResult<T>>` 或 `Promise<TableDataInfo<T[]>>`。

### 3.2 请求方式与 URL

- **列表（分页）**：GET，URL 如 `/system/user/list`，参数为 query（`params`），类型为对应 `XxxQueryParams`。
- **详情**：GET，URL 如 `/system/user/:id` 或 `/system/user/${id}`，路径参数用模板字符串。
- **新增**：POST，URL 如 `/system/user`，body 为 `data`。
- **修改**：PUT，URL 如 `/system/user`，body 为 `data`。
- **删除**：DELETE，URL 如 `/system/user/:ids`，路径参数或 query 与后端一致。

### 3.3 实现模板（与现有风格一致）

```typescript
import request from "@/utils/request";
import { parseStrEmpty } from "@/utils/ruoyi";
import type {
  UserQueryParams,
  UserFormDataResult,
  SysUser,
  AjaxResult,
  TableDataInfo,
  TreeSelect,
} from "@/types";

// 查询用户列表（分页）
export function listUser(
  query: UserQueryParams,
): Promise<TableDataInfo<SysUser[]>> {
  return request({
    url: "/system/user/list",
    method: "get",
    params: query,
  });
}

// 查询用户详细
export function getUser(userId?: number): Promise<UserFormDataResult> {
  return request({
    url: "/system/user/" + parseStrEmpty(userId),
    method: "get",
  });
}

// 新增
export function addUser(data: SysUser): Promise<AjaxResult> {
  return request({
    url: "/system/user",
    method: "post",
    data: data,
  });
}

// 修改
export function updateUser(data: SysUser): Promise<AjaxResult> {
  return request({
    url: "/system/user",
    method: "put",
    data: data,
  });
}

// 删除
export function delUser(userId: number | number[]): Promise<AjaxResult> {
  return request({
    url: "/system/user/" + userId,
    method: "delete",
  });
}
```

- 使用 `@/utils/request` 的 axios 实例，不另行创建。
- 需要“空参数”的 GET（如详情）使用 `parseStrEmpty` 等方式与后端约定一致。

## 四、页面（Views）规范

### 4.1 单文件结构顺序

1. **template**：单根节点，使用语义化标签；列表页使用 `app-container` 等与现有一致的 class。
2. **script**：`<script setup lang="ts">`，顺序建议为：import → 组件/指令注册 → 依赖（store、router、api）→ 类型与常量 → ref/reactive → computed → watch → 方法 → 生命周期（onMounted 等）。
3. **style**：`scoped`，优先使用现有 SCSS 变量与类名（如 `mb8`、`head-container`）。

### 4.2 列表页必备要素

- **查询表单**：`el-form`，`model` 绑定为 `queryParams`（含 `pageNum`、`pageSize` 及业务条件），与后端 `TableSupport` 参数一致；搜索/重置调用 `handleQuery`、`resetQuery`。
- **表格**：`el-table`，`v-loading="loading"`，`:data="列表变量"`；需要多选时 `@selection-change="handleSelectionChange"`，并维护 `ids`、`single`、`multiple`。
- **分页**：使用项目现有 `pagination` 组件，`:total="total"`，`v-model:page="queryParams.pageNum"`、`v-model:limit="queryParams.pageSize"`，`@pagination="getList"`。
- **请求**：列表接口返回 `TableDataInfo`，赋值 `rows` → 列表变量，`total` → 总条数；分页、搜索、重置后统一调 `getList()`。

### 4.3 表单与弹窗

- 新增/编辑使用 `el-dialog`，`v-model="open"` 控制显隐；表单 `ref`、`:rules` 与 `form` 对象与类型一致。
- 提交前 `proxy.$refs.xxxRef.validate()`，通过后调用对应 API（add/update），成功后关闭弹窗并刷新列表、`proxy.$modal.msgSuccess()`。

### 4.4 权限与指令

- 按钮级权限使用 `v-hasPermi="['system:user:add']"` 等，与后端 `@PreAuthorize` 权限标识一致。
- 新增编辑删除等操作按钮，权限标识与后端一致（如 `system:user:add`、`system:user:update`、`system:user:del`）。根据创建的文件的目录结构，确定按钮的权限名称。

### 4.5 工具与习惯

- 时间展示使用现有 `parseTime` 等工具。
- 确认框使用 `proxy.$modal.confirm`，成功提示使用 `proxy.$modal.msgSuccess`，与现有封装一致。
- 下载/导出使用 `proxy.download(...)`，不直接写 axios blob。
- **字典使用**：通过 `proxy.useDict("dictType1", "dictType2")` 获取字典数据，解构赋值后使用。示例：
  ```typescript
  const { proxy } = getCurrentInstance();
  const { sys_show_hide, sys_normal_disable } = proxy.useDict(
    "sys_show_hide",
    "sys_normal_disable",
  );
  ```

  - 多个字典类型可通过逗号分隔传入
  - 返回的字典对象可直接在模板中用于下拉选择或状态显示

## 五、组件与资源

### 5.1 公共组件

- 使用项目已有组件：如 `Pagination`、`RightToolbar`、`DictTag`、`Editor`、`FileUpload`、`ImageUpload` 等，不重复造轮子。
- 新增公共组件放在 `components/` 下，命名 PascalCase，需在 `types/components.d.ts` 中声明（若为全局注册）。

### 5.2 图标与样式

- 使用 Element Plus 图标（如 `Search`、`Plus`、`Edit`、`Delete`）或项目已有 SvgIcon，风格与现有页面一致。
- 样式类名与现有一致（如 `mb8`、`head-container`、`app-container`），避免随意新增全局类导致污染。

## 六、请求与异常

### 6.1 请求封装

- 所有 HTTP 请求通过 `@/utils/request` 发出的 axios 实例。
- 请求拦截器：自动携带 `Authorization: Bearer <token>`（除配置 `isToken: false` 的接口）；GET 参数处理方式与现有一致。
- 响应拦截器：按 `code` 处理 200 成功、401 跳转登录、500 等错误提示；返回值为 `res.data`，业务代码直接使用 `data`、`rows`、`total` 等。

### 6.2 错误与提示

- 不吞掉接口错误：列表/表单在 catch 中可做友好提示或重置状态，不静默失败。
- 错误文案以后端返回的 `msg` 为主，前端可做兜底文案（如“操作失败”）。

---

## 七、命名与注释

### 7.1 命名

- **文件**：页面/组件 PascalCase 或 kebab-case（与现有一致）；API、类型小写或 kebab-case。
- **变量/方法**：小驼峰；常量可大写下划线。
- **类型/接口**：PascalCase；与后端实体名对应（如 `SysUser`、`UserQueryParams`）。

### 7.2 注释

- API 方法上方简要注释（如「查询用户列表」）。
- 复杂逻辑或与后端约定不一致处必须注释说明。
- 类型字段可加 JSDoc 注释，便于与后端对照。

## 八、与后端对齐检查清单

生成或修改前端代码时，请确认：

- [ ] 分页参数 `pageNum`、`pageSize`、`orderByColumn`、`isAsc` 与后端一致。
- [ ] 列表接口返回使用 `TableDataInfo`（`rows`、`total`），其它使用 `AjaxResult`（`code`、`msg`、`data`）。
- [ ] 请求 URL、Method 与后端 Controller 一致；路径参数与 query 名称一致。
- [ ] 类型定义与后端实体/参数/响应一致（含可选与日期格式）。
- [ ] 权限标识与后端 `@PreAuthorize` 一致，且已在权限体系中配置。

## 九、其他注意事项，需严格按照以下规范进行，禁止出现deviations：

- 新增功能时：**API 放在 `api/` 对应模块下，类型放在 `types/api/` 对应路径，页面放在 `views/` 对应业务目录。**
- 组件/样式/图标等资源放在 `components/`、`styles/`、`assets/icons/` 等目录下，与现有结构一致。
- 新增公共组件时，需在 `types/components.d.ts` 中声明（若为全局注册）。
- 新增图标时，需在 `assets/icons/` 下新增 svg 文件，文件名与组件名一致（如 `Search.svg`、`Plus.svg`）。
- 新增样式类名时，需在 `styles/element/index.scss` 中新增（若为全局注册）。
- 需要响应式原始类型的数据使用ref定义。
- 后续的api types放在`types/api/`目录下。
- 生成的html代码中，使用element相关组件时，禁止添加`size`属性;
- 所有的promise请求都需要处理异常。
- 所有的异步函数都是用async/await定义。
- 如需用到vue的钩子函数，如ref、onMounted等，无需引用，直接使用即可。

以上为前端生成代码规范约束，须与文首「必须一起使用」所列文档（整体规范、后端规范、数据库说明、系统业务说明）一起使用。

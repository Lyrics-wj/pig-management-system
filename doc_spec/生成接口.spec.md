# 接口文档生成规范

本文档约束根据 PRD 生成前后端接口规范文档的流程与格式，确保生成的接口文档前后端可直接使用、可根据文档生成代码。

**必须一起使用**：本文档须与以下文档一起使用，缺一不可：
- [PRD设计规范](./PRD设计.spec.md) — 确保 PRD 中数据模型、字段定义完整
- [后端主要约束](./service/后端主要约束.spec.md) — 确保接口规范与后端技术栈一致
- [前端主要约束](./front/前端主要约束.spec.md) — 确保接口与前端调用方式一致
- [项目整体代码约束](./项目整体代码约束.spec.md) — 确保前后端权限标识一致

---

## 一、适用范围

- 所有新增功能模块的接口文档生成
- PRD 评审通过后、进入技术开发前生成
- 接口文档作为前后端开发的唯一契约
- 支持三种客户端类型：**Web管理后台**、**APP移动端**、**小程序（Applet）**

---

## 二、输入要求

生成接口文档前，需明确以下信息：

| 输入项 | 说明 | 示例 |
|--------|------|------|
| PRD文档 | 用户指定的 PRD 文档路径 | `doc_prd/小程序.prd.md`、`doc_prd/用户管理.prd.md` |
| 客户端类型 | web / app / applet | 决定接口前缀和权限标识格式 |
| 接口前缀 | 根据客户端类型确定 | `/system`、`/app`、`/applet` |

---

## 三、客户端类型差异

### 3.1 三种客户端对比

| 项目 | Web管理后台 | APP移动端 | 小程序（Applet） |
|------|-------------|-----------|------------------|
| Controller包 | `com.ruoyi.web.controller.**` | `com.ruoyi.app.controller.**` | `com.ruoyi.applet.controller.**` |
| URL前缀 | 现有接口保持不变；**新增功能使用 `/web/**`** | `/app/**` | `/applet/**` |
| 权限标识 | `{模块}:{资源}:{操作}` | `app:{模块}:{操作}` | `applet:{模块}:{操作}` |
| 认证方式 | JWT Token | JWT Token | JWT Token |
| 数据范围 | 按角色/部门数据权限 | **仅看自己的数据** | **仅看自己的数据** |

**Web接口URL说明**：
- **现有功能**：保持原有URL不变（如 `/system/user`、`/monitor/online`）
- **新增功能**：使用 `/web/{模块}` 前缀（如 `/web/breeding/info`、`/web/enterprise`）

**数据权限说明**：
- **Web管理后台**：使用 `@DataScope` 注解按角色配置的数据权限过滤（全部数据/本部门/本部门及以下/仅本人等）
- **APP / 小程序**：登录后默认只能查看和操作**自己的数据**或**自己所属企业/组织的数据**，无需复杂的数据权限配置

### 3.2 前端目录结构

前端代码目录结构根据当前项目实际情况生成：

**Web管理后台**（参考 `web/` 目录）：
```
web/src/
├── api/{模块}/          # 接口定义，如 api/system/user.ts
├── views/{模块}/        # 页面组件，如 views/system/user/index.vue
└── types/api/{模块}/    # 类型定义，如 types/api/system/user.ts
```

**APP移动端 / 小程序**：
- 根据独立项目的实际目录结构生成
- 参考对应项目的代码规范和目录约定

### 3.3 权限标识格式

| 客户端类型 | 格式 | 示例 |
|-----------|------|------|
| Web管理后台 | `{模块}:{资源}:{操作}` | `system:user:list`、`system:user:add` |
| APP移动端 | `app:{模块}:{操作}` | `app:user:list`、`app:breeding:add` |
| 小程序 | `applet:{模块}:{子模块}:{操作}` | `applet:breeding:info:list`、`applet:enterprise:add` |

## 四、生成流程

```
1. 确认输入  →  2. 读取 PRD  →  3. 提取信息  →  4. 设计接口  →  5. 生成文档  →  6. 前后端评审
```

| 步骤 | 说明 |
|------|------|
| 1. 确认输入 | 确认 PRD 文档路径、客户端类型（web/app/applet） |
| 2. 读取 PRD | 读取用户指定的 PRD 文档 |
| 3. 提取信息 | 提取功能列表、数据模型、字段定义（**含必填标识**）、业务流程 |
| 4. 设计接口 | 按本规范设计 URL、参数（**必填项须与 PRD 一致**）、响应、权限标识 |
| 5. 生成文档 | 输出到 `doc_prd/{模块名}接口文档.md`，**PRD 中的必填项必须体现在文档中** |
| 6. 前后端评审 | 前后端确认后作为开发依据 |

**强制要求（必须遵守）**：
- **接口完整性**：生成的接口文档**必须**覆盖需求或 PRD 中描述的**所有功能**，不得遗漏任何一个功能点
- **逐项核对**：生成完成后，须逐一核对 PRD 中的功能列表，确保每个功能都有对应的接口定义
- **缺失即不合格**：若 PRD 中有功能但接口文档中无对应接口，视为文档不合格，必须补充完整

## 五、接口文档结构（必须包含）

### 5.1 文档头部

根据客户端类型使用对应的文档头部：

**Web管理后台**：
```markdown
# {系统名称} - {模块名}接口文档（Web端）

> **文档版本**：v1.0  
> **关联PRD**：`doc_prd/{xxx}.prd.md` {版本号}  
> **接口前缀**：现有功能保持原有前缀（如 `/system`、`/monitor`）；新增功能使用 `/web` 前缀
```

**APP移动端**：
```markdown
# {系统名称} - {模块名}接口文档（APP端）

> **文档版本**：v1.0  
> **关联PRD**：`doc_prd/{xxx}.prd.md` {版本号}  
> **接口前缀**：APP端接口统一前缀 `/app`
```

**小程序**：
```markdown
# {系统名称} - {模块名}接口文档（小程序端）

> **文档版本**：v1.0  
> **关联PRD**：`doc_prd/{xxx}.prd.md` {版本号}  
> **接口前缀**：小程序端接口统一前缀 `/applet`
```

### 5.2 通用约定（必须包含）

```markdown
## 一、通用约定

### 1.1 请求规范

- **Base URL**：`{接口前缀}`（{客户端类型}端）
- **认证方式**：请求头 `Authorization: Bearer <token>`
- **Content-Type**：`application/json`
- **分页参数**：`pageNum`（从1开始）、`pageSize`、`orderByColumn`、`isAsc`

### 1.2 响应格式

**普通接口**（AjaxResult）：
{
  "code": 200,        // 状态码：200成功，401未登录，500服务器错误
  "msg": "操作成功",  // 提示信息
  "data": {}          // 返回数据
}

**分页接口**（TableDataInfo）：
{
  "code": 200,
  "msg": "查询成功",
  "total": 100,       // 总记录数
  "rows": []          // 数据列表
}

### 1.3 状态码

| code | 说明 |
|------|------|
| 200 | 成功 |
| 401 | 未登录或Token过期 |
| 500 | 服务器错误 |
```

### 5.3 接口定义（每个接口必须包含以下内容）

```markdown
### {序号} {接口名称}

**{HTTP方法}** `{接口路径}`

> {接口功能说明，一句话描述该接口做什么}

**权限标识**：`{权限字符}` 或 `需登录` 或 `无（公开接口）`
（根据业务需求决定是否需要权限控制）

**数据权限**：{如有数据过滤规则必须说明，如"仅返回当前用户所属企业的数据"}

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| xxx | string | 是 | {字段说明} |

**请求示例**：
{JSON示例}

**响应参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| xxx | string | {字段说明} |

**响应示例**：
{JSON示例}
```

### 5.4 权限标识汇总（如有权限控制则必须包含）

如果接口需要权限控制，文档末尾需包含权限标识汇总表：

```markdown
## N、接口权限标识

| 模块 | 权限标识前缀 | 说明 |
|------|-------------|------|
| {模块名} | {前缀}:{模块} | {模块说明} |
```

如果所有接口均为公开或仅需登录，可省略此章节。

## 七、权限标识规范

### 7.1 是否需要权限标识

**根据业务需求决定**，不是所有接口都必须有权限标识：

| 场景 | 是否需要权限标识 | 说明 |
|------|------------------|------|
| Web管理后台 | **通常需要** | 后台管理功能一般需要按角色控制权限 |
| APP移动端 | **按需** | 根据业务是否需要权限控制决定 |
| 小程序 | **按需** | 根据业务是否需要权限控制决定 |
| 公开接口 | **不需要** | 如登录、注册、验证码等无需登录的接口 |
| 仅登录可访问 | **可选** | 只要登录即可访问，无需细粒度权限控制 |

**接口文档中的标注方式**：

- 需要权限控制：`**权限标识**：applet:breeding:info:list`
- 仅需登录：`**权限**：需登录`
- 无需权限：`**权限**：无（公开接口）` 或不标注

### 7.2 权限标识格式（如需要）

```
{客户端前缀}:{模块}:{子模块}:{操作}
```

### 7.3 各客户端权限标识格式

| 客户端类型 | 格式 | 说明 |
|-----------|------|------|
| Web管理后台 | `{模块}:{资源}:{操作}` | 无客户端前缀 |
| APP移动端 | `app:{模块}:{操作}` | 以 app 为前缀 |
| 小程序 | `applet:{模块}:{子模块}:{操作}` | 以 applet 为前缀 |

### 7.4 操作类型

| 操作 | 标识 | 说明 |
|------|------|------|
| 列表查询 | list | 分页列表、下拉列表 |
| 详情查询 | query | 单条详情 |
| 新增 | add | 新增、保存草稿、提交 |
| 修改 | edit | 修改、撤回 |
| 删除 | remove | 删除 |
| 导出 | export | 导出Excel等 |

### 7.5 各客户端权限标识示例

| 功能 | Web管理后台 | APP移动端 | 小程序 |
|------|-------------|-----------|--------|
| 用户列表 | `system:user:list` | `app:user:list` | `applet:user:list` |
| 用户新增 | `system:user:add` | `app:user:add` | `applet:user:add` |
| 养殖信息列表 | `pig:breeding:info:list` | `app:breeding:info:list` | `applet:breeding:info:list` |

### 7.6 前后端一致性要求

**如果接口需要权限控制**，权限标识必须在以下三处完全一致：

| 位置 | 格式 | 示例 |
|------|------|------|
| 后端Controller | `@PreAuthorize("@ss.hasPermi('权限标识')")` | `@PreAuthorize("@ss.hasPermi('applet:breeding:info:list')")` |
| 前端按钮 | `v-hasPermi="['权限标识']"` | `v-hasPermi="['applet:breeding:info:list']"` |
| 接口文档 | `**权限标识**：权限字符` | `**权限标识**：applet:breeding:info:list` |

## 八、参数说明规范（强制）

### 8.1 必须包含的信息

每个请求/响应参数必须包含：

| 列 | 说明 | 必须 |
|----|------|------|
| 参数 | 参数名（驼峰命名） | 是 |
| 类型 | 数据类型 | 是 |
| 必填 | 是/否/条件 | 是（请求参数） |
| 说明 | 字段含义及约束 | 是 |

### 8.2 类型定义

| 类型 | 说明 | 示例 |
|------|------|------|
| string | 字符串 | "张三" |
| int | 整数 | 100 |
| long | 长整数 | 1234567890123 |
| decimal | 小数 | 105.123456 |
| boolean | 布尔值 | true/false |
| date | 日期 | "2026-02-27" |
| datetime | 日期时间 | "2026-02-27 10:00:00" |
| array | 数组 | [] |
| object | 对象 | {} |

### 8.3 说明字段要求（强制完整）

说明字段必须包含以下信息（如适用）：

| 信息类型 | 示例 |
|---------|------|
| 字段含义 | 企业名称 |
| 长度限制 | 最大100字符 |
| 取值范围 | 1-999999 |
| 枚举值（必须完整列出） | 状态：0草稿/1已提交/2已审核/3已退回/4已入库 |
| 格式要求 | 11位手机号、18位信用代码 |
| 关联关系 | 关联 pig_enterprise.enterprise_id |
| 默认值 | 默认0 |
| 只读标识 | 系统自动填充，只读 |

### 8.4 必填字段说明（必须与 PRD 一致）

**重要**：PRD 中定义的必填字段，**必须**在接口文档中体现，不得遗漏。

| 必填值 | 说明 |
|--------|------|
| 是 | 必须传值（**PRD 中标记为必填的字段**） |
| 否 | 可选 |
| 条件 | 特定条件下必填，**必须说明条件** |

**必填字段来源**：
1. **PRD 数据模型**：PRD 中字段定义表的"是否必填"列
2. **业务规则**：PRD 中描述的业务逻辑决定的必填项
3. **条件必填**：根据其他字段值决定是否必填

**生成要求**：
- 生成接口文档时，**必须检查 PRD 中的必填标识**
- PRD 中标记为必填的字段，接口文档中必填列必须为"是"
- 不得擅自修改 PRD 中定义的必填规则

条件必填示例：
```
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| supplierName | string | 条件 | 供应商名称，**sourceType=1（外购）时必填** |
| buyerName | string | 条件 | 购买方名称，**outboundPurpose=1（销售）时必填** |
```

### 8.5 枚举值规范（强制完整列出）

**禁止模糊描述**，必须列出所有枚举值：

❌ 错误示例：
```
| status | string | 是 | 状态等 |
```

✅ 正确示例：
```
| status | string | 是 | 状态：0草稿/1已提交/2村级已审核/3村级退回/4县级退回/5已入库（共6种） |
```

```markdown
**数据权限**：仅返回当前用户所属企业的数据（按 `enterprise_id` 过滤）
```

**Web管理后台**：
```markdown
**数据权限**：使用 @DataScope 注解，按部门数据权限过滤
```

### 11.2 新增/修改接口

```markdown
### 3.2 新增/修改企业信息

**POST** `/applet/enterprise/save`

> enterpriseId 存在为修改，不存在为新增

**权限标识**：`applet:enterprise:add`（新增）/ `applet:enterprise:edit`（修改）

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| enterpriseId | long | 否 | 企业ID，新增时不传 |
| enterpriseName | string | 是 | 企业名称，最大100字符 |
| creditCode | string | 是 | 统一社会信用代码，18位数字或字母 |
```

## 十二、检查清单

生成接口文档后必须检查：

- [ ] **完整性**：PRD 中每个功能点都有对应接口
- [ ] **必填一致性**：PRD 中定义的必填字段在接口文档中必须标记为必填，不得遗漏
- [ ] **权限标识**：根据业务需求标注（权限字符/需登录/公开接口），需要权限控制的接口前后端一致
- [ ] **请求参数**：包含参数名、类型、必填、说明
- [ ] **响应参数**：包含参数名、类型、说明
- [ ] **枚举值**：完整列出所有取值，无"等"字
- [ ] **条件必填**：说明具体条件
- [ ] **数据权限**：涉及数据过滤的接口已标注
- [ ] **业务校验**：说明校验规则和错误提示
- [ ] **分页参数**：使用 pageNum、pageSize、orderByColumn、isAsc
- [ ] **JSON示例**：请求和响应都有示例
- [ ] **权限汇总**：如有权限控制的接口，文档末尾需有权限标识汇总表

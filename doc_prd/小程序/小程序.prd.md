## 功能一：用户登录与认证（含登录后引导、退出登录）

### 1.1 基本信息

- **功能名称**：用户登录与认证
- **关联现有模块/功能**：
  - 认证接口：复用现有 `/login`（账号密码登录）、`/getInfo`（获取用户信息）、`/getRouters`（获取菜单权限）
  - 用户管理：依赖 `/system/user`，账号由管理后台创建与分配
  - 企业信息：登录后引导涉及 `pig_enterprise`（养殖企业表）、`pig_pigsty`（猪舍表）的新增操作
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 使用场景 | 主要需求 |
|---------|---------|---------|
| 养殖企业/个体户 | 首次打开小程序或 Token 失效时 | 使用账号密码登录，完善企业与猪舍信息 |
| 养殖从业人员 | 日常使用结束后 | 退出登录，保护账号安全 |
| 基层监管人员 | 首次打开小程序时 | 使用账号密码登录进入业务页面 |

### 1.2 目标与范围

**目标**：
1. 提供安全可靠的账号密码登录入口，支持 JWT Token 认证机制。
2. 登录成功后引导新用户完善企业信息与猪舍信息，降低后续上报障碍。
3. 提供退出登录功能，清除本地登录状态，保护用户账号安全。

**非目标（Non-Goals）**：
- ❌ 不提供用户自主注册入口，账号由管理后台创建与分配。
- ❌ 不提供忘记密码/自助重置密码功能（由后台管理员重置）。
- ❌ 不支持微信授权登录、手机号验证码登录等其他登录方式。
- ❌ 不做多账号切换功能。

### 1.3 现状与复用

**现状简述**：
- 现有系统已有基于 JWT 的认证体系，`/login` 接口接受用户名、密码（及验证码若启用），返回 Token。
- 现有 `/getInfo` 接口可获取当前登录用户信息（角色、权限等）。
- 账号由管理后台 `/system/user` 模块创建与管理，小程序端无注册入口。

**复用与差异**：

| 功能模块 | 复用内容 | 新增/修改内容 |
|---------|---------|--------------|
| 用户认证 | 复用 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制 | 小程序端无注册入口；登录成功后需判断是否进入引导流程 |
| 企业信息 | 无现有小程序端功能 | 新增：引导页调用企业信息新增/查询接口 |
| 猪舍信息 | 无现有小程序端功能 | 新增：引导页调用猪舍信息新增/查询接口 |

### 1.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 账号密码登录 | P0 | 输入用户名、密码（及验证码若启用）发起登录 |
| 登录态管理 | P0 | Token 存储、过期检测、自动跳转登录页 |
| 登录后引导 | P1 | 首次登录且企业/猪舍信息未完善时，引导用户填写（可跳过） |
| 退出登录 | P0 | 清除本地 Token 及用户信息，返回登录界面 |

**关键流程**：

```
登录流程：
打开小程序 → 检测 Token 有效性
  ├── Token 有效 → 直接进入首页
  └── Token 无效/不存在 → 展示登录界面
        ↓
用户输入账号 + 密码（+ 验证码若启用）→ 点击「登录」
        ↓
前端校验（非空、格式）→ 校验不通过：字段下方提示，阻断请求
        ↓
校验通过 → 发起 /login 请求 → 按钮置灰/loading
        ├── 登录成功 → 保存 Token + 用户信息
        │     ├── 企业/猪舍信息未完善 → 进入引导页
        │     └── 已完善 → 直接进入首页
        └── 登录失败 → 展示后端错误信息，不跳转

引导流程：
进入引导页 → 步骤一：填写企业信息
  ├── 点击「下一步」→ 校验当步必填字段 → 通过后进入步骤二
  ├── 点击「跳过」→ 直接进入首页（不触发校验）
  └── 步骤二：填写猪舍信息（至少一条）
        ├── 点击「完成」→ 校验必填字段 → 通过后进入首页
        └── 点击「跳过」→ 直接进入首页

退出登录流程：
「我的」页点击「退出登录」→ 弹出二次确认弹窗
  ├── 点击「确认」→ 清除本地 Token 及用户信息 → 跳转登录界面（清空页面栈）
  └── 点击「取消」→ 关闭弹窗，不退出
```

**交互与界面要点**：

登录界面布局（自上而下）：
1. 顶部：产品名称「蓬溪县生猪数字化管理平台」（Logo + 文字）
2. 账号输入框：占位符「请输入账号」，单行文本
3. 密码输入框：占位符「请输入密码」，密文；右侧「显示/隐藏」图标切换明文/密文
4. 记住账号（可选）：勾选框，勾选时下次自动填充账号（仅存账号，不存密码）
5. 验证码区域（若后端启用）：验证码图片 + 输入框，点击图片刷新
6. 「登录」按钮：主按钮，宽度充满容器
7. 底部：无注册入口、无忘记密码入口

引导页布局：
- 单页多步（步骤一：企业信息，步骤二：猪舍信息）
- 顶部步骤条显示当前进度
- 每步底部：「跳过」（文字链接）+ 「下一步」/「完成」（主按钮）
- 支持返回上一步修改

#### 1.4.1 功能流程逻辑

**登录状态判断规则**：
- 小程序启动时检测本地存储的 Token 是否存在且未过期
- Token 有效：直接进入首页，不展示登录页
- Token 无效/不存在：展示登录界面
- 访问需登录的业务页时，若检测到未登录，统一跳转至登录界面

**引导触发规则**：
- 登录成功后，调用接口检查当前用户是否已关联企业（`pig_enterprise` 中有该用户的有效记录）
- 未关联企业 → 进入引导步骤一（企业信息）
- 已关联企业但无猪舍记录 → 进入引导步骤二（猪舍信息）
- 已关联企业且有猪舍记录 → 直接进入首页，不展示引导

**引导跳过规则**：
- 每步均可跳过，跳过后进入首页，本次不再弹出引导
- 跳过后可在「我的」-「企业信息管理」/「猪舍管理」中补充完善
- 未完善时首页显示一次轻提示（如「建议完善企业/猪舍信息以便正常上报」），不阻断使用

**退出登录规则**：
- 清除本地 Token（`storage` 中的 token 字段）及用户信息缓存
- 跳转至登录界面，清空业务页面栈（登录页为独立页面，不保留业务页面的栈）
- 退出后再次进入小程序或访问需登录页面时，均进入登录界面

#### 1.4.3 界面交互逻辑

**登录界面校验规则（强制）**：

| 字段 | 必填 | 格式校验 | 校验时机 | 提示文案 |
|-----|------|---------|---------|---------|
| 账号 | 是 | 非空 | 失焦 + 提交时 | 「请输入账号」 |
| 密码 | 是 | 非空 | 失焦 + 提交时 | 「请输入密码」 |
| 验证码（若启用） | 是 | 非空 | 失焦 + 提交时 | 「请输入验证码」 |

- 错误提示紧邻对应字段下方展示（红色文字），不得仅用全局弹窗
- 登录请求进行中：登录按钮置灰并显示 loading，禁止重复点击
- 登录失败：在登录按钮上方展示后端返回错误信息（如「账号或密码错误」「账号已停用」），清空密码输入框，不跳转

**引导页表单校验规则（强制）**：

步骤一（企业信息）必填字段及校验：

| 字段 | 必填 | 格式校验 | 提示文案 |
|-----|------|---------|---------|
| 企业名称 | 是 | 非空，最大100字符 | 「企业名称不能为空」 |
| 统一社会信用代码 | 是 | 18位数字或字母 | 「统一社会信用代码不能为空」/「格式不正确，须为18位数字或字母」 |
| 企业类型 | 是 | 枚举值：1/2/3/4 | 「请选择企业类型」 |
| 法人代表 | 是 | 非空，最大50字符 | 「法人代表不能为空」 |
| 联系电话 | 是 | 11位手机号 | 「联系电话不能为空」/「手机号格式不正确」 |
| 详细地址 | 是 | 非空，最大200字符 | 「详细地址不能为空」 |
| 养殖规模 | 是 | 正整数，最小值1，最大值999999 | 「养殖规模不能为空」/「养殖规模须在1～999999之间」 |

步骤二（猪舍信息）必填字段及校验：

| 字段 | 必填 | 格式校验 | 提示文案 |
|-----|------|---------|---------|
| 猪舍名称 | 是 | 非空，最大100字符 | 「猪舍名称不能为空」 |
| 猪舍类型 | 是 | 枚举值：1/2/3/4/5/6 | 「请选择猪舍类型」 |
| 设计容量 | 是 | 正整数，最小值1，最大值9999 | 「设计容量不能为空」/「设计容量须在1～9999之间」 |
| 状态 | 是 | 枚举值：0/1/2；默认「使用中」 | 「请选择猪舍状态」 |

- 点击「下一步」时校验当步所有必填字段，不通过时阻断跳转，错误提示紧邻字段下方
- 点击「跳过」时不触发校验，直接进入下一步或首页
- 自动回显字段（当前存栏、创建时间、创建者等）在表单中只读展示，不可编辑

**退出登录交互**：
- 入口：「我的」页底部「退出登录」按钮
- 点击后弹出确认弹窗：「确定退出登录？」，含「确认」「取消」两个按钮
- 确认后：清除本地 Token 及用户信息，跳转登录界面，清空业务页面栈
- 取消后：关闭弹窗，不执行任何操作

**异常与边界处理**：
- 网络异常：提示「网络异常，请检查网络后重试」
- 接口超时：提示「请求超时，请重试」
- 页面首次加载时若已有有效 Token：直接跳转首页，不展示登录页

### 1.5 非功能需求

- **安全**：密码输入框使用密文类型，支持明文/密文切换；Token 存储于小程序本地 storage，不明文存储密码
- **性能**：登录接口响应时间 < 3 秒（P95）
- **兼容性**：支持微信小程序基础库版本 >= 2.10.0，兼容 iOS 和 Android

### 1.6 验收标准

- [ ] 小程序仅提供账号密码登录，无注册入口、无忘记密码入口
- [ ] 登录页展示：产品名称/Logo、账号输入框、密码输入框（含明文/密文切换）、记住账号（可选）、登录按钮
- [ ] 若后端启用验证码，登录页展示验证码图片及输入框，点击图片可刷新
- [ ] 账号或密码为空时点击登录，字段下方给出明确提示，阻断请求
- [ ] 登录请求进行中，按钮置灰或显示 loading，防止重复提交
- [ ] 登录成功后保存 Token 与用户信息，跳转引导页或首页
- [ ] 登录失败时展示后端错误信息，不跳转
- [ ] Token 过期或未登录访问业务页时自动跳转登录页
- [ ] 首次登录且企业/猪舍信息未完善时，进入完善信息引导页
- [ ] 引导页步骤一（企业信息）点击「下一步」时校验必填字段，不通过不跳转
- [ ] 引导页步骤二（猪舍信息）点击「完成」时校验必填字段，不通过不跳转
- [ ] 引导页每步均提供「跳过」，点击后直接进入首页，不触发校验
- [ ] 已完善企业/猪舍信息的用户再次登录直接进入首页，不展示引导
- [ ] 「我的」页提供「退出登录」入口，点击后弹出二次确认弹窗

## 功能二：小程序首页

### 2.1 基本信息

- **功能名称**：小程序首页
- **关联现有模块/功能**：

  - 通知公告：依赖 `system_notice`（系统通知公告表）、`system_notice_read`（通知阅读记录表）
  - 待办事项：依赖 `system_todo`（待办事项表）
  - 快捷入口：依赖 `user_shortcut`（用户快捷入口配置表）
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 使用场景 | 主要需求 |
|---------|---------|---------|

| 基层监管人员 | 日常使用 | 查看待办事项，接收通知公告 |

### 2.2 目标与范围

**目标**：
1. 提供核心功能的快捷入口，减少用户操作路径。
2. 展示实时数据统计（养殖数据、学习统计、今日数据），帮助用户快速了解整体情况。
3. 展示待办事项提醒，确保用户不遗漏重要操作。
4. 展示通知公告，确保用户及时获取重要信息。

**非目标（Non-Goals）**：
- ❌ 不做复杂数据分析与图表展示（由 PC 端管理后台实现）。
- ❌ 不做实时推送（依赖用户主动刷新或进入页面时加载）。
- ❌ 不做首页个性化算法推荐（快捷入口支持用户手动自定义）。

#### 2.4.1 功能流程逻辑

**数据统计规则**：

今日数据统计（统计时间范围：当日00:00:00 ～ 23:59:59）：
- 今日上报次数：统计当日所有上报记录数量（含所有状态）
- 今日学习时长：统计当日所有学习记录的时长累计（单位：分钟）
- 今日新增消息：统计当日收到的所有消息数量

养殖数据统计：
- 当前总存栏：所有猪舍的 `current_stock` 字段求和
- 本月出栏量：统计本月所有出栏记录（`pig_outbound_record`）的 `outbound_quantity` 累计（仅统计状态为「已入库」的记录）
- 本月入栏量：统计本月所有入栏记录（`pig_entry_record`）的 `entry_quantity` 累计（仅统计状态为「已入库」的记录）
- 待处理事项：统计 `system_todo` 中 `is_completed=0` 且 `del_flag=0` 的记录数量

学习统计：
- 累计学习天数：`knowledge_learn_record` 中有学习记录的天数累计（按 `update_time` 日期去重）
- 累计学习时长：所有学习记录的 `learn_duration` 累计（单位：分钟，`learn_duration` 字段单位为秒，展示时转换）
- 完成课程数：`knowledge_learn_record` 中 `is_completed=1` 且 `record_type=1` 的记录数量
- 我的收藏数：`knowledge_collect` 中 `del_flag=0` 的记录数量

**待办事项生成规则**：

| 待办类型 | 生成时机 | 优先级 | 截止时间 | 完成条件 |
|---------|---------|-------|---------|---------|
| 上报提醒 | 每日00:00自动生成「今日养殖信息上报」 | 高（`1`） | 当日23:59:59 | 当日有养殖信息上报记录 |
| 活动提醒 | 报名审核通过后；活动开始前24小时；活动开始前1小时 | 中（`2`） | 活动开始时间 | 活动签到完成 |
| 学习提醒 | 有未完成课程（进度<80%）时；新发布推荐课程时 | 低（`3`） | 无截止时间 | 课程完成度>=80% |
| 审核提醒 | 报名申请提交后（管理员）；审核结果出来后（申请人） | 中（`2`） | 提交后3个工作日 | 审核操作完成 |

**通知公告推送规则**：
- 通知范围为「全部用户」（`notice_scope=1`）：推送给所有已登录用户
- 通知范围为「指定企业类型」（`notice_scope=2`）：推送给 `target_enterprise_type` 中指定类型的企业用户
- 通知范围为「指定用户」（`notice_scope=3`）：仅推送给 `target_user_ids` 中列出的用户
- 置顶通知（`is_top=1`）优先展示；重要通知（`is_important=1`）标红显示；按发布时间倒序排列

**快捷入口管理规则**：
- 新用户首次登录时自动生成16个默认入口（见附录快捷入口编码表）
- 用户可隐藏不常用入口（最少保留4个）
- 用户可调整入口排序（长按拖动）
- 用户可添加更多入口（最多16个）
- 配置保存到 `user_shortcut` 表

**数据刷新规则**：
- 进入首页时自动加载最新数据
- 从其他页面返回首页时刷新数据
- 后台切换到前台时刷新数据
- 下拉刷新：刷新间隔不少于2秒（防止频繁刷新），刷新完成后显示「刷新成功」提示
- 统计数据缓存5分钟；待办事项实时查询；通知公告缓存10分钟

#### 2.4.3 界面交互逻辑

**Tab/标签切换**：首页底部导航栏切换时立即响应，切换后对应页面内容区域自动重新加载，切换过程中显示 loading 状态，当前激活 Tab 有明显选中态样式区分。

**数据加载交互**：
- 首次进入显示骨架屏，数据加载失败显示重试按钮
- 下拉刷新：下拉显示刷新图标，释放后触发刷新，刷新完成后显示「刷新成功」提示（1.5秒自动消失）
- 刷新间隔不少于2秒，防止频繁刷新

**快捷入口编辑模式**：
- 长按任意入口进入编辑模式，入口左上角显示删除（隐藏）按钮，支持拖动排序
- 底部显示「添加更多」按钮，点击可从全部功能列表中添加（最多16个）
- 最少保留4个入口，不足4个时隐藏按钮置灰
- 点击「完成」退出编辑模式，配置自动保存

**待办事项交互**：
- 最多展示3条，按优先级（高→中→低）和截止时间排序
- 高优先级（`priority=1`）标红显示
- 左滑显示「完成」按钮，点击后待办状态变为已完成，从列表中移除
- 点击「查看全部」跳转到待办列表页

**通知公告交互**：
- 单行文字滚动播放，自动轮播间隔3秒
- 重要通知（`is_important=1`）标红显示
- 点击某条通知跳转到「通知公告详情」页，展示完整内容
- 进入详情页时标记该用户已读（写入 `system_notice_read`）

**红点显示规则**：
- 消息图标：显示未读消息总数；超过99显示「99+」
- 快捷入口：上报入口显示今日未上报数量，消息入口显示未读消息数量，活动入口显示待审核报名数量
- 底部消息 Tab：显示未读消息数量

**通知公告详情页**：
- 导航栏标题：「通知详情」
- 展示：完整标题、通知类型标签（系统公告/政策通知/活动通知/预警通知）、发布单位/来源（若有）、发布时间（格式：YYYY-MM-DD HH:mm）、是否置顶/重要标识
- 正文区域：富文本内容（支持段落、加粗、列表、图片），附件列表（可点击下载或预览）
- 异常处理：通知不存在或已下架时提示「该通知不存在或已下架」并支持返回；网络失败时提示重试

### 2.5 非功能需求

- **性能**：首页首屏加载时间 < 2 秒（正常网络环境）；统计数据缓存5分钟，通知公告缓存10分钟
- **安全**：所有接口请求携带有效 JWT Token；企业用户仅能查看本企业数据
- **兼容性**：支持微信小程序基础库版本 >= 2.10.0，兼容 iOS 和 Android，适配375px～414px宽度屏幕

## 功能三：养殖信息上报（含审核入库流程）

### 3.1 基本信息

- **功能名称**：养殖信息上报
- **关联现有模块/功能**：
  - 用户认证：依赖功能一的登录态（JWT Token）
  - 企业/猪舍信息：依赖 `pig_enterprise`（养殖企业表）、`pig_pigsty`（猪舍表）
  - 文件上传：复用现有 `/common/upload` 接口
  - 消息通知：审核结果通过功能六（消息通知）推送给用户
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 使用场景 | 主要需求 |
|---------|---------|---------|
| 养殖企业/个体户 | 日常养殖管理 | 录入并上报养殖信息（10个板块），查询历史记录 |
| 村级审核员 | 移动端审核 | 查看待审核记录，执行审核通过或退回操作 |
| 县级管理员 | 移动端入库 | 查看村级已审核记录，执行确认入库或退回操作 |

### 3.2 目标与范围

**目标**：
1. 为养殖企业提供便捷的移动端数据上报渠道，覆盖10个养殖业务板块。
2. 实现村级审核→县级入库的两级审核流程，确保数据质量。
3. 支持数据的录入、提交、撤回、修改、查询，确保数据完整性和可追溯性。
4. 通过消息通知及时告知各角色审核状态变化。

**非目标（Non-Goals）**：
- ❌ 不做复杂数据统计分析（由 PC 端管理后台实现）。
- ❌ 不做完整的 PC 端审批流程（审批由 PC 端处理，小程序仅做数据上报与移动端审核）。
- ❌ 不做离线数据采集与同步（需在线操作）。
- ❌ 不做多租户隔离（本期不涉及多区县、多平台的租户隔离）。

### 3.3 现状与复用

**现状简述**：
- 现有系统无养殖信息上报功能，需全部新增。
- 文件上传复用现有 `/common/upload` 接口，支持图片（jpg/jpeg/png，单张不超过5MB）和视频（mp4，单个不超过50MB）。

**复用与差异**：

| 功能模块 | 复用内容 | 新增/修改内容 |
|---------|---------|--------------|
| 用户认证 | 复用 JWT Token 认证 | 无 |
| 文件上传 | 复用 `/common/upload` 接口 | 需支持小程序端图片/视频上传 |
| 数据字典 | 复用现有字典接口 | 新增34项养殖相关字典（见公共附录） |
| 养殖信息上报 | 无现有功能 | 新增：10张业务表、上报接口、审核接口、查询接口 |

### 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 养殖信息上报（10个板块） | P0 | 基础养殖信息、繁育、断奶、入栏、转栏、投入品、无害化处理、出栏、免疫、消毒 |
| 草稿保存 | P1 | 填写中途可保存草稿，下次进入自动恢复 |
| 提交审核 | P0 | 确认提交后进入村级审核流程 |
| 撤回 | P1 | 已提交且村级未操作时可撤回 |
| 历史记录查询 | P0 | 按状态、日期、猪舍筛选查询上报记录 |
| 村级审核 | P0 | 村级审核员查看待审核记录，执行审核通过/退回 |
| 县级入库 | P0 | 县级管理员查看村级已审核记录，执行确认入库/退回 |

**关键流程**：

```
养殖信息上报主流程（含审核入库）：

养殖场填写表单 → 保存草稿（可选）→ 确认提交
        ↓
  状态：已提交（待村级审核）
        ↓
  ┌─────────────────────────────────┐
  │  养殖场可撤回（仅限村级未审核前）  │
  └─────────────────────────────────┘
        ↓
  村级审核员审核
        ├── 审核通过 → 状态：村级已审核（待县级入库）
        │                     ↓
        │             县级管理员确认入库
        │                     ├── 确认入库 → 状态：已入库（终态）
        │                     └── 退回 → 状态：县级退回（养殖场可修改后重新提交）
        └── 退回 → 状态：村级退回（养殖场可修改后重新提交）

历史记录查询流程：
进入对应模块 → 查看列表（含状态筛选）→ 筛选/搜索 → 查看详情 → 操作（按状态和角色判断可用操作）
```

**交互与界面要点**：

上报表单通用规则：
- 必填字段标红色星号 `*`
- 字段失焦（blur）时即时校验，提交时对全部字段整体校验
- 错误提示紧邻字段下方展示（红色文字），不得仅用全局弹窗笼统提示
- 自动回显字段（企业ID、创建时间、创建者等）只读展示，不可编辑
- 图片上传：显示上传区域，支持多张，缩略图右上角显示删除按钮，上传中显示进度条
- 草稿保存：点击「保存草稿」不进行校验，提示「已保存」；再次进入自动恢复草稿内容
- 提交确认：点击「确认提交」弹出确认弹窗，显示关键信息摘要，确认后显示 loading，提交成功跳转列表页

列表页通用规则：
- 卡片式布局，每条记录一个卡片，显示关键信息（日期、数量、状态等）
- 顶部 Tab 按状态筛选：全部 / 草稿 / 审核中（含已提交+村级已审核）/ 已退回（含村级退回+县级退回）/ 已入库
- **Tab 切换立即筛选**，列表内容即时更新，切换过程中显示 loading 状态
- 支持按日期范围筛选（默认近7天）、按猪舍筛选（下拉选择）
- 下拉刷新、上拉加载更多（每页20条）

#### 3.4.1 功能流程逻辑

**数据状态规则**：

| 状态值 | 状态名称 | 说明 | 可操作角色 |
|--------|----------|------|-----------|
| `0` | 草稿 | 已保存未提交，仅养殖场可见 | 养殖场：编辑、删除、提交 |
| `1` | 已提交 | 养殖场确认提交，等待村级审核 | 养殖场：撤回（仅限村级未操作前）；村级：审核通过、退回 |
| `2` | 村级已审核 | 村级审核通过，等待县级入库 | 县级：确认入库、退回 |
| `3` | 村级退回 | 村级审核退回，需养殖场修改 | 养殖场：编辑、重新提交 |
| `4` | 县级退回 | 县级退回，需养殖场修改 | 养殖场：编辑、重新提交 |
| `5` | 已入库 | 县级确认入库，终态，不可修改 | 所有角色：仅查看 |

**状态流转规则**：
- 草稿 → 已提交：养殖场点击「确认提交」
- 已提交 → 草稿：养殖场点击「撤回」（仅限村级未操作时）
- 已提交 → 村级已审核：村级点击「审核通过」
- 已提交 → 村级退回：村级点击「退回」
- 村级已审核 → 已入库：县级点击「确认入库」
- 村级已审核 → 县级退回：县级点击「退回」
- 村级退回 → 已提交：养殖场修改后重新提交
- 县级退回 → 已提交：养殖场修改后重新提交
- 已入库：终态，不可流转

**删除规则**：仅「草稿」状态可删除（逻辑删除，del_flag=2）；已提交及以后状态不可删除。

**数据权限规则**：
- 养殖场用户：仅能查看和操作本企业的上报数据（按企业ID隔离）
- 村级审核员：可查看本辖区内所有企业的待审核及历史数据，可执行审核通过/退回，不可修改数据内容
- 县级管理员：可查看所有企业的村级已审核数据，可执行入库/退回，不可修改数据内容

**存栏量变更规则**：
- 存栏量变更（入栏、出栏、转栏、无害化处理）仅在记录状态变为「已入库」时正式生效
- 草稿和审核中状态不影响存栏统计

**审核操作规则**：

村级审核员：
- 退回时必须填写退回原因（最少10个字符，最大500个字符）
- 审核通过后系统向养殖场发送消息通知：「您的[上报类型]记录已通过村级审核，等待县级入库」
- 退回后系统向养殖场发送消息通知：「您的[上报类型]记录被村级退回，原因：[原因]」
- 审核通过后系统向县级管理员发送消息通知：「[企业名称]的[上报类型]记录已通过村级审核，请及时入库」

县级管理员：
- 退回时必须填写退回原因（最少10个字符，最大500个字符）
- 确认入库后系统向养殖场发送消息通知：「您的[上报类型]记录已成功入库」
- 退回后系统向养殖场发送消息通知：「您的[上报类型]记录被县级退回，原因：[原因]」

**各板块特殊业务规则**：

繁育信息规则：
- 配种日期 + 114天 = 预产期（自动计算，只读）
- 分娩日期与预产期差异超过7天需备注说明
- 产仔总数 = 活仔数 + 死胎数（提交前校验）

断奶信息规则：
- 断奶日龄低于18天或高于35天需备注说明
- 断奶仔猪数不能大于该胎次活仔数（提交前校验）

投入品使用规则：
- 兽药使用时休药期必填
- 批准文号：兽药、疫苗类型时必填

无害化处理规则：
- 委托处理时处理单位和处理凭证号必填
- 现场照片至少上传1张

出栏信息规则：
- 出栏数量不能大于当前猪舍存栏量（提交前校验）
- 出栏用途为「销售」时购买方名称、地址、电话必填

转栏信息规则：
- 转栏数量不能大于源猪舍存栏量（提交前校验）
- 目标猪舍不能与源猪舍相同（提交前校验）

#### 4.4.1 功能流程逻辑

**课程视频规则**：
- 学习进度：观看时长 / 视频总时长 × 100%，完成度 ≥ 80% 视为完成该课程
- 自动记录播放进度（`last_position`），下次打开从上次位置继续播放
- 实际播放时长累计（非视频总时长）

**政策资讯规则**：
- 打开资讯详情即视为阅读，写入 `knowledge_learn_record`（record_type=2）
- 置顶资讯（`is_top=1`）优先展示；重要资讯（`is_important=1`）标红显示；已读资讯标题变灰

**培训活动规则**：

活动状态判断：
- 报名中：当前时间 < 报名截止时间（`register_end_time`）
- 报名截止：当前时间 ≥ 报名截止时间 且 < 活动开始时间（`start_time`）
- 进行中：当前时间 ≥ 活动开始时间 且 ≤ 活动结束时间（`end_time`）
- 已结束：当前时间 > 活动结束时间

报名规则：
- 每个活动每个用户只能报名1次
- 报名人数达到名额上限（`max_participants`）后自动关闭报名
- 报名截止时间后不能报名
- 已报名用户可在活动开始前24小时取消报名（`register_status` 变为「已取消」）
- 审核通过后不能取消报名

报名审核规则：
- 报名提交后状态为「待审核」（`register_status=1`）
- 管理员审核通过后状态变为「已通过」（`register_status=2`），立即推送消息通知
- 审核拒绝后状态变为「已拒绝」（`register_status=3`），可再次报名

提醒规则：
- 审核通过后立即推送消息通知
- 活动开始前24小时推送提醒消息
- 活动开始前1小时再次推送提醒消息

**互动功能规则**：
- 评论内容：最少2个字符，最多500个字符
- 评论图片：最多3张，每张不超过5MB，格式 jpg/jpeg/png
- 回复最多3级（顶级评论 → 一级回复 → 二级回复）
- 用户可删除自己的评论（无回复时）
- 用户可编辑自己的评论（发布后5分钟内）
- 每个用户对每条评论只能点赞1次，可取消

### 5.2 目标与范围

**目标**：
1. 提供个人信息查看与修改入口。
2. 提供企业信息管理与猪舍管理入口，支持完善与修改。
3. 提供上报记录、学习记录、我的收藏、我的提问的快速查看入口（首屏5条 + 查看更多）。

#### 5.4.1 功能流程逻辑

**猪舍删除规则**：
- 当前存栏（`current_stock`）> 0 的猪舍不允许删除，提示「该猪舍存在存栏记录，无法删除」
- 当前存栏 = 0 的猪舍可删除，删除前弹出二次确认弹窗，确认后逻辑删除（del_flag=2）

**首屏展示规则**：
- 上报记录：展示最近5条，按创建时间倒序，每条展示上报类型、日期、猪舍、数量摘要
- 学习记录：展示最近5条，按最后学习时间倒序，每条展示课程/资讯标题、学习进度、时长
- 我的收藏：展示最近5条，按收藏时间倒序，每条展示标题、类型（视频/资讯）、封面或摘要
- 我的提问：展示最近5条，按提问时间倒序，每条展示提问摘要、回复数、是否有新回复

**独立列表页规则**：
- 每页加载20条，支持上拉加载更多
- 支持下拉刷新
- 空状态显示空图标和对应提示文案
- 点击某条记录进入对应详情页

**消息通知设置规则**：
- 系统通知开关（`notify_system`）：控制系统公告、政策通知、预警等推送与站内消息
- 活动提醒开关（`notify_activity`）：控制培训活动报名结果、活动开始前提醒
- 互动消息开关（`notify_interact`）：控制评论回复、@提醒、点赞等
- 开关变更自动保存（或提供「保存」按钮），保存成功后轻提示「保存成功」

**隐私设置规则**：
- 手机号展示开关（`privacy_phone_show`）：`0` 不展示、`1` 脱敏展示（在社区/评论等场景）
- 昵称头像展示开关（`privacy_nick_avatar_show`）：`0` 不展示、`1` 展示（在评论、活动名单等场景）
- 提供《隐私政策》文字链接，点击进入隐私政策页（富文本或静态页）

**目标**：
1. 提供统一的消息中心，汇聚所有类型的消息通知。
2. 支持消息分类查看（互动消息、系统通知），便于用户快速定位。
3. 支持消息已读/未读状态管理，支持全部已读操作。
4. 支持点击消息跳转到对应内容页面。

**非目标（Non-Goals）**：
- ❌ 不做实时推送（依赖用户进入消息中心时加载）。
- ❌ 不做微信服务通知/订阅消息（本期仅做站内消息）。
- ❌ 不做消息搜索功能。
- ❌ 不做消息删除功能（消息仅逻辑保留，不提供用户侧删除入口）。

### 6.3 现状与复用

**现状简述**：
- 现有系统无小程序消息通知功能，需全部新增。

**复用与差异**：

| 功能模块 | 复用内容 | 新增/修改内容 |
|---------|---------|--------------|
| 用户认证 | 复用 JWT Token 认证 | 无 |
| 消息通知 | 无现有功能 | 新增：knowledge_message 表及全部相关接口 |

### 6.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 消息列表（分类 Tab） | P0 | 全部 / 互动消息 / 系统通知 两个 Tab |
| 消息已读/未读标记 | P0 | 进入消息详情自动已读；支持「全部已读」 |
| 消息跳转 | P1 | 点击消息跳转到对应内容页 |
| 未读数量红点 | P0 | 首页消息图标和底部 Tab 显示未读数量 |

**关键流程**：

```
进入消息中心 → 展示消息列表（默认「全部」Tab）
        ↓
Tab 切换（全部 / 互动消息 / 系统通知）→ 立即筛选
        ↓
点击某条消息 → 标记已读 → 跳转对应内容页（若有关联）
        ↓
点击「全部已读」→ 所有消息标记为已读 → 未读红点清零
```

**交互与界面要点**：
- 消息列表卡片：发送者头像（系统消息用平台图标）、消息标题、消息摘要（最多2行）、时间（今天显示 HH:mm，昨天显示「昨天 HH:mm」，更早显示 MM-DD）、未读红点
- 未读消息卡片背景色与已读有明显区分（如未读背景浅蓝色）
- 顶部右侧「全部已读」按钮，点击后所有消息标记为已读

#### 6.4.1 功能流程逻辑

**消息生成规则**：

| 触发事件 | 消息类型 | 接收对象 | 消息标题模板 | 消息内容模板 |
|---------|---------|---------|------------|------------|
| 上报记录村级审核通过 | 系统通知（`3`） | 上报的养殖场用户 | 「审核通知」 | 「您的[上报类型]记录已通过村级审核，等待县级入库」 |
| 上报记录村级退回 | 系统通知（`3`） | 上报的养殖场用户 | 「审核通知」 | 「您的[上报类型]记录被村级退回，原因：[原因]」 |
| 上报记录县级入库 | 系统通知（`3`） | 上报的养殖场用户 | 「入库通知」 | 「您的[上报类型]记录已成功入库」 |
| 上报记录县级退回 | 系统通知（`3`） | 上报的养殖场用户 | 「审核通知」 | 「您的[上报类型]记录被县级退回，原因：[原因]」 |
| 上报记录提交（村级有待审核） | 系统通知（`3`） | 村级审核员 | 「待审核提醒」 | 「[企业名称]的[上报类型]记录已提交，请及时审核」 |
| 上报记录村级审核通过（县级待入库） | 系统通知（`3`） | 县级管理员 | 「待入库提醒」 | 「[企业名称]的[上报类型]记录已通过村级审核，请及时入库」 |
| 评论被回复 | 互动消息（`1`） | 被回复的评论作者 | 「有人回复了你」 | 「[用户昵称]回复了你：[回复内容摘要]」 |
| 评论被@提及 | 互动消息（`2`） | 被@的用户 | 「有人@了你」 | 「[用户昵称]在评论中@了你：[评论内容摘要]」 |
| 培训活动报名审核通过 | 活动通知（`4`） | 报名用户 | 「报名审核通过」 | 「您报名的[活动名称]已审核通过，请准时参加」 |
| 培训活动报名审核拒绝 | 活动通知（`4`） | 报名用户 | 「报名审核结果」 | 「您报名的[活动名称]审核未通过，如有疑问请联系主办方」 |
| 活动开始前24小时 | 活动通知（`4`） | 审核通过的报名用户 | 「活动提醒」 | 「[活动名称]将于明天[HH:mm]开始，请准时参加」 |
| 活动开始前1小时 | 活动通知（`4`） | 审核通过的报名用户 | 「活动提醒」 | 「[活动名称]将于1小时后开始，请准时参加」 |

**消息已读规则**：
- 点击消息卡片进入详情（或跳转到关联内容页）时，自动将该消息标记为已读（`is_read=1`，写入 `read_time`）
- 点击「全部已读」时，将当前用户所有 `is_read=0` 的消息批量标记为已读
- 未读数量实时计算：`knowledge_message` 中 `receiver_user_id=当前用户` 且 `is_read=0` 且 `del_flag=0` 的记录数量

**消息跳转规则**：

| 消息类型 | related_type | 跳转目标 |
|---------|-------------|---------|
| 上报审核通知 | `1` 养殖信息 | 对应上报记录详情页 |
| 评论回复/@ | `4` 评论 | 对应评论所在的内容详情页（视频/资讯/活动），并定位到该评论 |
| 活动通知 | `3` 培训活动 | 对应培训活动详情页 |
| 系统公告 | 无 related_type | 不跳转，在消息详情页展示完整内容 |

**消息清理规则**：
- 系统定期清理180天前的已读消息（定时任务，不影响用户侧功能）

#### 6.4.2 数据模型与字段定义

**消息表（knowledge_message）**：

| 字段名（中文） | 字段名（英文） | 类型 | 长度 | 必填 | 默认值 | 取值范围/枚举值 | 说明 |
|--------------|--------------|------|------|------|--------|----------------|------|
| 消息ID | message_id | bigint | 20 | 是 | 自增 | - | 主键 |
| 消息类型 | message_type | char | 1 | 是 | - | `1` 评论回复、`2` @提醒、`3` 系统通知、`4` 活动通知 | 共4种，无其他 |
| 接收用户ID | receiver_user_id | bigint | 20 | 是 | - | 关联 sys_user.user_id | - |
| 发送用户ID | sender_user_id | bigint | 20 | 否 | - | 关联 sys_user.user_id | 系统消息时为空 |
| 发送用户昵称 | sender_user_nickname | varchar | 50 | 否 | - | - | 冗余字段，系统自动填充，只读 |
| 发送用户头像 | sender_user_avatar | varchar | 200 | 否 | - | - | 冗余字段，系统自动填充，只读 |
| 消息标题 | message_title | varchar | 100 | 是 | - | - | - |
| 消息内容 | message_content | varchar | 500 | 是 | - | - | - |
| 关联类型 | related_type | char | 1 | 否 | - | `1` 养殖信息、`2` 课程视频、`3` 培训活动、`4` 评论 | 共4种，无其他 |
| 关联ID | related_id | bigint | 20 | 否 | - | 关联对应表的主键 | - |
| 是否已读 | is_read | char | 1 | 是 | `0` | `0` 未读、`1` 已读 | 仅2种 |
| 阅读时间 | read_time | datetime | - | 否 | - | - | 已读时系统自动填充，只读 |

普通索引：`idx_receiver_user` (receiver_user_id, is_read, del_flag) — 查询用户消息列表
普通索引：`idx_create_time` (create_time) — 定时清理过期消息

#### 6.4.3 界面交互逻辑

**Tab 切换立即筛选（强制）**：
- 消息列表 Tab：全部 / 互动消息 / 系统通知
- Tab 切换时立即触发筛选，列表内容即时更新，切换过程中显示 loading 状态，当前 Tab 有明显选中态样式
- 互动消息：`message_type` 为 `1`（评论回复）或 `2`（@提醒）的消息
- 系统通知：`message_type` 为 `3`（系统通知）或 `4`（活动通知）的消息

**消息列表交互**：
- 未读消息卡片背景色与已读有明显区分（未读背景浅蓝色，已读白色）
- 未读消息标题加粗显示
- 时间显示规则：今天显示 HH:mm，昨天显示「昨天 HH:mm」，更早显示 MM-DD
- 系统消息（无发送用户）显示平台图标作为头像
- 点击消息卡片：标记已读 → 若有关联内容则跳转对应页面，否则在消息详情页展示完整内容
- 顶部右侧「全部已读」按钮：点击后所有消息标记为已读，列表刷新，未读红点清零，轻提示「已全部标记为已读」

**消息详情页（无关联内容时）**：
- 展示：消息标题、发送时间、完整消息内容
- 底部无操作按钮，支持返回消息列表

**空状态处理**：
- 某 Tab 下无消息时：展示空图标 + 「暂无消息」提示文案
- 全部 Tab 无消息时：展示空图标 + 「暂无消息，请保持关注」提示文案

### 6.5 非功能需求

- **性能**：消息列表首屏加载时间 < 2 秒；未读数量实时计算（进入消息中心时刷新）
- **安全**：用户只能查看自己的消息（按 receiver_user_id 隔离）；所有接口携带有效 JWT Token
- **兼容性**：支持微信小程序基础库版本 >= 2.10.0，兼容 iOS 和 Android

## 功能一：企业信息管理

### 3.1 基本信息

- **功能名称**：企业信息管理
- **关联现有模块/功能**：
  - 小程序端个人中心（功能五）：小程序端已定义 `pig_enterprise` 表及企业信息查看/编辑接口，WEB 端企业信息管理功能与小程序端功能一致，数据共享同一张表
  - 用户认证：依赖现有 JWT 认证体系，接口携带 Bearer Token；登录后仅展示当前登录用户所关联的企业信息
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_prd/小程序/小程序.prd.md`（功能五：个人中心）
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 企业管理员 | `ent_admin` | 登录 WEB 端后，通过「企业信息管理 → 基础信息」入口查看并维护本企业的基础信息 | 查看企业名称、统一社会信用代码、企业类型、法人代表、联系电话、详细地址、养殖规模信息，支持修改和更新 |
| 企业填报员 | `ent_reporter` | 登录 WEB 端后，查看本企业基础信息（仅查看，无编辑权限） | 查看企业基础信息，不可编辑 |

> 角色名称与角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。

### 3.2 目标与范围

**目标**：
1. 提供 WEB 端企业基础信息的查看入口，展示本企业的全部基础信息字段。
2. 支持企业基础信息的在线编辑与保存，确保信息与小程序端同步（共享同一数据源）。
3. 支持企业营业执照照片的上传与管理。
4. 支持企业定位（经纬度）的展示，WEB 端以只读方式展示，不提供 WEB 端重新定位操作（定位由小程序端获取）。

**非目标（Non-Goals）**：
- ❌ 不支持在 WEB 端通过设备定位获取企业坐标（经纬度坐标由小程序端负责采集和更新）。
- ❌ 不支持新增企业（企业账号与企业绑定关系由平台管理端维护）。
- ❌ 不支持删除企业。
- ❌ 不支持修改企业状态（启用/停用由管理端操作）。
- ❌ 不做跨企业数据的查看（登录用户只能查看和编辑本企业信息）。

### 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 企业信息展示 | P0 | 展示本企业全部基础信息字段（详见 3.4.2 数据模型） |
| 企业信息编辑 | P0 | 支持修改企业名称、统一社会信用代码、企业类型、法人代表、联系电话、详细地址、养殖规模、备注 |
| 营业执照照片管理 | P1 | 支持上传/删除/预览营业执照照片（最多5张） |
| 企业定位展示 | P1 | 只读展示经度、纬度坐标（精确到小数点后6位），无重新定位按钮 |
| 表单前端校验 | P0 | 保存前对必填字段及格式进行校验（详见 3.4.3） |

**关键流程**：

```
进入「企业信息管理 → 基础信息」
  ↓
系统调用 GET /farm/enterprise/my，查询当前登录用户关联的企业信息
  ├── 查询成功 → 展示企业信息详情页
  └── 未关联企业 → 展示空状态提示「暂无企业信息，请联系平台管理员绑定企业」

企业信息详情展示：
  ├── 点击「编辑」按钮 → 表单字段变为可编辑态
  ├── 点击「保存」按钮 → 前端校验 → 校验通过发起 PUT /farm/enterprise → 保存成功提示 → 返回只读展示态
  └── 点击「取消」按钮 → 放弃修改，恢复为只读展示态（弹出二次确认弹窗，含未保存内容时）
```

**交互与界面要点**：
- 页面默认为只读详情展示，顶部右上角提供「编辑」按钮。
- 点击「编辑」后，各字段切换为可编辑输入控件；系统自动回显字段（企业ID、创建者、创建时间、更新时间）保持只读状态。
- 编辑态下顶部操作按钮变为「保存」和「取消」。
- 营业执照照片以图片列表形式展示，编辑态下提供上传、预览、删除操作；只读态仅支持预览。
- 「编辑」按钮受权限控制：仅拥有 `farm:enterprise:edit` 权限的用户可见，企业填报员（`ent_reporter`）进入页面时不展示「编辑」按钮。

#### 3.4.1 功能流程逻辑

**查询逻辑**：
- 页面加载时，以当前登录用户的 `user_id` 为条件，查询其关联的企业信息（`pig_enterprise.user_id = 当前用户ID`）。
- 若查询结果为空，展示空状态提示，不展示编辑按钮。
- 若查询到企业信息，展示详情页面，提供编辑功能。

**编辑保存逻辑**：
- 点击「编辑」后，将只读展示区切换为可编辑表单，同时加载企业类型字典数据。
- 点击「保存」时：
  1. 前端执行全字段校验（见 3.4.3）。
  2. 校验通过，调用 `PUT /farm/enterprise` 提交修改，请求体含 `enterprise_id` 及所有可编辑字段。
  3. 接口返回成功 → 页面提示「保存成功」（Message 成功提示，1.5 秒消失）→ 切换回只读展示态，展示最新数据。
  4. 接口返回失败 → 提示具体错误信息，保留编辑态，不重置表单内容。
- 点击「取消」时：
  - 若内容未修改 → 直接切换回只读展示态。
  - 若内容已修改 → 弹出二次确认弹窗，提示「确定放弃修改吗？」，点击「确认」切换回只读态，点击「取消」保留编辑态。

**营业执照照片逻辑**：
- 编辑态下，照片区域支持上传图片文件（仅限 `.jpg`、`.jpeg`、`.png`、`.gif` 格式，单张文件大小不超过 5MB，最多上传 5 张）。
- 上传使用 `POST /common/uploads` 接口，上传成功后将返回的图片 URL 追加到 `license_photo` 字段（多张以英文逗号分隔存储）。
- 删除某张照片时，从逗号分隔的 URL 列表中移除该 URL，删除操作仅在点击「保存」后才生效持久化。
- 只读态下，每张照片提供点击放大预览功能（使用 Element Plus 图片预览组件）。

**企业定位展示逻辑**：
- 展示经度（`longitude`）和纬度（`latitude`）字段，格式为「经度：XXX.XXXXXX，纬度：XXX.XXXXXX」。
- 若经纬度为空，展示「暂未定位，请使用小程序端获取企业位置」。
- WEB 端不提供重新定位按钮，坐标为只读展示。

- 点击「保存」时先对全部字段进行整体校验，任一字段不通过则阻断提交并将页面滚动至第一个错误字段处。

**加载与反馈状态**：
- 页面初始化加载企业信息时：页面展示加载骨架屏（skeleton），加载完成后渲染内容。
- 点击「保存」后：「保存」按钮置灰并显示 loading，防止重复提交；接口响应后恢复按钮状态。
- 保存成功：页面顶部显示 Element Plus Message 成功提示「保存成功」（1.5秒自动消失）。
- 保存失败：显示 Element Plus Message 错误提示，展示具体错误信息。

### 3.2 目标与范围

**目标**：
1. 提供 WEB 端圈舍列表展示，支持搜索与筛选，便于管理人员快速定位圈舍。
2. 支持圈舍新增，录入圈舍基础信息（名称、类型、设计容量）。
3. 支持圈舍编辑，修改圈舍基础信息（当前存栏字段不可手动编辑，由系统自动维护）。
4. 支持圈舍删除，仅允许删除当前存栏为0的圈舍，保护在用数据安全。
5. 与小程序端数据共享，WEB 端与小程序端操作的是同一套圈舍数据。

**非目标（Non-Goals）**：
- ❌ 不支持批量导入圈舍数据（本期仅支持单条新增）。
- ❌ 不支持修改圈舍的当前存栏数量（由入栏/出栏/转栏业务操作自动维护）。
- ❌ 不支持跨企业的圈舍查看（登录用户只能查看和管理本企业圈舍）。
- ❌ 不支持圈舍编号的批量修改。
- ❌ 不做圈舍与猪只的直接绑定管理（由信息填报各模块处理）。

**关键流程**：

```
进入「圈舍管理」页面
  ↓
系统调用 GET /farm/pigsty/list 加载圈舍列表（按当前企业过滤）
  ↓
列表展示圈舍信息 + 顶部搜索/筛选条件区 + 右上角「新增」按钮

新增流程：
  点击「新增」→ 弹出新增圈舍弹窗 → 填写表单 → 点击「确定」
    → 前端校验 → 校验通过 → 调用 POST /farm/pigsty
    → 成功：弹窗关闭，列表刷新，提示「新增成功」
    → 失败：弹窗保留，提示具体错误信息

编辑流程：
  点击某条记录的「编辑」→ 弹出编辑弹窗，回填当前数据 → 修改后点击「确定」
    → 前端校验 → 校验通过 → 调用 PUT /farm/pigsty
    → 成功：弹窗关闭，列表刷新，提示「修改成功」
    → 失败：弹窗保留，提示具体错误信息

删除流程：
  点击某条记录的「删除」
    ├── current_stock > 0 → 直接提示「该圈舍存在存栏记录（当前存栏X头），无法删除」，阻断操作
    └── current_stock = 0 → 弹出确认弹窗「确定删除圈舍「XXX」吗？此操作不可恢复」
          → 点击「确认」→ 调用 DELETE /farm/pigsty/{pigstyIds}
          → 成功：列表刷新，提示「删除成功」
          → 失败：提示具体错误信息

搜索/筛选流程：
  输入圈舍名称关键词 / 选择圈舍类型 / 选择圈舍状态 → 点击「查询」按钮 → 列表更新
  点击「重置」→ 清空搜索条件，重新加载全部列表
```

**交互与界面要点**：
- 圈舍列表采用 Element Plus Table 组件，默认每页20条，支持分页。
- 列表顶部提供搜索区域（圈舍名称文本框、圈舍类型下拉、圈舍状态下拉）及「查询」「重置」按钮，右侧提供「新增」按钮。
- 新增/编辑使用 Element Plus Dialog 弹窗形式，弹窗宽度 600px。
- 列表「操作」列提供「编辑」「删除」文字按钮。
- 当前存栏列展示当前存栏头数；若存栏 > 0，「删除」按钮置灰并禁用，悬浮提示「存在存栏记录，无法删除」。
- 「新增」按钮受权限控制：仅拥有 `farm:pigsty:add` 权限的用户可见；「编辑」「删除」按钮分别受 `farm:pigsty:edit`、`farm:pigsty:remove` 权限控制。

#### 3.4.1 功能流程逻辑

**圈舍删除规则**：
- 删除前端先判断 `current_stock` 字段值：
  - `current_stock > 0`：「删除」按钮置灰禁用，悬浮提示「存在存栏记录，无法删除」；点击时不触发弹窗，直接弹出错误提示「该圈舍存在存栏记录（当前存栏 X 头），无法删除」。
  - `current_stock = 0`：「删除」按钮可点击，点击后弹出二次确认弹窗。
- 后端删除接口同样需校验 `current_stock = 0`，防止前端绕过。
- 删除操作为逻辑删除（`del_flag = 2`）。

**圈舍编号自动生成规则**：
- 新增圈舍时，若「圈舍编号」字段用户未填写，保存后由后端自动生成（格式由后端定义）。
- 若用户手动填写圈舍编号，后端校验该编号在本企业内是否唯一，重复时返回错误信息「该圈舍编号已存在，请更换」。

**列表加载规则**：
- 列表接口需以 `enterprise_id` 过滤，仅返回当前登录用户所属企业的圈舍数据。
- 默认按 `create_time` 降序排列。
- 支持搜索参数：`pigsty_name`（模糊匹配，使用 `LIKE %keyword%`）、`pigsty_type`（精确匹配）、`status`（精确匹配）。
- 分页参数：`pageNum`（页码，默认1）、`pageSize`（每页条数，默认20，最大100）。

|-----|------|---------|---------|---------|
| 圈舍名称 | 是 | 非空，最大100字符 | 失焦 + 点击确定时 | 「圈舍名称不能为空」/「圈舍名称最大100字符」 |
| 圈舍类型 | 是 | 枚举值：`1`/`2`/`3`/`4`/`5`/`6` | 失焦 + 点击确定时 | 「请选择圈舍类型」 |
| 设计容量 | 是 | 正整数，最小值1，最大值9999 | 失焦 + 点击确定时 | 「设计容量不能为空」/「设计容量须在1～9999之间，且为正整数」 |
| 状态 | 是 | 枚举值：`0`/`1`/`2` | 失焦 + 点击确定时 | 「请选择圈舍状态」 |
| 圈舍编号 | 否 | 最大50字符；企业内唯一校验由后端返回 | 失焦时校验长度 + 点击确定时 | 「圈舍编号最大50字符」（长度）；后端返回唯一冲突时提示「该圈舍编号已存在，请更换」 |
| 建筑面积 | 否 | 大于等于0.01，最大值99999.99，保留不超过2位小数 | 失焦 + 点击确定时 | 「建筑面积须在0.01～99999.99之间」 |
| 备注 | 否 | 最大500字符 | 失焦 + 点击确定时 | 「备注最大500字符」 |

- 点击弹窗「确定」时对全部字段进行整体校验，任一字段不通过则阻断提交，焦点定位至第一个错误字段。
- 点击弹窗「取消」时弹窗关闭，表单重置。

**加载与反馈状态**：
- 列表分页加载时展示表格行骨架屏效果。
- 弹窗表单提交时「确定」按钮置灰并显示 loading，防止重复提交。
- 新增/编辑/删除操作成功后，列表自动刷新（重新调用列表接口）。
- 操作成功提示 Element Plus Message 成功提示（1.5秒消失）；失败时提示错误信息。

#### 3.4.4 接口路径定义（强制）

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 圈舍列表（分页） | GET | `/farm/pigsty/list` | pageNum、pageSize、enterpriseId（从登录上下文取）、pigstyName（模糊）、pigstyType（精确）、status（精确） | 分页圈舍列表 + 总数 | 🆕 新增；数据权限按企业 |
| 圈舍详情 | GET | `/farm/pigsty/{pigstyId}` | pigstyId（路径参数） | 圈舍信息对象（见 3.4.2 全字段） | 🆕 新增 |
| 新增圈舍 | POST | `/farm/pigsty` | 见 3.4.2 字段定义（除 pigsty_id、enterprise_id、current_stock、create_by、create_time、update_by、update_time 外） | 操作结果（code、msg） | 🆕 新增；enterprise_id 由后端从登录上下文填充 |

### 3.5 非功能需求

- **性能**：圈舍列表首屏加载时间 < 1.5 秒；新增/编辑/删除操作响应时间 < 3 秒；单企业圈舍数量预期不超过500条，分页查询无需额外优化。
- **安全与权限**：
  - 权限标识：`farm:pigsty:list`（列表查看）、`farm:pigsty:add`（新增）、`farm:pigsty:edit`（编辑）、`farm:pigsty:remove`（删除）。
  - 角色与权限对应：企业管理员（`ent_admin`）拥有全部圈舍权限（list/add/edit/remove）；企业填报员（`ent_reporter`）拥有 `farm:pigsty:list` + `farm:pigsty:add` + `farm:pigsty:edit`，不拥有 `farm:pigsty:remove`。角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1。
  - 数据权限：所有圈舍接口需以企业维度过滤，后端须校验 `pig_pigsty.enterprise_id` 关联到当前登录用户所属企业，防止越权访问。数据范围规则遵循全局权限体系 §2.1（企业角色 `data_scope = '4'`，本部门及以下）。
  - 删除接口须后端双重校验 `current_stock = 0`，防止前端绕过保护。
- **兼容性**：支持 Chrome 90+、Edge 90+、Firefox 88+ 等主流浏览器；适配 1280×720 及以上分辨率。

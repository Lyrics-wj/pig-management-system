## 功能一：员工信息管理

### 3.1 基本信息

- **功能名称**：员工信息管理
- **关联现有模块/功能**：
  - 用户认证：依赖现有 JWT 认证体系，登录后仅展示当前登录用户所属企业的员工信息
  - 系统用户管理（`/system/user`）：员工信息为企业自建的员工档案，与系统登录账号解耦；员工是否关联系统账号为可选项，非强依赖
  - 企业信息管理（基础信息-功能一）：员工信息依赖 `pig_enterprise`，一名员工属于一家企业
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_spec/现有数据库说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 企业管理员 | `ent_admin` | 登录 WEB 端后，通过「企业信息管理 → 员工信息」入口管理本企业员工档案 | 录入员工基础信息（姓名、职位、联系方式），查看员工列表，编辑员工信息，对离职员工进行停用或删除处理 |
| 企业填报员 | `ent_reporter` | 日常使用 | 查看本企业员工列表，支持按条件搜索定位员工 |

> 角色名称与角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。

### 3.2 目标与范围

**目标**：
1. 提供养殖企业员工档案的集中管理入口，支持员工信息的增删改查。
2. 支持按姓名、职位、状态条件搜索员工，便于快速定位。
3. 记录员工的岗位职责、联系方式、入职时间核心信息，为养殖场日常管理提供人员台账依据。
4. 支持员工状态管理（在职/离职），离职员工不删除数据，仅停用。

**非目标（Non-Goals）**：
- ❌ 不做员工薪资、考勤、绩效管理（本功能仅做基础信息档案管理）。
- ❌ 不做员工与系统登录账号的强关联绑定（账号创建和管理由平台管理端负责）。
- ❌ 不做跨企业员工信息的查看（登录用户只能查看本企业员工）。
- ❌ 不做批量导入/导出员工信息（本期仅支持单条录入，导出可在后续迭代补充）。
- ❌ 不做员工权限管理（权限管理由系统管理端统一操作）。

### 3.3 现状与复用

**现状简述**：
- 现有系统无企业端员工信息管理功能，需全部新增。
- 系统已有 `sys_user`（用户信息表，见现有数据库说明.spec.md §2.1）管理平台登录账号，但员工档案与系统账号属于不同维度，员工信息为养殖企业自主维护的人员台账，无需与 `sys_user` 强绑定。
- 需新建 `pig_employee`（企业员工表）存储员工档案数据。

**复用检查结论**：

### 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 员工列表展示 | P0 | 分页展示本企业所有员工，展示姓名、工号、职位、联系电话、入职日期、状态、操作 |
| 员工搜索与筛选 | P1 | 支持按员工姓名模糊搜索、职位精确筛选、状态精确筛选 |
| 新增员工 | P0 | 弹窗表单新增员工，录入员工基础信息 |
| 编辑员工 | P0 | 弹窗表单编辑员工信息 |
| 删除员工 | P1 | 删除员工档案（逻辑删除），仅允许删除状态为「离职」的员工 |
| 员工状态切换 | P0 | 在列表中直接切换员工在职/离职状态（通过操作按钮） |

**关键流程**：

```
进入「企业信息管理 → 员工信息」
  ↓
系统调用 GET /farm/employees/list 加载员工列表（按当前企业过滤）
  ↓
列表展示员工信息 + 搜索筛选区 + 「新增」按钮

新增流程：
  点击「新增」→ 弹出新增员工弹窗 → 填写表单 → 点击「确定」
    → 前端校验 → 校验通过 → 调用 POST /farm/employees
    → 成功：弹窗关闭，列表刷新，提示「新增成功」
    → 失败：弹窗保留，提示具体错误信息

编辑流程：
  点击某条记录的「编辑」→ 弹出编辑弹窗，回填当前数据 → 修改后点击「确定」
    → 前端校验 → 校验通过 → 调用 PUT /farm/employees
    → 成功：弹窗关闭，列表刷新，提示「修改成功」
    → 失败：弹窗保留，提示具体错误信息

状态切换流程：
  点击列表操作列「停用」/「启用」按钮
    → 弹出确认弹窗「确定将员工「XXX」设为离职吗？」
    → 确认 → 调用 PUT /farm/employees/changeStatus
    → 成功：列表刷新，提示「操作成功」

删除流程：
  点击某条记录的「删除」
    ├── 员工状态为「在职」→ 直接提示「在职员工不可删除，请先将员工状态设为离职」，阻断操作
    └── 员工状态为「离职」→ 弹出确认弹窗「确定删除员工「XXX」吗？此操作不可恢复」
          → 点击「确认」→ 调用 DELETE /farm/employees/{employeeIds}
          → 成功：列表刷新，提示「删除成功」
```

**交互与界面要点**：
- 员工列表采用 Element Plus Table 组件，默认每页20条，支持分页。
- 列表顶部提供搜索区域（员工姓名文本框、职位下拉、状态下拉）及「查询」「重置」按钮，右侧提供「新增」按钮。
- 新增/编辑使用 Element Plus Dialog 弹窗形式，弹窗宽度 600px。
- 列表「操作」列提供「编辑」「停用/启用」「删除」文字按钮。
- 员工为「在职」状态时「删除」按钮置灰禁用，悬浮提示「在职员工不可删除」。
- 「新增」按钮受权限控制：仅拥有 `farm:employee:add` 权限的用户可见；「编辑」「停用/启用」「删除」按钮分别受 `farm:employee:edit`、`farm:employee:changeStatus`、`farm:employee:remove` 权限控制。

#### 3.4.1 功能流程逻辑

**员工删除规则**：
- 删除前端先判断 `status` 字段值：
  - `status = 0`（在职）：「删除」按钮置灰禁用，悬浮提示「在职员工不可删除」；点击时阻断操作并弹出错误提示「在职员工不可删除，请先将员工状态设为离职」。
  - `status = 1`（离职）：「删除」按钮可点击，点击后弹出二次确认弹窗。
- 后端删除接口同样需校验 `status = 1`，防止前端绕过。
- 删除操作为逻辑删除（`del_flag = 2`）。

**工号自动生成规则**：
- 新增员工时，若「工号」字段用户未填写，保存后由后端自动生成（格式：`EMP` + 8位数字，如 `EMP00000001`，按企业内序号递增）。
- 若用户手动填写工号，后端校验该工号在本企业内是否唯一，重复时返回错误信息「该工号已存在，请更换」。

**列表加载规则**：
- 列表接口需以 `enterprise_id` 过滤，仅返回当前登录用户所属企业的员工数据。
- 默认按 `create_time` 降序排列。
- 支持搜索参数：`employee_name`（模糊匹配，使用 `LIKE %keyword%`）、`position`（精确匹配）、`status`（精确匹配）。
- 分页参数：`pageNum`（页码，默认1）、`pageSize`（每页条数，默认20，最大100）。

| 备注 | 否 | 最大500字符 | 失焦 + 点击确定时 | 「备注最大500字符」 |

- 离职日期与入职日期的联动校验：当离职日期不为空时，校验离职日期 ≥ 入职日期，不通过则提示「离职日期不能早于入职日期」。
- 错误提示紧邻对应字段下方展示，不得仅用全局弹窗。
- 点击「确定」时先对全部字段进行整体校验，任一字段不通过则阻断提交并将焦点定位至第一个错误字段。

**状态切换交互**：
- 列表操作列「停用」/「启用」按钮：
  - 员工状态为「在职（0）」时，显示「停用」按钮（橙色文字），点击后弹出确认弹窗「确定将员工「XXX」设为离职吗？离职后该员工将不再出现在在职列表中」，确认后调用状态切换接口。
  - 员工状态为「离职（1）」时，显示「启用」按钮（绿色文字），点击后弹出确认弹窗「确定将员工「XXX」恢复为在职吗？」，确认后调用状态切换接口。
- 状态切换成功后列表刷新，提示「操作成功」（1.5秒消失）。

**加载与反馈状态**：
- 列表分页加载时展示表格行骨架屏效果。
- 弹窗表单提交时「确定」按钮置灰并显示 loading，防止重复提交。
- 新增/编辑/删除/状态切换操作成功后，列表自动刷新。

### 3.5 非功能需求

- **性能**：员工列表首屏加载时间 < 1.5 秒；新增/编辑/删除操作响应时间 < 3 秒；单企业员工数量预期不超过200条，分页查询无需额外优化。
- **安全与权限**：
  - 权限标识：`farm:employee:list`（列表查看）、`farm:employee:add`（新增）、`farm:employee:edit`（编辑）、`farm:employee:remove`（删除）、`farm:employee:changeStatus`（状态切换）。
  - 角色与权限对应：企业管理员（`ent_admin`）拥有全部员工管理权限（list/add/edit/remove/changeStatus）；企业填报员（`ent_reporter`）仅拥有 `farm:employee:list`（仅查看）。角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1。
  - 数据权限：所有员工接口需以企业维度过滤，后端须校验 `pig_employee.enterprise_id` 关联到当前登录用户所属企业，防止越权访问。数据范围规则遵循全局权限体系 §2.1（企业角色 `data_scope = '4'`，本部门及以下）。
  - 删除接口须后端双重校验 `status = 1`（离职），防止前端绕过保护。
  - 身份证号作为敏感信息，列表页不展示身份证号字段，仅在详情弹窗或编辑弹窗中展示，且展示时做脱敏处理（展示格式：`150***********5018`，中间8位用`*`替代）。
- **兼容性**：支持 Chrome 90+、Edge 90+、Firefox 88+ 等主流浏览器；适配 1280×720 及以上分辨率。

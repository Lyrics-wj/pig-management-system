## 3.1 基本信息

- **功能名称**：政策资讯查看
- **关联现有模块/功能**：
  - 用户认证：依赖现有 JWT Token 认证（`/login`、`/getInfo`）
  - 知识课堂（小程序）：政策资讯内容与小程序端共用同一数据表 `knowledge_policy`，WEB企业端仅提供查看入口，内容由监管端发布

## 3.2 目标与范围

**目标**：
1. 为WEB企业端用户提供与小程序端一致的政策资讯浏览入口，支持按分类筛选、关键词搜索。
2. 支持富文本内容阅读，阅读即记录已读状态；置顶、重要标识与小程序端展示逻辑一致。
3. 支持点赞、收藏、评论互动，逻辑与小程序端保持一致。
4. 实现可见范围过滤：企业端仅展示 `visibility_type=0`（全部可见）的政策，以及 `visibility_type=1`（部分可见）且当前用户所属企业在 `knowledge_policy_visibility` 中存在关联记录的政策。
5. 支持项目申报入口：允许申报且在申报时限内的政策详情页展示「去申报」按钮，点击后提示用户前往「项目申报」模块进行申报。

**非目标（Non-Goals）**：
- 不在WEB企业端提供政策资讯的发布、编辑、下架、删除操作（内容管理由WEB监管端负责）。
- 不在WEB企业端展示或管理政策可见范围设置（可见范围由监管端管理，企业端仅被动过滤）。
- 不做个性化推荐算法（仅支持分类筛选与关键词搜索）。
- 不做政策资讯的审核流程（审核由监管端完成后方可展示）。
- 不在本PRD中实现项目申报的具体表单、审批流程、申报记录管理（由项目申报板块PRD负责）；本功能仅提供从政策详情跳转至项目申报模块的入口和提示。

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 政策资讯列表（分类Tab筛选） | P0 | 分类Tab即时筛选，置顶/重要/已读状态展示；仅展示对本企业可见的已发布政策 |
| 关键词搜索 | P0 | 搜索框实时触发，按标题/来源匹配 |
| 政策资讯详情阅读 | P0 | 富文本展示，阅读即记录已读，附件下载；后端校验可见权限 |
| 点赞 | P1 | 乐观更新，每用户每条只能点赞1次，可取消 |
| 收藏 | P1 | 乐观更新，可取消收藏 |
| 评论与回复 | P1 | 最多3级回复，支持图片附件，评论内容校验 |
| 项目申报入口 | P0 | 允许申报且在申报时限内的政策详情页展示「去申报」按钮，点击提示跳转至项目申报模块 |

**关键流程**：

```
政策资讯浏览主流程：
进入政策资讯页 → 后端按可见范围过滤（visibility_type=0 的全部 + visibility_type=1 且本企业关联的）
  → 选择分类Tab（立即筛选）→ 浏览列表 → 点击资讯卡片 → 后端校验可见权限
    ├── 有权查看 → 阅读详情 → 自动记录已读 → 点赞 / 收藏 / 评论
    │                                        └── 若该政策允许申报且在申报时限内 → 详情页展示「去申报」按钮
    │                                            → 点击「去申报」→ 弹出提示「请到"项目申报"板块进行项目申报」
    │                                            → 点击「前往项目申报」→ 跳转至项目申报页面
    └── 无权查看（不应出现，兜底处理）→ 提示「该政策暂无查看权限」→ 返回列表

可见范围过滤逻辑（后端实现，前端无感知）：
  条件1：publish_status = 1（已发布）
  条件2：del_flag = 0（未删除）
  条件3：visibility_type = 0（全部可见）
       OR（visibility_type = 1 AND 当前用户所属企业 dept_id 存在于 knowledge_policy_visibility 表中）

搜索流程：
输入搜索关键词（防抖300ms后触发）→ 列表刷新展示匹配结果（仍受可见范围限制）→ 清空关键词则恢复分类列表
```

**交互与界面要点**：
- 列表页顶部有分类Tab：全部 / 国家政策 / 地方政策 / 行业动态 / 技术指南，Tab切换立即筛选，列表即时刷新
- 置顶资讯（`is_top=1`）排在列表最前，置顶资讯可叠加重要/已读状态
- 重要资讯（`is_important=1`）标题显示红色文字
- 已读资讯（`knowledge_learn_record` 中存在对应 record_type=2 的记录）标题显示灰色文字
- 资讯卡片展示：封面图（无封面时用占位图）、标题、分类标签、来源、发布时间、阅读数、点赞数、收藏数
- 详情页展示资讯完整内容（富文本），下方固定评论输入区域
- 企业端用户无需感知可见范围的存在——列表和详情均由后端静默过滤，前端不展示可见范围相关信息

#### 3.4.1 功能流程逻辑

**可见范围过滤规则（后端实现）**：
- 企业端列表接口返回数据时，后端根据当前登录用户所属企业（`sys_user` 关联 `sys_dept`）自动过滤：
  - `visibility_type=0` 的政策：所有企业用户均可查看
  - `visibility_type=1` 的政策：仅当 `knowledge_policy_visibility` 表中存在 `policy_id` + 当前用户所属企业 `dept_id` 的记录时才返回
- 企业端详情接口返回数据时，后端校验当前用户是否有权查看该政策；无权则返回404或403
- 可见范围过滤对企业端用户完全透明，前端不展示任何可见范围相关的筛选条件或标签

**阅读记录规则**：
- 用户点击进入资讯详情页即视为已读，后端写入 `knowledge_learn_record`（`record_type=2`，`content_id=policy_id`，`learn_progress=100`，`is_completed=1`）
- 若已存在对应记录则不重复写入，仅更新 `update_time`
- 已读后列表中该条资讯标题变灰（用于区分未读内容）

**置顶与排序规则**：
- 置顶资讯（`is_top=1`）优先展示，多条置顶资讯按 `sort_order` 升序排列
- 非置顶资讯按 `publish_time` 倒序排列
- 切换分类Tab时，置顶优先规则继续适用

**分类筛选规则**：
- 点击 Tab 「全部」：展示所有对本企业可见且 `publish_status=1`（已发布）的资讯
- 点击其他 Tab（国家政策/地方政策/行业动态/技术指南）：在可见范围内仅展示对应 `policy_category` 值的资讯

**搜索规则**：
- 搜索框输入后防抖300ms触发搜索，同时匹配 `policy_title`（标题模糊匹配）和 `policy_source`（来源模糊匹配）
- 搜索模式下，分类Tab不可交互（置灰），搜索结果不受分类Tab限制（但仍受可见范围限制）
- 清空搜索关键词（输入框为空）后，恢复分类Tab可交互，列表回到当前Tab对应分类内容

**点赞与收藏交互规则（乐观更新）**：
- 点击点赞/收藏图标后，前端立即将数量 +1 并高亮图标（乐观更新），同时后端异步写入记录
- 若后端请求失败，前端回滚数量并提示「操作失败，请重试」
- 再次点击已点赞/已收藏图标：取消点赞/收藏，数量 -1，图标恢复未激活状态
- 图标样式：未激活为灰色轮廓，已激活为填充色（点赞橙色，收藏黄色）
- 每个用户对每条政策资讯只能点赞1次（`knowledge_like` 唯一索引保证）

**项目申报入口规则**：
- 详情页「去申报」按钮仅在同时满足以下全部条件时展示：
  - `allow_apply=1`（允许申报）
  - `apply_status=1`（申报中，即未被监管端手动关闭）
  - 当前时间 ≤ `apply_deadline`（未超过申报截止时间）
- 不满足上述任一条件时，详情页不展示「去申报」按钮，用户不感知该政策曾允许申报
- 「去申报」按钮位置：详情页正文下方、附件区域之后、互动操作栏之前，独立一行居中展示
- 按钮样式：主色按钮，文案「去申报」，按钮前方展示申报截止时间文案「申报截止：YYYY-MM-DD HH:mm」
- 点击「去申报」按钮后的交互：
  - 弹出提示弹窗，弹窗内容为「请到"项目申报"板块进行项目申报」
  - 弹窗底部两个按钮：「前往项目申报」（主色按钮）、「取消」（文字链接）
  - 点击「前往项目申报」：跳转至WEB企业端「项目申报」页面（路由地址由项目申报板块PRD定义）
  - 点击「取消」：关闭弹窗，留在当前详情页
- 列表页资讯卡片不展示申报相关信息，仅在详情页展示申报入口

**评论规则**：
- 评论区在详情页正文下方展示，顶级评论按发布时间倒序；每条顶级评论下展示最新2条回复，回复超过2条时显示「查看全部X条回复」
- 仅展示 `audit_status=2`（已通过）的评论
- 用户可删除自己的评论（该评论无子回复时），删除前弹出二次确认
- 用户可在评论发布后5分钟内编辑自己的评论，超时后编辑入口隐藏
- 回复最多3级（顶级评论 → 一级回复 → 二级回复），超过3级时在二级回复层继续追加

#### 3.4.2 数据模型与字段定义

| 字段名（中文） | 字段名（英文） | 类型 | 长度 | 必填 | 默认值 | 取值范围/枚举值 | 说明 |
|--------------|--------------|------|------|------|--------|----------------|------|
| 资讯ID | policy_id | bigint | 20 | 是 | 自增 | - | 主键 |
| 资讯标题 | policy_title | varchar | 200 | 是 | - | - | - |
| 资讯摘要 | policy_summary | varchar | 500 | 否 | - | - | - |
| 资讯分类 | policy_category | char | 1 | 是 | - | `1` 国家政策、`2` 地方政策、`3` 行业动态、`4` 技术指南 | 共4种，无其他 |
| 资讯来源 | policy_source | varchar | 100 | 是 | - | - | 如：农业农村部 |
| 来源链接 | source_url | varchar | 500 | 否 | - | - | 原文链接 |
| 封面图片 | cover_image | varchar | 200 | 否 | - | - | URL地址 |
| 正文内容 | content | text | - | 是 | - | - | 富文本内容 |

| 评论数 | comment_count | int | 11 | 是 | `0` | 最小值0 | 累计评论数，只读 |
| 收藏数 | collect_count | int | 11 | 是 | `0` | 最小值0 | 累计收藏数，只读 |
| 是否置顶 | is_top | char | 1 | 是 | `0` | `0` 否、`1` 是 | 仅2种 |
| 是否重要 | is_important | char | 1 | 是 | `0` | `0` 否、`1` 是 | 仅2种，重要资讯标红 |

#### 3.4.3 界面交互逻辑

**列表页布局**：
- 顶部搜索框（placeholder：「搜索资讯标题或来源」），右侧无需额外按钮，防抖300ms后即时触发
- 搜索框下方为分类Tab栏：全部 / 国家政策 / 地方政策 / 行业动态 / 技术指南
  - 切换Tab时立即筛选，列表区域显示 loading 骨架屏后刷新内容
  - 当前激活Tab有明显选中态（下划线或背景色高亮）
  - 搜索模式下Tab置灰，不响应点击
- 列表区域每条资讯以卡片形式展示，卡片从上到下依次展示：
  - 第一行：置顶标签（若 `is_top=1` 显示「[置顶]」标签，红色）；分类标签（绿色胶囊）
  - 标题（若 `is_important=1` 显示红色文字；若已读则显示灰色文字；否则显示默认黑色文字）
  - 摘要（若有 `policy_summary` 则展示，最多2行，超出省略）
  - 封面图（若有 `cover_image` 则右侧展示缩略图，宽80px×高60px）
  - 底部信息行：来源 + 发布时间（左对齐）；阅读数+点赞数+收藏数（右对齐，图标+数字）
- 列表支持分页（每页20条），滚动到底部自动加载下一页；无更多数据时显示「已加载全部内容」
- 空列表时展示空状态图标和文案「暂无相关政策资讯」
- 列表不展示任何可见范围相关信息，用户无需感知可见范围机制

**详情页布局**：
- 顶部：资讯标题（大号字体，粗体）
- 副标题行：分类标签（胶囊）+ 来源 + 发布时间
- 若 `is_important=1` 在标题下方展示红色「重要」角标
- 正文区域：富文本渲染，支持图片、段落格式
- 附件区域（若 `attachment_urls` 非空）：列出所有附件，每条附件展示文件名和下载图标，点击触发下载
- 项目申报入口区域（仅当 allow_apply=1 且 apply_status=1 且当前时间 ≤ apply_deadline 时展示）：独立一行居中展示「去申报」主色按钮，按钮前方显示申报截止时间文案「申报截止：YYYY-MM-DD HH:mm」
- 互动操作栏（固定在详情页底部或正文下方）：阅读数（只读）/ 点赞（可点击）/ 收藏（可点击）/ 评论数（点击跳转评论区）
- 评论区在互动操作栏下方，展示评论列表（仅展示 `audit_status=2` 的评论）+ 底部固定评论输入框

**交互细节**：
- 进入详情页时，顶部 loading 状态（骨架屏）→ 内容加载完成后显示
- 若后端返回403/404（用户无权查看该政策），前端展示提示页「该政策暂无查看权限」，底部「返回列表」按钮
- 点赞/收藏乐观更新：点击后图标立即切换高亮并数量+1，失败时回滚并展示顶部 toast「操作失败，请重试」（持续2秒后自动消失）
- 评论提交后，评论列表自动滚动到新评论位置（若审核后展示，则提示「评论已提交，等待审核通过后展示」）
- 附件下载：点击后弹出浏览器原生下载，不在新标签页打开
- 「去申报」按钮：点击后弹出提示弹窗「请到"项目申报"板块进行项目申报」，弹窗底部「前往项目申报」（主色按钮，点击跳转至项目申报页面）和「取消」（文字链接，关闭弹窗）

**评论表单前端校验规则（强制）**：

| 字段 | 必填 | 格式校验 | 提示文案 |

## 3.5 非功能需求

- **性能**：政策资讯列表首屏加载时间 < 2秒（正常网络环境，含分类Tab默认「全部」数据）；详情页富文本渲染完成时间 < 3秒；可见范围过滤查询不应导致列表接口响应时间明显增加（通过 `knowledge_policy_visibility` 表索引优化）。
- **安全与权限**：所有接口携带有效 JWT Token；评论内容提交后需经监管端审核通过才可展示，前端不展示 `audit_status≠2` 的评论；详情接口须校验当前用户所属企业对该政策的可见权限，无权时返回403。角色定义、数据范围统一以 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` 为唯一基准，不在本PRD中重新定义或变更角色体系。
- **兼容性**：支持 Chrome 90+、Edge 90+、Safari 14+；页面响应式布局，适配1280px及以上分辨率。

## 3.6 验收标准

**可见范围过滤**：
- [ ] 企业端政策资讯列表仅展示 `visibility_type=0`（全部可见）的政策以及 `visibility_type=1`（部分可见）且当前用户所属企业在 `knowledge_policy_visibility` 中存在关联记录的政策
- [ ] 监管端将某政策从全部可见改为部分可见后，未被选择的企业用户在企业端列表中不再看到该政策
- [ ] 监管端将某政策从部分可见改为全部可见后，所有企业用户在企业端列表中均可看到该政策
- [ ] 企业端页面不展示任何可见范围相关信息（无「全部可见」「部分可见」标签或筛选条件）
- [ ] 企业端用户尝试通过URL直接访问无权查看的政策详情时，后端返回403，前端展示「该政策暂无查看权限」提示页

**列表与分类筛选**：
- [ ] 政策资讯列表页顶部显示分类Tab（全部/国家政策/地方政策/行业动态/技术指南），点击Tab立即筛选并刷新列表，切换过程显示loading状态，激活Tab有明显选中态
- [ ] 置顶资讯（`is_top=1`）排在列表最前，展示「置顶」标签
- [ ] 重要资讯（`is_important=1`）标题以红色文字显示
- [ ] 已读资讯标题以灰色文字显示，未读资讯以默认黑色文字显示
- [ ] 搜索框输入防抖300ms后触发，同时匹配标题和来源，结果正确展示且受可见范围限制；搜索模式下Tab置灰不可交互；清空搜索关键词后Tab恢复可交互
- [ ] 列表支持分页（每页20条），滚动到底部自动加载下一页，无更多数据时展示「已加载全部内容」
- [ ] 空列表时展示空状态图标和「暂无相关政策资讯」文案

**项目申报入口**：
- [ ] 允许申报（allow_apply=1）且申报中（apply_status=1）且当前时间 ≤ 申报截止时间的政策，详情页展示「去申报」按钮及申报截止时间
- [ ] 不允许申报、已关闭申报、已超过申报截止时间的政策，详情页不展示「去申报」按钮
- [ ] 点击「去申报」按钮，弹出提示弹窗「请到"项目申报"板块进行项目申报」
- [ ] 弹窗中点击「前往项目申报」跳转至项目申报页面；点击「取消」关闭弹窗
- [ ] 列表页资讯卡片不展示任何申报相关信息

**详情与互动**：
- [ ] 点击资讯卡片进入详情页，详情页展示完整富文本内容，阅读后自动写入已读记录
- [ ] 若资讯有附件（`attachment_urls` 非空），详情页显示附件列表，点击可下载
- [ ] 点赞操作乐观更新：点击后图标立即高亮、数量+1；失败时回滚并展示「操作失败，请重试」提示

### 企业端可见范围过滤SQL示意（后端参考）

```sql
SELECT kp.*
FROM knowledge_policy kp
WHERE kp.publish_status = '1'
  AND kp.del_flag = '0'
  AND (
    kp.visibility_type = '0'
    OR (
      kp.visibility_type = '1'
      AND EXISTS (
        SELECT 1 FROM knowledge_policy_visibility kpv
        WHERE kpv.policy_id = kp.policy_id
          AND kpv.dept_id = #{currentUserDeptId}
      )
    )
  )
ORDER BY kp.is_top DESC, kp.sort_order ASC, kp.publish_time DESC
```

## 功能一：项目申报通知查看

### 1.1 基本信息

- **功能名称**：项目申报通知查看
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 站内消息：复用现有消息通知模块（若已有）
  - 政策资讯：企业端用户也可从「政策资讯」详情页的「去申报」按钮跳转至申报填报页（功能二），此时携带 `policy_id` 参数，见 `doc_prd/WEB/企业端/政策信息查看/WEB企业端-政策资讯.prd.md` §3.4.1 项目申报入口规则
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 企业管理员 | `ent_admin` | 查看县农业农村局发布的项目申报通知 | 了解申报项目名称、申报条件、截止时间等信息，点击"去申报"进入填报流程 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。本功能仅面向企业管理员（`ent_admin`），企业填报员（`ent_reporter`）无项目申报权限。

### 1.2 目标与范围

**目标**：
1. 为企业端用户提供项目申报通知列表，展示由管理端（县农业农村局）发布的申报通知。
2. 支持查看通知详情，了解项目背景、申报条件、申报材料要求、截止时间等。
3. 提供"去申报"入口按钮，点击后跳转至申报填报页面（功能二）。
4. 展示通知状态（进行中/已截止/未开始），仅"进行中"状态的通知可点击"去申报"。

**非目标（Non-Goals）**：
- ❌ 不提供通知发布、编辑、删除功能（由管理端实现）。
- ❌ 不支持通知导出功能。
- ❌ 不提供历史通知归档删除功能。

### 1.3 现状与复用

**现状简述**：
- 现有 WEB 端无项目申报通知浏览功能，需新增页面与前端路由。
- 申报通知数据由管理端（县农业农村局工作人员）在管理端系统中发布，企业端通过接口读取展示。

#### 1.4.1 功能流程逻辑

**通知状态定义**：
- `NOT_STARTED`（未开始）：当前时间 < 通知发布的申报开始时间
- `IN_PROGRESS`（进行中）：申报开始时间 ≤ 当前时间 ≤ 申报截止时间
- `EXPIRED`（已截止）：当前时间 > 申报截止时间

**按钮展示逻辑**：
- 已有申报记录（`application_status` 不为 `WITHDRAWN`）→ 显示"查看申报进度"按钮（主色按钮），隐藏"去申报"按钮
- 无申报记录 + 通知状态为 `IN_PROGRESS` → 显示"去申报"按钮（主色按钮）
- 无申报记录 + 通知状态为 `NOT_STARTED` → 显示"去申报"按钮（禁用态灰色），hover 提示"申报未开始"
- 无申报记录 + 通知状态为 `EXPIRED` → 显示"去申报"按钮（禁用态灰色），hover 提示"申报已截止"

#### 1.4.3 界面交互逻辑

**通知列表页**：
- 页面顶部展示状态 Tab：全部 / 进行中 / 已截止 / 未开始，默认激活"进行中"Tab。
- **Tab 切换为即时响应（按规范3.4.3第1条）**：点击 Tab 标签后立即筛选并刷新下方列表内容，无需额外点击「查询」按钮。切换过程中展示骨架屏加载效果，防止内容空白闪烁。当前激活标签以主色底色+白色文字标识选中态，非激活标签为浅灰底色。
- 通知卡片内容：项目名称（加粗）、申报截止时间（格式：`YYYY年MM月DD日 截止`）、状态标签（进行中-绿色、已截止-灰色、未开始-蓝色）。
- 列表分页，每页展示 10 条，底部分页控件。

**通知详情页**：
- 页面顶部展示面包屑：项目管理 > 项目申报通知 > 通知详情。
- 正文区域渲染富文本内容（HTML 内容安全渲染，防 XSS）。
- 页面底部固定展示操作区：根据按钮展示逻辑（见 1.4.1）渲染对应按钮。
- 点击"去申报"时，将当前通知ID（`notice_id`）作为参数传入申报填报页（功能二）。

**校验规则**：
- 进入申报通知列表页须为已登录状态，未登录跳转至登录页。
- 点击"去申报"时，前端再次校验通知状态是否为"进行中"（防止页面停留期间通知截止），若已截止则弹窗提示"申报已截止，无法发起申报"，不跳转。校验不通过时以全局弹窗形式提示（本功能无表单输入，无需字段级提示）。

## 功能二：项目建设申报信息填报

### 2.1 基本信息

- **功能名称**：项目建设申报信息填报
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 养殖场信息：复用现有养殖场基础信息表（如有）中的申请单位名称、场址等回显信息
  - 文件上传：复用现有文件上传接口
  - 关联功能一：申报通知查看，填报页通过 `notice_id` 关联具体通知
  - 政策资讯模块：申报须关联一条权限范围内的可申报政策（`knowledge_policy`），通过 `policy_id` 外键关联；政策可见范围过滤逻辑见 `doc_prd/WEB/企业端/政策信息查看/WEB企业端-政策资讯.prd.md` §3.4.1
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 企业管理员 | `ent_admin` | 在申报受理期内填写并提交项目建设申报表 | 填写申报基本信息、通过添加方式填写申请建设内容明细、上传资质文件，提交后等待审核 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。本功能仅面向企业管理员（`ent_admin`），企业填报员（`ent_reporter`）无项目申报权限。

### 2.2 目标与范围

**目标**：
1. 提供与《蓬溪县XXX项目建设申请表》格式对应的线上填报表单，字段完整覆盖纸质表内容。
2. "申请建设内容"通过动态添加行的方式填报，支持按子项目分类选择建设内容，数量不限。
3. 金额（万元）字段由系统根据"数量 × 单价（元）÷ 10000"自动计算并回显，不可手动编辑。
4. 支持上传6类资质文件附件（营业执照、土地备案表、环评备案表/环评批复、动物防疫条件许可证、征信记录、承诺书）。
5. 支持"暂存草稿"功能，用户可分多次填写，提交前数据不丢失。
6. 提交后申报状态变为"待公示"，进入审核流程（第三步：乡镇畜牧兽医站现场核实）。

**非目标（Non-Goals）**：
- ❌ 不支持批量导入申报数据。
- ❌ 不自动从外部系统同步养殖场资质信息（需用户手动上传附件）。
- ❌ 已提交后不允许编辑（仅可在"被退回"状态下修改后重新提交）。

### 2.3 现状与复用

**现状简述**：
- 现有 WEB 端无项目申报填报功能，需新增页面与前端路由。
- 养殖场基础信息（申请单位名称、场址）若在现有系统中有养殖场信息表，可通过登录上下文直接回显，否则允许手动填写。
- 文件上传使用现有系统的文件上传接口。

**复用检查结论**：

**1. 接口复用检查（对照 `doc_spec/现有业务说明.spec.md`）**

| 检查项 | 现有资源 | 复用结论 | 说明 |
|--------|---------|---------|------|
| 用户认证（登录） | POST `/login` | ✅ 直接复用 | 见现有业务说明.spec.md §二 认证与通用 |
| 获取用户信息 | GET `/getInfo` | ✅ 直接复用 | 见现有业务说明.spec.md §二 认证与通用，用于回显申请单位名称 |
| 获取路由菜单 | GET `/getRouters` | ✅ 直接复用 | 见现有业务说明.spec.md §二 认证与通用 |

#### 2.4.1 功能流程逻辑

**申请建设内容交互逻辑**：

1. 点击"+ 添加建设内容"按钮，在明细区域新增一行。
2. 每行包含以下字段（顺序固定）：
   - 第1列：子项目（下拉选择，选项固定为6个：`圈舍建设`、`自动化饲喂系统建设`、`智能化管理系统建设`、`防疫系统建设`、`粪污处理系统建设`、`智能化环控系统建设`）
   - 第2列：建设内容（下拉选择，选项随子项目联动，不同子项目的选项见下方映射表）
   - 第3列：单位（根据子项目+建设内容自动填入，只读不可编辑）
   - 第4列：数量（数字输入，最小值 0.01，最大值 999999.99，保留2位小数）
   - 第5列：单价（元）（数字输入，最小值 0.01，最大值 99999999.99，保留2位小数）
   - 第6列：金额（万元）（系统自动计算，只读，保留4位小数，计算公式：数量 × 单价 ÷ 10000）
   - 第7列：型号（文本输入，最大长度 200 字符，选填）
   - 第8列：备注（文本输入，最大长度 500 字符，选填）
   - 第9列：操作（删除按钮，点击删除当前行；行数≥2时，每行显示删除按钮；行数=1时，删除按钮不可点击并提示"至少保留一条建设内容"）
3. 子项目与建设内容及单位的映射关系（固定，不可增删改）：
   - `圈舍建设`：新建（单位：㎡）、改建（单位：㎡）、扩建（单位：㎡）
   - `自动化饲喂系统建设`：料塔（单位：个）、料线（单位：米）、料塔称重器（单位：套）、自动饮水器（单位：套）
   - `智能化管理系统建设`：视频监控系统（单位：套）
   - `防疫系统建设`：兽医室（单位：㎡）、消毒室（单位：㎡）、防疫围挡（单位：㎡）
   - `粪污处理系统建设`：自动刮粪机（单位：组）、干湿分离机（单位：组）、漏缝板（单位：张）、沼液暂存池（单位：m³）、沼气池（单位：m³）、沼液输送管网（单位：米）、粪污运输车（单位：辆）
   - `智能化环控系统建设`：风机（单位：个）、水帘（单位：㎡）、地暖（单位：㎡）、环境控制器（单位：套）
4. 子项目选择后，建设内容下拉联动刷新为对应子项目的选项；建设内容选择后，单位自动填入只读展示。
5. 当子项目切换时，若已选择建设内容，建设内容重置为空，单位重置为空，要求重新选择。
6. 合计投资金额展示在所有明细行下方，为所有行金额（万元）之和，实时动态更新（只读）。

**申报状态流转**（审批链路参照 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.4 典型审批链路：企业管理员 → 乡镇畜牧兽医站 → 乡镇政府业务人员 → 县级业务人员）：

- `DRAFT`（草稿）：暂存后的状态，可继续编辑、修改、提交
- `PENDING_PUBLICITY`（待公示）：企业管理员（`ent_admin`）提交后，等待乡镇畜牧兽医站（`town_vet_station`）发起公示
- `IN_PUBLICITY`（公示中）：乡镇畜牧兽医站（`town_vet_station`）已发起公示，公示期内
- `PENDING_STATION_REVIEW`（待站审核）：公示期满，等待乡镇畜牧兽医站（`town_vet_station`）上传公示照片并进行审核
- `STATION_APPROVED`（站审核通过）：乡镇畜牧兽医站（`town_vet_station`）审核通过，等待乡镇政府审核
- `STATION_REJECTED`（站审核不通过）：乡镇畜牧兽医站（`town_vet_station`）审核不通过，已通知企业
- `PENDING_TOWN_REVIEW`（待镇审核）：乡镇畜牧兽医站通过后，等待乡镇政府业务人员（`town_gov_staff`）审核
- `TOWN_APPROVED`（镇审核通过）：乡镇政府业务人员（`town_gov_staff`）审核通过，等待县农业农村局审核
- `TOWN_REJECTED`（镇审核不通过）：乡镇政府业务人员（`town_gov_staff`）审核不通过，已通知企业
- `PENDING_COUNTY_REVIEW`（待县审核）：乡镇政府通过后，等待县级业务人员（`county_staff`）审核
- `COUNTY_APPROVED`（县审核通过）：县级业务人员（`county_staff`）审核通过，申报成功，企业可开始填报实施信息
- `COUNTY_REJECTED`（县审核不通过）：县级业务人员（`county_staff`）审核不通过，已通知企业
- `ACCEPTED`（验收通过）：项目已通过竣工验收，不可再编辑实施信息
- `WITHDRAWN`（已撤回）：企业管理员（`ent_admin`）主动撤回草稿状态的申报

**被退回后重新提交规则**：
- 仅 `STATION_REJECTED`、`TOWN_REJECTED`、`COUNTY_REJECTED` 状态下，系统允许企业端用户进入编辑页面修改内容。
- 修改并重新提交后，状态重置为 `PENDING_PUBLICITY`，重新进入审核流程。

## 功能三：申报进度跟踪与结果查看

### 3.1 基本信息

- **功能名称**：申报进度跟踪与结果查看
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 站内消息：与站内消息通知模块关联（审核不通过时推送消息）
  - 功能二：申报信息填报（草稿继续填写、退回后修改入口）
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 企业管理员 | `ent_admin` | 提交申报后跟踪审核进度 | 查看申报当前状态、历史流程节点进度、审核意见，被退回时及时知晓并修改重提 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。本功能仅面向企业管理员（`ent_admin`），企业填报员（`ent_reporter`）无项目申报跟踪权限。

### 3.2 目标与范围

**目标**：
1. 提供当前用户所有申报记录的列表视图（含各状态的申报）。
2. 提供单条申报的详情页，展示完整流程进度（五个节点状态及时间）、已填报内容摘要、资质附件列表。
3. 审核不通过时，在申报详情页明确展示退回原因，并提供"修改并重新提交"入口。
4. 草稿状态的申报提供"继续填写"入口和"撤回（删除草稿）"入口。
5. 县农业农村局审核通过后，提供PDF申请表下载入口（由乡镇畜牧兽医站生成，企业端可下载）。

**非目标（Non-Goals）**：
- ❌ 不支持企业端对已提交（非草稿、非退回）申报进行编辑。
- ❌ 不提供申报数据统计分析功能。

```

        ↓

        ↓

        ↓
```

#### 3.4.1 功能流程逻辑

**流程进度轴节点定义**（对应5步审核流程）：

| 步骤序号 | 节点名称 | 对应状态区间 | 展示逻辑 |
|---------|---------|------------|---------|
| 步骤1 | 填报提交 | 任意非DRAFT状态均为已完成 | 完成态（绿色勾） |
| 步骤2 | 乡镇畜牧兽医站审核 | `PENDING_PUBLICITY`、`IN_PUBLICITY`、`PENDING_STATION_REVIEW` 为进行中；`STATION_APPROVED` 为已完成；`STATION_REJECTED` 为退回（红色叉） | — |
| 步骤3 | 乡镇政府审核 | `PENDING_TOWN_REVIEW` 为进行中；`TOWN_APPROVED` 为已完成；`TOWN_REJECTED` 为退回（红色叉）；`STATION_APPROVED` 之前为未开始（灰色） | — |
| 步骤4 | 县农业农村局审核 | `PENDING_COUNTY_REVIEW` 为进行中；`COUNTY_APPROVED` 为已完成；`COUNTY_REJECTED` 为退回（红色叉）；`TOWN_APPROVED` 之前为未开始（灰色） | — |
| 步骤5 | 审核完成 | `COUNTY_APPROVED` 或 `ACCEPTED` 时为已完成（绿色勾），其余为未开始（灰色） | — |

**步骤2详细子状态说明**（展示在步骤2节点展开区域）：
- `PENDING_PUBLICITY`：等待乡镇畜牧兽医站发起公示
- `IN_PUBLICITY`：公示中（展示公示截止日期倒计时）
- `PENDING_STATION_REVIEW`：公示已结束，等待审核

**状态分组（用于列表页Tab筛选）**：
- **草稿**：`DRAFT`
- **审核中**：`PENDING_PUBLICITY`、`IN_PUBLICITY`、`PENDING_STATION_REVIEW`、`STATION_APPROVED`、`PENDING_TOWN_REVIEW`、`TOWN_APPROVED`、`PENDING_COUNTY_REVIEW`
- **已通过**：`COUNTY_APPROVED`、`ACCEPTED`
- **已退回**：`STATION_REJECTED`、`TOWN_REJECTED`、`COUNTY_REJECTED`

**站内消息通知规则**：
- 触发时机：乡镇畜牧兽医站（`town_vet_station`）、乡镇政府业务人员（`town_gov_staff`）、县级业务人员（`county_staff`）任意一方审核不通过时，系统自动推送站内消息给申报用户（`ent_admin`）。
- 消息内容模板：「您的【{项目名称}】项目申报已被{审核机构名称}退回，退回原因：{退回意见}。请点击查看详情并修改重新提交。」
- 消息跳转：点击消息通知跳转至对应申报记录的详情页。

- **审核流程进度轴**：横向步骤条，5个节点，每个节点显示名称、状态图标（待处理灰圆圈、进行中蓝色、已通过绿色勾、已退回红色叉）、完成时间（已完成/已退回节点显示操作时间）；审核退回时，对应节点下方展示退回意见文字（红色字体）。
- **已填报内容折叠区**：默认折叠，点击展开查看完整填报内容（申报基本信息 + 建设内容明细表 + 资质附件列表）。
- **底部操作区**：根据状态展示对应按钮（见3.4功能列表中的操作按钮规则）：

**审核不通过消息推送**：
- 消息通知以系统消息形式出现在企业端消息中心（铃铛通知角标+1）。
- 消息列表中显示：消息类型图标（警告）、消息标题"项目申报审核退回通知"、消息摘要（退回机构+项目名称）、时间。
- 点击消息跳转至对应申报详情页。

**校验规则**：
- 点击"撤回"草稿时弹出确认弹窗："确认撤回该申报草稿吗？撤回后将无法恢复。"，确认后执行撤回，取消则关闭弹窗。
- 撤回成功后，该记录在列表中消失（或展示为已撤回灰态，不可再操作）。

## 功能四：项目实施信息填报

### 4.1 基本信息

- **功能名称**：项目实施信息填报
- **关联现有模块/功能**：
  - **项目建设申报信息填报（功能二）**：本功能依赖功能二的申报主记录表（`project_application`）和建设内容明细表（`project_application_item`），实施信息按建设内容明细逐项关联填报。入口为功能三申报详情页的"填报实施信息"按钮，携带 `application_id` 参数。
  - **申报进度跟踪与结果查看（功能三）**：本功能的入口在功能三的申报详情页，当状态为 `COUNTY_APPROVED`（县审核通过）时展示"填报实施信息"主按钮，`ACCEPTED`（验收通过）时展示"查看实施信息"只读按钮。
  - **通用上传接口**：照片和视频文件上传复用现有系统通用上传接口 `POST /common/upload`。
- **目标用户/场景**：企业管理员（`ent_admin`，角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1），在项目通过县级审核（`COUNTY_APPROVED`）后、验收通过（`ACCEPTED`）前，需要记录并上传项目实施过程中的前期、中期、后期的照片、视频和文字说明，且须与申报建设内容逐项对应，用于后续竣工验收评审。

### 4.2 目标与范围

- **目标**：
  - 为审核通过的项目提供实施过程记录能力，企业可按前期（开工准备）、中期（施工中）、后期（完工）三个阶段分别上传照片、视频、文字说明
  - 实施信息与申报建设内容明细表（`project_application_item`）逐项对应，确保每一项建设内容都有对应的实施过程记录
  - 支持分次填报、多次保存，不要求一次性全部完成
  - 为管理端竣工验收评审提供完整的实施过程资料依据
- **非目标（Non-Goals）**：
  - 本功能不涉及验收审核流程本身（验收审核由管理端 PRD 定义）
  - 不支持除照片/视频/文字外的其他文件格式（如 PDF、CAD 图纸等）
  - 不涉及实施进度的百分比计算或甘特图展示
  - 不支持多人协同编辑同一条实施记录

### 4.3 现状与复用

- **现状简述**：当前系统在项目县级审核通过后无后续实施过程记录功能，企业无法在线上传实施过程资料。本功能为全新功能，需新建数据表和接口。

### 4.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 实施信息填报主页 | P0 | 展示申报项目基本信息摘要 + 建设内容明细列表，每项建设内容显示三个阶段的填报状态 |
| 按阶段填报实施信息 | P0 | 对每项建设内容，分别填报前期、中期、后期三个阶段的照片、视频和文字说明 |
| 上传照片 | P0 | 支持 JPG/PNG/GIF/WebP 格式，单张最大 10MB，每个阶段最多上传 9 张照片 |
| 上传视频 | P1 | 支持 MP4/MOV/AVI 格式，单个最大 200MB，每个阶段最多上传 3 个视频 |
| 文字说明 | P0 | 每个阶段可填写文字说明，最大 1000 字符 |
| 保存实施记录 | P0 | 每个阶段独立保存，保存后可继续修改（验收通过前） |
| 实施进度总览 | P1 | 按建设内容明细展示每项的前/中/后期填报完成状态（已填/未填），一目了然 |
| 只读模式查看 | P0 | 验收通过（`ACCEPTED`）后，所有实施信息以只读模式展示，不可编辑 |

**关键流程**：

```
从功能三申报详情页点击"填报实施信息"按钮
        ↓

        ↓
校验申报状态：

  - ACCEPTED → 进入只读模式
  - COUNTY_APPROVED → 进入可编辑模式
        ↓
页面顶部展示项目基本信息摘要（申请单位、关联政策、场址等，只读）
        ↓
下方展示建设内容明细列表（来自 project_application_item）
每项建设内容显示为一个折叠卡片：
  - 标题：子项目 + 建设内容 + 数量 + 单位
  - 右侧标签：前期（已填/未填）、中期（已填/未填）、后期（已填/未填）
        ↓
点击某项建设内容卡片 → 展开该项的阶段填报区域
        ↓
展示三个 Tab：前期 / 中期 / 后期
        ↓
每个 Tab 内：
  - 照片上传区（网格展示，已上传的缩略图 + "+"上传按钮）
  - 视频上传区（列表展示，已上传的视频封面 + "+"上传按钮）
  - 文字说明（多行文本输入框）
  - 保存按钮（仅 COUNTY_APPROVED 状态可见）
        ↓
点击"保存" → 校验必填项 → 保存当前阶段实施记录
        ↓
保存成功 → 该阶段状态更新为"已填"，Toast 提示"保存成功"
```

#### 4.4.1 功能流程逻辑

**实施阶段定义**：

| 阶段编码 | 阶段名称 | 含义说明 |
|---------|---------|---------|
| `EARLY` | 前期 | 项目开工准备阶段，包括场地平整、材料准备、基础施工等 |
| `MIDDLE` | 中期 | 项目施工建设过程中，包括主体施工、设备安装、调试等 |
| `LATER` | 后期 | 项目竣工完成阶段，包括完工实景、设备运行、投入使用等 |

**实施信息与建设内容的对应关系**：

- 每条建设内容明细（`project_application_item`）对应三条实施记录（前期/中期/后期），即 `project_implementation_record` 按 `(item_id, stage)` 联合确定唯一记录
- 实施记录采用"按需创建"策略：用户首次点击某阶段Tab并保存时才创建对应记录，未操作的阶段不创建空记录
- 每条实施记录下可挂载多个媒体文件（照片/视频），存储在 `project_implementation_media` 表中

**保存逻辑**：

- 每个阶段独立保存，保存操作仅影响当前阶段的当前建设内容项
- 保存时校验规则：照片、视频、文字说明三项中至少填写一项，不允许保存完全空白的记录
- 已保存的记录可反复修改，修改后点击保存覆盖更新
- 项目状态变为 `ACCEPTED`（验收通过）后，所有实施记录锁定为只读，保存按钮隐藏

**媒体文件上传规则**：

| 类型 | 允许格式 | 单文件大小上限 | 数量上限（每阶段每项） | 上传方式 |
|------|---------|-------------|-----------------|---------|
| 照片 | JPG、PNG、GIF、WebP | 10MB | 9 张 | 复用 `POST /common/upload`，上传后返回文件路径 |
| 视频 | MP4、MOV、AVI | 200MB | 3 个 | 复用 `POST /common/upload`，上传后返回文件路径 |

- 上传文件格式不符时，前端拦截并提示「仅支持 JPG/PNG/GIF/WebP 格式的图片」或「仅支持 MP4/MOV/AVI 格式的视频」
- 上传文件超出大小限制时，前端拦截并提示「图片大小不能超过 10MB」或「视频大小不能超过 200MB」
- 达到数量上限后，"+"上传按钮置灰并提示「该阶段最多上传 {N} 张照片」或「该阶段最多上传 {N} 个视频」
- 已上传的照片支持点击预览大图（Lightbox 模式），支持左右切换浏览
- 已上传的视频支持点击在线播放（浏览器内置播放器）
- 已上传的文件支持单个删除，删除前弹出确认弹窗：「确认删除该{照片/视频}吗？删除后不可恢复。」

#### 4.4.3 界面交互逻辑

**页面布局**：

1. **面包屑导航**：项目管理 > 我的申报 > 申报详情 > 实施信息填报
2. **项目信息摘要区**（只读，不可编辑）：
   - 展示字段：申请单位名称、关联政策名称、场址（镇/村/社）、建设性质、建设期限、设计存栏/出栏规模
   - 布局：两列栅格布局，字段标签灰色、字段值黑色加粗
   - 右上角展示项目状态标签（`COUNTY_APPROVED` 显示蓝色"审核通过"标签，`ACCEPTED` 显示绿色"验收通过"标签）
3. **实施进度总览区**：
   - 位于项目信息摘要区下方
   - 以进度统计行展示：「实施填报进度：已填 X 项 / 共 Y 项（Z%）」，其中 Y = 建设内容明细总数 × 3（每项3个阶段），X = 已创建的实施记录数
   - `ACCEPTED` 状态时额外展示绿色标记：「该项目已验收通过，实施信息为只读状态」
4. **建设内容明细列表区**：
   - 每条建设内容渲染为一个可折叠的卡片
   - 卡片标题行：`[子项目名称] - [建设内容] [数量][单位]`，例如「圈舍建设 - 新建 500㎡」
   - 卡片标题行右侧展示三个状态标签：
     - 「前期」标签：已填为绿色实心标签，未填为灰色空心标签
     - 「中期」标签：已填为蓝色实心标签，未填为灰色空心标签
     - 「后期」标签：已填为橙色实心标签，未填为灰色空心标签
   - 默认全部折叠，点击卡片标题行可展开/收起
5. **卡片展开后的阶段填报区域**：
   - 展开后内部以三个 Tab 切换：`前期` / `中期` / `后期`，默认激活第一个未填的阶段Tab（若全部已填，则默认激活"前期"）
   - 每个 Tab 内容区布局：
     - **照片区**：标题"项目照片"，九宫格网格布局；已上传照片展示缩略图（固定 120×120px），悬停显示删除按钮（右上角红色圆形×）；最后一个位置为"+"上传按钮（虚线边框），达到上限时隐藏；下方小字提示「支持 JPG/PNG/GIF/WebP，单张不超过 10MB，最多 9 张」
     - **视频区**：标题"项目视频"，列表布局；已上传视频展示封面帧缩略图 + 视频时长 + 文件名 + 删除按钮；最后一行为"+ 上传视频"按钮，达到上限时隐藏；下方小字提示「支持 MP4/MOV/AVI，单个不超过 200MB，最多 3 个」
     - **文字说明区**：标题"文字说明"，多行文本输入框（`textarea`），最大 1000 字符，下方展示当前字数/最大字数
     - **操作按钮区**：仅 `COUNTY_APPROVED` 状态展示「保存」按钮（蓝色主按钮）；`ACCEPTED` 状态不展示保存按钮，照片/视频区的上传按钮和删除按钮均隐藏，文字说明设为 `readonly`

### 4.5 非功能需求

- **性能/数据量**：实施信息总览页加载（含所有建设内容的阶段状态）须在 2s 内完成；单个阶段的照片/视频加载（含缩略图）须在 3s 内完成。
- **文件存储**：照片和视频文件存储路径使用系统通用上传目录结构（`/profile/upload/yyyy/MM/dd/`），不单独规划存储目录。
- **安全与权限**：仅企业管理员（`ent_admin`）可操作，实施记录严格按 `reporter_user_id` + `application_id` 做数据隔离，只能填报自己申报的项目的实施信息，越权访问返回 403。角色定义引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1。数据权限按 `data_scope = '4'`（本部门及以下）控制，见全局权限文档 §2.1。
- **并发控制**：同一条实施记录不支持多人同时编辑（同一企业当前仅 `ent_admin` 角色有权操作，无并发场景）。保存接口使用乐观锁（`update_time` 字段比对），若检测到并发修改返回提示「该记录已被修改，请刷新后重试」。

### 4.6 验收标准

- [ ] 县审核通过（`COUNTY_APPROVED`）状态的项目，在申报详情页（功能三）展示"填报实施信息"蓝色主按钮，点击跳转至实施信息填报页面。
- [ ] 验收通过（`ACCEPTED`）状态的项目，在申报详情页（功能三）展示"查看实施信息"白色描边按钮，点击跳转至实施信息只读页面。
- [ ] 非 `COUNTY_APPROVED` / `ACCEPTED` 状态的项目无法进入实施信息页面，接口返回错误提示。
- [ ] 实施信息填报页面正确展示项目基本信息摘要（申请单位、关联政策、场址等），均为只读。
- [ ] 建设内容明细列表正确加载，与申报时提交的 `project_application_item` 数据一致，每项显示子项目名称、建设内容、数量、单位。
- [ ] 每项建设内容的三个阶段（前期/中期/后期）标签正确显示已填/未填状态。
- [ ] 点击建设内容卡片可展开阶段填报区域，Tab 切换即时响应。
- [ ] 照片上传功能正常：支持 JPG/PNG/GIF/WebP 格式，不超过 10MB，最多 9 张；格式不符或超大时前端拦截提示。
- [ ] 视频上传功能正常：支持 MP4/MOV/AVI 格式，不超过 200MB，最多 3 个；格式不符或超大时前端拦截提示。
- [ ] 达到上传数量上限后，上传按钮正确置灰并提示。
- [ ] 照片支持点击预览大图（Lightbox），支持左右切换。
- [ ] 视频支持点击在线播放。
- [ ] 照片/视频支持单个删除，删除前弹出确认弹窗。
- [ ] 文字说明输入正常，最大 1000 字符，实时显示字数统计。
- [ ] 保存校验：三项（照片/视频/文字说明）至少填写一项，否则提示错误。
- [ ] 保存成功后，Toast 提示"保存成功"，阶段状态标签立即更新为"已填"。
- [ ] 已保存的记录可再次进入修改，修改后保存覆盖更新。
- [ ] 实施进度统计正确：「已填 X 项 / 共 Y 项（Z%）」数值准确。
- [ ] 验收通过（`ACCEPTED`）后，所有实施信息为只读模式：保存按钮隐藏、上传/删除按钮隐藏、文字说明 readonly。
- [ ] 见可交互 HTML 原型。

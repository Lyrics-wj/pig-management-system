# 功能一：培训活动管理

## 3.1 基本信息

- **功能名称**：培训活动管理

## 3.2 目标与范围

**目标**：
1. 为监管端提供培训活动的全生命周期管理（新增、编辑、发布、下架、删除）。
2. 支持活动列表分页查询，按类型、状态、名称搜索筛选。
3. 活动状态根据时间自动流转：报名中→进行中→已结束。
4. 有报名记录的活动不可删除，保证数据完整性。

**非目标（Non-Goals）**：
- 不提供培训活动的前台浏览与报名功能（由网站端承担）。
- 不实现培训签到、现场管理功能。
- 不实现培训效果评估、满意度调查功能。

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 活动列表 | P0 | 分页展示所有培训活动，支持按类型、状态、名称搜索筛选 |
| 新增活动 | P0 | 填写活动信息（名称、简介、封面图、类型、方式、讲师、地点、时间、名额、附件） |
| 编辑活动 | P0 | 修改活动信息；已发布活动编辑时需谨慎提示 |
| 活动发布/下架 | P0 | 草稿→已发布、已发布→已下架 |
| 删除活动 | P1 | 逻辑删除；有报名记录的活动不可删除 |
| 活动状态自动流转 | P0 | 根据时间自动从「报名中」变为「进行中」，从「进行中」变为「已结束」 |

**关键流程**：

```
新增活动流程：
点击「新增」→ 进入新增表单页 → 填写活动信息（名称、简介、封面、类型、方式、讲师、地点、开始/结束/报名截止时间、名额、附件）
  → 前端校验（必填、时间逻辑、格式）→ 提交
  → 保存成功 → 跳转列表或提示「保存成功」

发布/下架流程：
列表操作列「发布」（草稿/已下架）→ 二次确认「确认发布该活动？」→ publish_status=1，publish_time=当前时间
列表操作列「下架」（已发布）→ 二次确认「确认下架？下架后网站端将不可见」→ publish_status=2

删除流程：
列表操作列「删除」→ 后端校验是否存在报名记录
  ├── 无报名记录 → 二次确认「确认删除该活动？删除后不可恢复」→ 逻辑删除（del_flag=2）
  └── 有报名记录 → 返回「该活动已有报名记录，不可删除」
```

**交互与界面要点**：
- 列表页：顶部筛选区 + 操作按钮行 + 数据表格 + 分页控件
- 新增/编辑页：独立表单页（非弹窗），富文本编辑需较大空间
- 已发布活动点击「编辑」时弹出提示「该活动已发布，修改后将即时对用户生效，是否继续？」

### 3.4.1 功能流程逻辑

**活动状态自动流转规则**：
- `training_status` 字段由定时任务或接口查询时动态计算，不依赖人工操作
- 计算规则：
  - 当前时间 < `start_time`：`training_status=0`（报名中）
  - `start_time` ≤ 当前时间 < `end_time`：`training_status=1`（进行中）
  - 当前时间 ≥ `end_time`：`training_status=2`（已结束）
- 建议：定时任务每5分钟执行一次，批量更新 `kc_training` 表中 `training_status` 字段；或列表/详情接口返回时动态计算 `training_status` 展示值（数据库可保留上次计算值用于筛选，查询时以动态计算为准）

**发布状态流转规则**：
- `草稿（0）` → 发布操作 → `已发布（1）`：`publish_time` 自动填充
- `已发布（1）` → 下架操作 → `已下架（2）`
- `已下架（2）` → 发布操作 → `已发布（1）`
- 删除仅允许 `草稿（0）` 和 `已下架（2）` 状态，且无报名记录

**删除校验规则**：
- 删除前查询 `kc_training_enrollment` 表，`training_id` 关联且 `del_flag=0` 的记录数
- 若记录数 > 0，拒绝删除，返回「该活动已有报名记录，不可删除」

**current_enrollment 计算规则**：
- `current_enrollment` = `kc_training_enrollment` 表中该活动 `approval_status=1`（已通过）且 `del_flag=0` 的记录数
- 后台列表/详情展示时实时统计或定时更新

# 功能二：培训报名审批

## 3.1 基本信息

- **功能名称**：培训报名审批
- **关联现有模块/功能**：
  - 培训活动管理（本 PRD 功能一）：报名记录关联 `kc_training` 活动
  - 用户认证：依赖现有 JWT Token 认证
  - 生猪知识讲堂网站：用户通过网站端提交报名，本功能负责审批
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_prd/WEB/生猪知识讲堂/网站/WEB-生猪知识讲堂网站.prd.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（引用自全局权限体系 §1.1） | 使用场景 | 主要需求 |
|---------|--------------------------------------|---------|---------|
| 县级管理员 | county_admin | 审批培训报名申请 | 查看报名列表、逐条或批量审批、导出报名名单 |
| 县级业务人员 | county_staff | 日常审批报名 | 查看报名列表、逐条或批量审批、导出报名名单 |

---

## 3.2 目标与范围

**目标**：
1. 为监管端提供某活动报名记录的分页列表，支持按审批状态筛选。
2. 支持逐条审批（通过/拒绝）和批量审批，填写审批意见。
3. 支持将某活动已通过的报名记录导出为 Excel 文件。

**非目标（Non-Goals）**：
- 不提供用户端报名提交功能（由网站端承担）。
- 不实现报名后的签到、现场管理功能。
- 不支持审批流程多级审批（仅单级通过/拒绝）。

**现状简述**：
- 培训报名表 `kc_training_enrollment` 由网站端 PRD 定义，后台管理复用。
- 现有系统无报名审批接口，需全部新增。

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 报名列表 | P0 | 分页展示某活动的报名记录，支持按审批状态筛选 |
| 报名审批 | P0 | 逐条审批或批量审批（通过/拒绝），填写审批意见 |
| 导出报名名单 | P1 | 将某活动已通过的报名记录导出为 Excel |

**关键流程**：

```
报名审批流程：
进入培训活动管理 → 点击某活动「报名管理」或从菜单进入「培训报名审批」→ 选择活动
  → 展示该活动报名列表
  → 逐条审批：点击「通过」/「拒绝」→ 弹出审批意见输入框（选填）→ 确认
    → approval_status 更新为 1/2，approval_remark、approval_by、approval_time 填充
  → 批量审批：勾选多条 → 点击「批量通过」/「批量拒绝」→ 弹出审批意见输入框（选填）→ 确认
    → 批量更新

导出流程：
报名列表页 → 点击「导出报名名单」→ 仅导出当前活动下 approval_status=1 的记录
  → 返回 Excel 文件流，文件名格式「{活动名称}_报名名单_YYYYMMDD_HHmmss.xlsx」
```

**交互与界面要点**：
- 报名列表需先选择活动（下拉或从活动列表跳转带入 training_id）
- 审批意见输入框为选填，拒绝时建议填写
- 导出仅包含已通过记录

### 3.4.1 功能流程逻辑

**审批状态流转规则**：
- `待审批（0）` → 通过操作 → `已通过（1）`：`approval_by`、`approval_time`、`approval_remark` 填充；`kc_training.current_enrollment` 需同步 +1
- `待审批（0）` → 拒绝操作 → `已拒绝（2）`：`approval_by`、`approval_time`、`approval_remark` 填充
- 已通过、已拒绝的记录可再次操作修改（如误操作可改为拒绝或通过），修改通过为拒绝时 `current_enrollment` -1，修改拒绝为通过时 `current_enrollment` +1

**批量审批规则**：
- 仅可选择 `approval_status=0`（待审批）的记录进行批量操作
- 已通过、已拒绝的记录不参与批量操作（或批量时自动过滤）

**导出字段**：
- 报名人姓名、联系电话、所属单位、报名备注、审批状态、审批意见、报名时间

| 字段名（中文） | 字段名（英文） | 类型 | 长度 | 必填 | 默认值 | 取值范围/枚举值 | 说明 |
|--------------|--------------|------|------|------|--------|----------------|------|
| 报名ID | enrollment_id | bigint | 20 | 是 | 自增 | - | 主键，只读 |
| 活动ID | training_id | bigint | 20 | 是 | - | 关联 kc_training.training_id | - |
| 用户ID | user_id | bigint | 20 | 是 | - | - | 只读 |
| 用户来源 | user_source | varchar | 20 | 是 | - | `platform`、`kc_portal` | 仅2种，只读 |
| 报名人姓名 | enrollee_name | varchar | 50 | 是 | - | 最大长度50个字符 | 只读 |

### 3.4.3 界面交互逻辑

**报名列表页布局**：
- 顶部：活动选择下拉（必选，数据来源 `kc_training` 表 publish_status=1 或全部），选择后加载该活动报名列表
- 筛选区：审批状态下拉（全部 / 待审批 / 已通过 / 已拒绝）
- 操作按钮行：「批量通过」「批量拒绝」（勾选待审批记录后可点击）「导出报名名单」
- 数据表格列：勾选框、报名人姓名、联系电话、所属单位、报名备注、审批状态、审批意见、报名时间、操作列
- 操作列：「通过」（待审批时显示）「拒绝」（待审批时显示）
- 分页控件：每页10/20/50条，默认20条

**审批弹窗**：
- 单条审批：点击「通过」/「拒绝」→ 弹出弹窗，标题「审批 - 通过」或「审批 - 拒绝」
- 弹窗内容：审批意见输入框（多行，选填，最大200字符）
- 底部：「确认」按钮 + 「取消」按钮
- 批量审批：勾选多条后点击「批量通过」/「批量拒绝」→ 弹出相同弹窗，确认后批量更新

**前端校验规则（强制）**：
- 审批意见：选填，若填写则最大200字符
- 导出前需已选择活动

**自动回显字段（只读）**：
- 报名ID、活动ID、用户ID、用户来源、报名人姓名、联系电话、所属单位、报名备注、创建时间（用户填写，后台只读）
- 审批人、审批时间（系统自动填充）

### 3.4.4 接口路径定义（强制）

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 报名记录分页列表 | GET | `/kc-admin/training/enrollment/list` | pageNum、pageSize、trainingId（必填）、approvalStatus（0/1/2，可为空） | 分页列表（enrollment_id、training_id、enrollee_name、enrollee_phone、enrollee_org、enrollee_remark、approval_status、approval_remark、approval_by、approval_time、create_time）+ 总数 | 🆕 新增 |
| 审批通过 | PUT | `/kc-admin/training/enrollment/approve` | enrollmentId（单条）或 enrollmentIds（批量，逗号分隔）、approvalStatus（1 通过）、approvalRemark（选填） | 操作结果 + 影响行数 | 🆕 新增；通过时 current_enrollment +1 |
| 审批拒绝 | PUT | `/kc-admin/training/enrollment/reject` | enrollmentId（单条）或 enrollmentIds（批量）、approvalStatus（2 拒绝）、approvalRemark（选填） | 操作结果 + 影响行数 | 🆕 新增 |
| 导出报名名单 | POST | `/kc-admin/training/enrollment/export` | trainingId（必填） | Excel 文件流 | 🆕 新增；仅导出 approval_status=1 |
| 活动下拉选项 | GET | `/kc-admin/training/options` | 无 | 活动列表（training_id、training_name）用于报名列表页活动选择 | 🆕 新增；可选返回全部或仅已发布 |

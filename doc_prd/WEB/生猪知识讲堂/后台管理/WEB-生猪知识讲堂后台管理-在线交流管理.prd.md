## 3.2 目标与范围

**目标**：
1. 为监管端人员提供论坛板块的增删改查管理能力。
2. 支持新增板块，配置板块名称、描述、图标、排序序号。

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 板块列表 | P0 | 展示所有论坛板块，支持分页 |
| 新增板块 | P0 | 输入板块名称、描述、图标、排序序号 |
| 编辑板块 | P0 | 修改板块信息 |
| 删除板块 | P0 | 有帖子的板块不可删除 |
| 板块状态切换 | P0 | 启用/停用 |

**关键流程**：

```
板块列表流程：
进入论坛板块管理页 → 加载板块列表（按 sort_order 升序）
  → 展示板块表格 → 可执行：新增、编辑、删除、启用/停用

新增板块流程：
点击「新增板块」→ 弹出表单 → 填写板块名称（必填）、板块描述（选填）、板块图标（选填）、排序序号（必填，默认0）
  → 前端校验 → 提交 → 后端写入 kc_forum_board → 提示「新增成功」→ 列表刷新

编辑板块流程：
列表页点击「编辑」→ 弹出表单（回显已有数据）→ 修改字段 → 前端校验 → 提交
  → 后端更新 kc_forum_board → 提示「修改成功」→ 列表刷新

删除板块流程：
列表页点击「删除」→ 后端检查该板块下帖子数量（kc_forum_post 中 board_id 关联且 del_flag=0 的条数）
  ├── 帖子数 > 0 → 返回「该板块下有帖子，不可删除」
  └── 帖子数 = 0 → 二次确认 → 逻辑删除（del_flag=2）→ 提示「删除成功」

状态切换流程：
列表页点击「启用」或「停用」→ 二次确认 → 提交
  → 更新 kc_forum_board.status（0 正常、1 停用）→ 提示成功 → 列表刷新
```

**交互与界面要点**：
- 列表页表格列：板块ID、板块名称、板块描述、板块图标（缩略图）、排序序号、帖子数量、状态、操作（编辑、删除、启用/停用）
- 新增/编辑表单：板块名称、板块描述、板块图标（图片上传）、排序序号
- 删除、状态切换需二次确认

### 3.4.1 功能流程逻辑

**删除校验规则**：
- 删除前查询 `kc_forum_post` 表，条件：`board_id = 当前板块ID` 且 `del_flag = '0'`
- 若存在至少 1 条记录，则不允许删除，返回「该板块下有帖子，不可删除」
- 若不存在记录，允许逻辑删除（`del_flag='2'`）

**状态切换逻辑**：
- 当前 `status='0'`（正常）时，按钮展示「停用」，点击后 `status` 置为 `1`
- 当前 `status='1'`（停用）时，按钮展示「启用」，点击后 `status` 置为 `0`
- 停用后网站端该板块不展示，用户无法在该板块发帖

**排序规则**：
- 列表按 `sort_order` 升序排列，`sort_order` 相同时按 `create_time` 升序

### 3.4.2 数据模型与字段定义

**论坛板块表（kc_forum_board）**（✅ 复用网站端 PRD 已定义的表，见 `WEB-生猪知识讲堂网站.prd.md` §3.4.2）：

| 字段名（中文） | 字段名（英文） | 类型 | 长度 | 必填 | 默认值 | 取值范围/枚举值 | 说明 |
|--------------|--------------|------|------|------|--------|----------------|------|
| 板块ID | board_id | bigint | 20 | 是 | 自增 | - | 主键 |
| 板块名称 | board_name | varchar | 50 | 是 | - | 最大长度50个字符 | - |
| 板块描述 | board_desc | varchar | 200 | 否 | - | 最大长度200个字符 | - |
| 板块图标 | board_icon | varchar | 200 | 否 | - | 图片URL | - |
| 排序序号 | sort_order | int | 11 | 是 | `0` | 最小值0，最大值999 | 数值越小越靠前 |
| 帖子数量 | post_count | int | 11 | 是 | `0` | 最小值0 | 只读，自动统计 kc_forum_post 中 board_id 关联且 del_flag=0 的条数 |
| 状态 | status | char | 1 | 是 | `0` | `0` 正常、`1` 停用 | 仅2种，无其他 |
| 删除标志 | del_flag | char | 1 | 是 | `0` | `0` 存在、`2` 删除 | 仅2种 |
| 创建者 | create_by | varchar | 64 | 否 | - | - | 只读，系统自动填充当前登录用户 |
| 创建时间 | create_time | datetime | - | 是 | CURRENT_TIMESTAMP | - | 只读 |
| 更新者 | update_by | varchar | 64 | 否 | - | - | 只读 |
| 更新时间 | update_time | datetime | - | 是 | CURRENT_TIMESTAMP | - | 只读 |

**新增/编辑表单可编辑字段**：board_name、board_desc、board_icon、sort_order、status（仅状态切换时修改）

### 3.4.3 界面交互逻辑

**列表页布局**：
- 顶部「新增板块」按钮
- 表格列：板块ID、板块名称、板块描述、板块图标（80px×80px 缩略图）、排序序号、帖子数量、状态（正常/停用标签）、操作（编辑、删除、启用/停用）
- 操作列：编辑按钮、删除按钮、启用/停用按钮（根据当前状态展示其一）
- 删除、状态切换点击后弹出确认弹窗

**新增/编辑表单弹窗**：
- 板块名称：输入框，placeholder「请输入板块名称」，必填
- 板块描述：文本域，placeholder「请输入板块描述（选填）」，选填
- 板块图标：图片上传组件，选填，支持 jpg/jpeg/png，单张不超过 2MB
- 排序序号：数字输入框，placeholder「请输入排序序号，数值越小越靠前」，必填，默认值 0，范围 0~999
- 底部「确定」「取消」按钮

**前端校验规则（强制）**：

| 字段 | 必填 | 格式校验 | 提示文案 |
|-----|------|---------|---------|
| 板块名称 | 是 | 1~50个字符 | 「请输入板块名称」/「板块名称不能超过50个字符」 |
| 板块描述 | 否 | 最大200个字符 | 「板块描述不能超过200个字符」 |
| 排序序号 | 是 | 0~999 整数 | 「请输入排序序号」/「排序序号为0~999的整数」 |

- 字段失焦时即时校验
- 点击「确定」时整体校验
- 错误提示紧邻对应字段下方展示（红色文字）

**自动回显字段（只读）**：
- 板块ID、帖子数量、创建者、创建时间、更新者、更新时间（编辑时展示，不可编辑）

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 帖子列表 | P0 | 分页展示所有帖子，支持按板块、标题搜索 |
| 置顶/取消置顶 | P0 | 帖子置顶后网站端排在最前 |
| 加精/取消加精 | P0 | 加精帖子展示「精」标签 |
| 删除帖子 | P0 | 逻辑删除违规帖子 |
| 回复列表 | P0 | 查看帖子的回复列表 |
| 删除回复 | P0 | 删除违规回复 |

**关键流程**：

```
帖子列表流程：
进入论坛内容管理页 → 选择板块（下拉，可选全部）、输入标题关键词 → 点击「查询」
  → 后端分页查询 kc_forum_post（del_flag=0，status=1）→ 展示帖子列表
  → 可执行：查看详情、置顶/取消置顶、加精/取消加精、删除、查看回复

置顶/加精流程：
列表页点击「置顶」或「加精」→ 二次确认（若当前已置顶/已加精则展示「取消置顶」「取消加精」）
  → 提交 → 更新 kc_forum_post.is_top 或 is_featured（0/1 切换）→ 提示成功 → 列表刷新

删除帖子流程：
列表页点击「删除」→ 二次确认 → 提交
  → 后端将 kc_forum_post.status 置为 0（已删除），del_flag 置为 2 → 提示「删除成功」→ 列表刷新

回复管理流程：
列表页点击「查看回复」→ 跳转或弹窗展示该帖子的回复列表
  → 回复列表分页展示 → 可执行：删除某条回复
  → 点击「删除回复」→ 二次确认 → 将 kc_forum_reply.status 置为 0，del_flag 置为 2 → 提示成功
```

**交互与界面要点**：
- 帖子列表表格列：帖子ID、标题、所属板块、发帖人、发帖时间、查看数、回复数、置顶、加精、操作
- 筛选区域：板块下拉（全部+各板块）、标题关键词输入框、「查询」按钮
- 回复列表可嵌入帖子详情弹窗或独立页面

### 3.4.1 功能流程逻辑

**帖子删除规则**：
- 逻辑删除：`kc_forum_post.status` 置为 `0`（已删除），`del_flag` 置为 `2`
- 删除后网站端该帖子不再展示

**回复删除规则**：
- 逻辑删除：`kc_forum_reply.status` 置为 `0`（已删除），`del_flag` 置为 `2`
- 删除后需同步更新 `kc_forum_post.reply_count` 减 1

**置顶/加精按钮展示逻辑**：
- 当前 `is_top='0'` 时展示「置顶」，点击后 `is_top` 置为 `1`
- 当前 `is_top='1'` 时展示「取消置顶」，点击后 `is_top` 置为 `0`
- 当前 `is_featured='0'` 时展示「加精」，点击后 `is_featured` 置为 `1`

## 3.2 目标与范围

**目标**：
1. 为监管端人员提供问答问题的集中管理能力。
2. 支持分页查看所有问题，按分类、状态筛选。
3. 支持删除违规问题（逻辑删除）。
4. 支持后台人员（专家/教授）直接回答用户问题，回答自动标记为专家回答（is_expert=1）。
5. 支持查看问题下的回答列表，删除违规回答。

**非目标（Non-Goals）**：
- 不提供后台提问功能（提问由用户在网站端完成）。
- 不提供问题编辑功能。
- 不提供采纳/取消采纳回答功能（由提问者在网站端操作）。

## 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 问题列表 | P0 | 分页展示所有问题，支持按分类、状态筛选 |
| 删除问题 | P0 | 逻辑删除违规问题 |
| 回答问题 | P0 | 后台人员以专家身份回答，is_expert=1 |
| 回答列表 | P0 | 查看问题下的回答列表 |
| 删除回答 | P0 | 删除违规回答 |

**关键流程**：

```
问题列表流程：
进入问答管理页 → 选择分类（全部/养殖技术/疫病防治/饲料营养/市场价格/政策法规）、选择状态（全部/待回答/已回答/已采纳）
  → 点击「查询」或直接加载 → 后端分页查询 kc_qa_question（del_flag=0）→ 展示问题列表
  → 可执行：查看详情、删除、回答问题、查看回答

回答问题流程：
列表页或详情页点击「回答问题」→ 弹出回答表单 → 输入回答内容（必填）、上传图片（选填，最多5张）
  → 前端校验 → 提交
  → 后端写入 kc_qa_answer（user_id、user_source 为当前登录的监管端用户，is_expert=1）
  → 同步更新 kc_qa_question.answer_count +1、question_status 置为 1（已回答）
  → 提示「回答成功」→ 回答列表刷新

删除问题流程：
列表页点击「删除」→ 二次确认 → 提交
  → 将 kc_qa_question.del_flag 置为 2 → 提示「删除成功」→ 列表刷新

删除回答流程：
回答列表点击「删除」→ 二次确认 → 提交
  → 将 kc_qa_answer.del_flag 置为 2，status 若有则置为 0
  → 同步更新 kc_qa_question.answer_count -1
  → 若该问题无其他有效回答，question_status 置回 0（待回答）
  → 提示成功
```

**交互与界面要点**：
- 问题列表表格列：问题ID、标题、分类、状态、提问人、提问时间、查看数、回答数、操作
- 筛选区域：分类下拉、状态下拉、「查询」按钮
- 回答表单：富文本或文本域输入回答内容，图片上传（最多5张）

### 3.4.1 功能流程逻辑

**后台回答自动标记规则**：
- 监管端人员（county_admin、county_staff）回答问题时，`kc_qa_answer.is_expert` 自动置为 `1`（专家回答）

- 删除回答后，若该问题无其他有效回答，`question_status` 置回 `0`

**问题分类枚举**：
- `1` 养殖技术、`2` 疫病防治、`3` 饲料营养、`4` 市场价格、`5` 政策法规

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 问题分页列表 | GET | `/kc-admin/qa/questions/list` | pageNum、pageSize、questionCategory（1/2/3/4/5，可为空）、questionStatus（0/1/2，可为空）、keyword（可为空） | 分页列表（question_id、title、question_category、question_status、user_nickname、view_count、answer_count、create_time）+ 总数 | 🆕 新增；仅返回 del_flag=0 |
| 问题详情 | GET | `/kc-admin/qa/questions/{id}` | path: question_id | 问题完整信息 + 回答列表（按时间正序，最佳答案置顶） | 🆕 新增 |
| 删除问题 | DELETE | `/kc-admin/qa/questions/{ids}` | path: question_id，支持批量逗号分隔 | 操作结果 | 🆕 新增；逻辑删除 |
| 回答问题 | POST | `/kc-admin/qa/questions/{id}/answers` | path: question_id；content、imageUrls（可选） | 操作结果 + answer_id | 🆕 新增；is_expert 自动置为 1 |
| 回答列表 | GET | `/kc-admin/qa/questions/{id}/answers` | path: question_id；pageNum、pageSize | 回答分页列表（answer_id、user_nickname、user_avatar、content、image_urls、is_expert、is_accepted、create_time）+ 总数 | 🆕 新增；仅返回 del_flag=0 |
| 删除回答 | DELETE | `/kc-admin/qa/answers/{ids}` | path: answer_id，支持批量逗号分隔 | 操作结果 | 🆕 新增；逻辑删除，同步更新 answer_count、question_status |
| 回答图片上传 | POST | `/common/upload` | file | fileUrl | ✅ 直接复用，见现有业务说明.spec.md |

## 3.5 非功能需求

- **性能**：问题列表首屏加载 < 2秒；回答提交响应 < 1秒。
- **安全与权限**：仅 county_admin、county_staff 可访问；需登录且具备对应菜单权限。
- **兼容性**：同功能一。

## 3.6 验收标准

- [ ] 问题列表支持按分类、状态筛选，分页展示
- [ ] 问题详情正确展示问题信息和回答列表
- [ ] 删除问题后，网站端该问题不再展示
- [ ] 后台人员可回答问题，回答内容正确写入 kc_qa_answer，is_expert=1
- [ ] 后台回答后，问题 question_status 正确更新为「已回答」，answer_count +1
- [ ] 网站端展示后台回答时显示「专家」标识
- [ ] 删除回答后，answer_count 正确减 1；若无其他有效回答，question_status 置回「待回答」
- [ ] 回答表单前端校验在提交时正确触发
- [ ] 删除问题、删除回答均有二次确认

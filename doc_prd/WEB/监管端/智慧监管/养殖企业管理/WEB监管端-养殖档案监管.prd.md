## 功能一：养殖档案列表查看与筛选

### 1.1 基本信息

- **功能名称**：养殖档案列表查看与筛选
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 权限管理：复用现有角色权限体系，新增"养殖档案监管总览入口"权限标识 `admin:archive:overview`
  - 企业端养殖信息管理：18 个子模块的列表接口全部复用（列表查询、筛选条件），见附录「18 个档案类别接口与字段对照表」
  - 部门树：`sys_dept` 表提供行政区划数据，用于乡镇下拉筛选与数据权限过滤
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 县级管理员 | `county_admin` | 全县养殖档案总览 | 查看全县所有企业的各类养殖档案记录 |
| 县级业务人员 | `county_staff` | 日常审批工作台 | 按Tab查看不同类别的档案记录，找到待终审的数据 |
| 乡镇政府业务人员 | `town_gov_staff` | 辖区内企业档案审核 | 按Tab查看本乡镇企业的各类档案记录，找到待审核的数据 |
| 乡镇畜牧兽医站 | `town_vet_station` | 辖区内企业档案核实 | 按Tab查看本乡镇企业的各类档案记录，找到待核实的数据 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。

### 1.2 目标与范围

**目标**：
1. 以 Tab 页签形式组织 18 个档案类别，每个 Tab 对应一类养殖档案记录的分页列表。
2. 每个 Tab 下的列表在企业端对应模块列表字段基础上，额外展示"企业名称"和"所属乡镇"两列。
3. 每个 Tab 下支持按企业名称（模糊搜索）、所属乡镇（下拉筛选）、状态（下拉筛选）及各档案类别自有的搜索条件进行筛选。
4. 数据范围按角色自动过滤：县级看全县，乡镇看本乡镇。

**非目标（Non-Goals）**：
- ❌ 监管端不提供养殖档案的新增/填报功能（由企业端完成，县级管理员的直接管理操作见功能五）。
- ❌ 不将 18 个档案类别拆分为 18 个独立菜单页面。
- ❌ 不提供跨档案类别的混合搜索（每个 Tab 下独立搜索）。

### 1.3 现状与复用

**现状简述**：
- 18 个档案类别的数据全部来自企业端已定义的各业务表，企业端用户填报，监管端消费。
- 企业端各模块的列表接口已支持 `enterpriseName`（企业名称筛选）和 `areaCode`（行政区划筛选）参数，后端已实现数据权限过滤（按部门树 + `data_scope`）。
- 监管端直接调用企业端的列表接口，传入监管端用户的认证信息，后端自动按监管端角色的数据范围返回对应数据。

### 1.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| Tab 页签切换 | P0 | 18 个档案类别以 Tab 页签形式组织，按业务逻辑分组 |
| 各类别分页列表展示 | P0 | 每个 Tab 下展示对应类别的分页列表 |
| 监管端专属筛选条件 | P0 | 在企业端筛选条件基础上额外增加企业名称和所属乡镇筛选 |
| 数据权限自动过滤 | P0 | 县级看全县，乡镇看本乡镇 |

**关键流程**：

```
进入养殖档案监管页面，默认激活第一个Tab（养殖信息）
    ↓
系统按当前用户数据权限 + 当前Tab对应的接口加载列表
    ↓
用户切换Tab → 立即加载对应类别的列表数据（即时响应）
    ↓
用户可在当前Tab下输入筛选条件 → 点击"查询"刷新列表
    ↓
用户可在操作列点击"查看"→ 弹出详情弹窗（功能二）
用户可在操作列点击审批操作按钮 → 弹出审批弹窗（功能三）
```

#### 1.4.1 功能流程逻辑

**Tab 页签分组规则**：

Tab 页签按以下 5 个分组横向排列展示，同一分组内的 Tab 紧邻排列，分组间以竖线分隔符区分：

| 分组 | Tab 名称（按顺序） |
|------|----------------|
| 养殖管理 | 养殖信息、繁育信息、断奶信息、入栏信息、转栏信息、出栏信息 |
| 防疫免疫 | 畜禽免疫记录、消毒记录、防疫监测记录 |
| 投入品管理 | 兽药购进记录、兽药使用记录、饲料添加剂购进记录、配合饲料使用记录 |
| 疾病与处理 | 畜禽疾病诊疗记录、病死畜禽无害化处理记录、粪便及污物无害化处理记录 |
| 生产与销售 | 生产记录、畜禽及其产品销售记录 |

**Tab 切换逻辑**：
- 切换 Tab 为即时响应：点击 Tab 后立即重新加载对应类别的列表数据，无需额外点击「查询」按钮。
- 切换过程中展示骨架屏/loading 遮罩，防止内容空白闪烁。
- 当前激活 Tab 以主色底色 + 白色文字标识选中态，非激活 Tab 为浅灰底色。
- Tab 数量超出可视宽度时支持横向滚动或左右箭头切换。
- 切换 Tab 时重置该 Tab 下的筛选条件为默认值。

**监管端列表与企业端列表的差异**：

每个 Tab 下的列表在企业端对应模块列表的基础上有以下差异：

| 差异项 | 企业端 | 监管端 |
|-------|-------|-------|
| 企业名称列 | 不展示（企业端只看本企业数据） | **额外展示**，位于列表第 2 列（序号之后） |
| 所属乡镇列 | 不展示 | **额外展示**，位于企业名称列之后 |
| 筛选条件 | 仅业务字段筛选 | **额外增加**企业名称（模糊搜索）和所属乡镇（下拉筛选） |
| 数据范围 | 本企业数据 | 按角色数据权限过滤（全县/本乡镇） |
| 操作列 | 编辑、删除、提交 | 查看、审批操作（核实/审核/终审，按角色和数据状态动态展示） |
| 新增/编辑/删除按钮 | 企业端有 | 监管端无（县级管理员除外，见功能五） |

**筛选条件规则**（适用于所有 18 个 Tab）：

| 序号 | 筛选项名称 | 适用角色 | 控件类型 | 说明 |
|------|---------|---------|---------|------|
| 1 | 企业名称 | 全部角色 | 输入框（文本） | 模糊搜索，最大长度 100 字符，传入 `enterpriseName` 参数 |
| 2 | 所属乡镇 | 仅县级角色展示 | 下拉选择（单选） | 含"全部"选项，数据来自 `GET /system/dept/treeselect`；乡镇角色不展示此筛选项（自动按本乡镇过滤） |
| 3 | 状态 | 全部角色 | 下拉选择（单选） | 含"全部"选项，枚举值：`0` 草稿、`1` 待核实、`2` 待审核、`3` 待终审、`4` 已入库、`5` 核实退回、`6` 审核退回、`7` 终审退回，共 8 种取值 |
| 4 | 各类别自有筛选条件 | 全部角色 | 按各企业端 PRD 定义 | 每个 Tab 继承企业端对应模块的筛选条件（如日期范围、圈舍名称筛选） |

#### 1.4.2 数据模型与字段定义

#### 1.4.3 界面交互逻辑

**养殖档案监管页面**：
- 页面标题：养殖档案监管。
- 顶部 Tab 页签栏：横向排列 18 个 Tab，按 1.4.1 中的分组规则排列，分组间以竖线（`|`）分隔。Tab 栏可横向滚动（当 Tab 总宽度超出页面宽度时，右侧出现「>」滚动箭头，左侧出现「<」滚动箭头）。
- Tab 下方为筛选栏 + 列表区域，每个 Tab 独立。
- **Tab 切换为即时响应**：点击 Tab 标签后立即筛选并刷新下方展示内容，无需额外点击「查询」按钮。切换过程中展示骨架屏加载效果。当前激活标签以主色底色 + 白色文字标识选中态，非激活标签为浅灰底色。

**每个 Tab 下的列表页结构**：
- 筛选栏：企业名称（输入框）、所属乡镇（下拉，仅县级角色展示）、状态（下拉）、各类别自有筛选条件 + 「查询」按钮 + 「重置」按钮。
- 操作按钮区（筛选栏下方右侧）：
  - 「导出」按钮（默认色，功能四）。
  - 「新增」按钮（主色，仅 `county_admin` 角色展示，功能五）。
- 列表表格：序号、企业名称、所属乡镇、各类别业务字段列、状态（彩色标签）、操作列。
- 操作列按钮（按角色和数据状态动态展示）：
  - 「查看」灰色文字按钮（所有角色、所有状态可见）。
  - 「核实通过」+「核实退回」蓝色/红色文字按钮（仅 `town_vet_station` 角色，仅状态为 `1`（待核实）时展示）。

### 2.1 基本信息

- **功能名称**：养殖档案详情查看
- **关联现有模块/功能**：
  - 用户认证：复用现有登录认证机制

| 县级业务人员 | `county_staff` | 终审前查看档案详情 | 查看完整字段信息、审核进度、历史审核意见 |

### 2.2 目标与范围

**目标**：
1. 点击列表中某条记录时，弹出详情弹窗展示该记录的完整字段信息。
2. 详情内容与企业端各模块的详情页字段完全相同。
3. 额外展示：企业名称、所属乡镇、审核进度步骤条。
4. 所有字段只读展示。

**非目标（Non-Goals）**：
- ❌ 不在详情弹窗中提供编辑功能。
- ❌ 不提供跳转到企业端详情页的能力。

### 2.3 现状与复用

**现状简述**：
- 企业端各模块已定义详情接口（`GET /{basePath}/{id}`），返回单条记录的全部字段。
- 监管端直接调用企业端详情接口获取数据，后端通过数据权限自动校验访问合法性。

**复用检查结论**：

**1. 接口复用检查（对照 `doc_spec/现有业务说明.spec.md`）**

| 检查项 | 现有资源 | 复用结论 | 说明 |
|--------|---------|---------|------|
| 各档案类别的详情接口 | 如 GET `/farm/breeding-info/{id}` | ✅ 直接复用 | 18 个子模块各自的详情接口全部复用，见附录 |

**2. 数据库表复用检查（对照 `doc_spec/现有数据库说明.spec.md`）**

| 检查项 | 现有资源 | 复用结论 | 说明 |
|--------|---------|---------|------|
| 18个档案业务表 | 各 `pig_*` 表 | ✅ 直接复用 | 只读查询 |

### 2.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 详情弹窗展示 | P0 | 弹窗展示记录全部字段，只读 |
| 审核进度步骤条 | P0 | 横向步骤条展示四级审批进度 |
| 监管端额外信息 | P0 | 额外展示企业名称、所属乡镇 |

**关键流程**：

```
在某个Tab下的列表中，点击操作列的"查看"按钮
    ↓
弹出详情弹窗（Dialog，宽度 700px）
    ↓
弹窗顶部展示审核进度步骤条（横向 4 个节点）
    ↓
弹窗内容展示企业名称、所属乡镇 + 企业端各模块详情页的全部字段（只读）
    ↓

```

#### 2.4.1 功能流程逻辑

**审核进度步骤条定义**（横向步骤条，4 个节点，所有 18 个类别通用）：

| 步骤序号 | 节点名称 | 状态映射 | 展示逻辑 |
|---------|---------|---------|---------|
| 步骤1 | 企业填报 | 任意非 `0`（草稿）状态均为已完成 | 已完成：绿色勾 |
| 步骤2 | 乡镇畜牧兽医站核实 | `1`=进行中（蓝色）；`2`/`3`/`4`=已完成（绿色勾）；`5`=退回（红色叉） | — |
| 步骤3 | 乡镇政府审核 | `2`=进行中（蓝色）；`3`/`4`=已完成（绿色勾）；`6`=退回（红色叉）；`1`/`5`=未开始（灰色） | — |
| 步骤4 | 县级终审 | `3`=进行中（蓝色）；`4`=已完成（绿色勾）；`7`=退回（红色叉）；`1`/`2`/`5`/`6`=未开始（灰色） | — |

退回节点下方展示退回意见文字（红色字体，来自对应的 `verify_remark`、`audit_remark` 或 `final_audit_remark` 字段）。

**详情字段展示规则**：
- 弹窗顶部区域：审核进度步骤条。
- 弹窗内容区域分为两部分：
  1. **监管端额外信息**（灰色背景区域）：企业名称（`enterprise_name`）、所属乡镇（`area_name`）。
  2. **业务字段区域**：与企业端各模块详情页展示的字段完全一致（包括照片预览），所有字段只读展示。各字段的具体定义见企业端各子模块 PRD 的 §X.4.2 数据模型。
- 弹窗底部区域：
  - 若当前用户有审批操作权限且数据处于对应待审批状态，展示审批操作按钮（功能三）。
  - 否则仅展示"关闭"按钮。

#### 2.4.2 数据模型与字段定义

本功能无新建表。详情展示字段完全复用企业端各模块已定义的数据模型，见各企业端子模块 PRD 的 §X.4.2。

### 3.2 目标与范围

**目标**：
1. 监管端不同角色在对应的待审批状态下可执行审批操作（通过/退回）。
2. 审批操作复用企业端各模块已定义的四级审批接口。
3. 退回时必须填写退回原因，通过时意见选填。
4. 审批操作后列表自动刷新，数据状态更新。

**非目标（Non-Goals）**：
- ❌ 不支持批量审批。
- ❌ 不提供审批撤销功能。
- ❌ 不修改企业端已定义的审批状态流转规则。

### 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 核实通过/退回 | P0 | 乡镇畜牧兽医站对"待核实"数据操作，通过后状态变为"待审核"，退回后状态变为"核实退回" |
| 审核通过/退回 | P0 | 乡镇政府业务人员对"待审核"数据操作，通过后状态变为"待终审"，退回后状态变为"审核退回" |
| 终审通过/退回 | P0 | 县级业务人员对"待终审"数据操作，通过后状态变为"已入库"，退回后状态变为"终审退回" |

**关键流程**：

```
审批流程（以核实为例，审核和终审流程完全一致）：
    ↓
方式一：在列表操作列点击"核实通过"或"核实退回"
方式二：在详情弹窗底部点击"核实通过"或"核实退回"
    ↓
点击"通过"：
  → 弹出确认弹窗（含选填意见文本域）
  → 确认后调用核实通过接口
  → 成功：关闭弹窗，刷新列表，提示"操作成功"
    ↓
点击"退回"：
  → 弹出确认弹窗（含必填退回原因文本域）
  → 确认后调用核实退回接口
  → 成功：关闭弹窗，刷新列表，提示"操作成功"
```

#### 3.4.1 功能流程逻辑

**审批状态流转规则**（与企业端各模块定义完全一致）：

```
待核实(1) ──核实通过──→ 待审核(2)
     └──核实退回──→ 核实退回(5)

待审核(2) ──审核通过──→ 待终审(3)
     └──审核退回──→ 审核退回(6)

待终审(3) ──终审通过──→ 已入库(4)
     └──终审退回──→ 终审退回(7)

退回后(5/6/7) → 企业端修改重新提交 → 待核实(1)（重新进入审批流程）
```

**各角色的审批权限**：

| 操作 | 操作角色 | 触发条件（status值） | 操作后status值 |
|------|---------|-------------------|--------------|
| 核实通过 | `town_vet_station` | status = `1`（待核实） | status → `2`（待审核） |
| 核实退回 | `town_vet_station` | status = `1`（待核实） | status → `5`（核实退回） |
| 审核通过 | `town_gov_staff` | status = `2`（待审核） | status → `3`（待终审） |
| 审核退回 | `town_gov_staff` | status = `2`（待审核） | status → `6`（审核退回） |
| 终审通过 | `county_staff` | status = `3`（待终审） | status → `4`（已入库） |
| 终审退回 | `county_staff` | status = `3`（待终审） | status → `7`（终审退回） |

**退回原因规则**：
- 退回操作时，退回原因为必填字段，不填写则无法提交退回操作。
- 通过操作时，审批意见为选填字段。
- 审批意见/退回原因最大长度 500 字符。

#### 3.4.2 数据模型与字段定义

本功能无新建表或新增字段。审批操作更新企业端各业务表中已有的审核字段：

#### 3.4.3 界面交互逻辑

**审批操作入口**（两种方式）：

1. **列表操作列按钮**：在功能一列表的操作列中，按角色和数据状态动态展示审批操作按钮。
2. **详情弹窗底部按钮**：在功能二详情弹窗的底部操作区，按角色和数据状态展示审批操作按钮。

**审批确认弹窗**（所有审批操作通用）：

- **通过操作弹窗**：
  - 标题：根据操作类型动态显示——"确认核实通过" / "确认审核通过" / "确认终审通过"
  - 内容：审批意见文本域（选填，placeholder: "请输入审批意见（选填）"，最大 500 字符）
  - 按钮："取消"（默认色）、"确认通过"（主色按钮）
  - 确认前二次弹窗：不需要（直接在审批弹窗内确认即可）

- **退回操作弹窗**：
  - 标题：根据操作类型动态显示——"确认核实退回" / "确认审核退回" / "确认终审退回"
  - 内容：退回原因文本域（必填，placeholder: "请输入退回原因（必填）"，最大 500 字符）
  - 按钮："取消"（默认色）、"确认退回"（红色按钮）
  - 退回原因为空时点击"确认退回"，文本域下方展示红色提示文字"请填写退回原因"

**校验规则**：

> **校验时机**：点击"确认通过"/"确认退回"时校验。
>
> **校验提示位置**：错误提示紧邻文本域下方展示（红色文字）。

| 校验字段 | 校验类型 | 校验规则 | 错误提示文案 |
|---------|---------|---------|------------|
| 审批意见（通过时） | 长度 | 选填，最大 500 字符 | 「审批意见不能超过500个字符」 |
| 退回原因（退回时） | 必填 + 长度 | 不能为空，最大 500 字符 | 「请填写退回原因」/「退回原因不能超过500个字符」 |

**操作反馈**：
- 操作成功：关闭审批弹窗（和详情弹窗，若从详情弹窗触发），弹出成功提示（Toast，2秒自动关闭）——"操作成功"，列表自动刷新。
- 操作失败：审批弹窗不关闭，弹出错误提示（Toast）——展示后端返回的错误信息。

## 功能五：县级管理员直接管理操作

### 5.1 基本信息

- **功能名称**：县级管理员直接管理操作
- **关联现有模块/功能**：
  - 用户认证：复用现有登录认证机制
  - 企业端养殖信息管理：18 个子模块的新增、编辑、删除接口全部复用
  - 参考文档：`doc_spec/现有业务说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 县级管理员 | `county_admin` | 对养殖档案数据进行直接管理 | 直接新增档案记录（入库）、编辑已有记录、删除记录 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。仅县级管理员拥有此管理权限。

### 5.2 目标与范围

**目标**：
1. 县级管理员可在监管端对任意档案类别直接新增记录，新增记录的 `data_source` 标记为 `2`（县级直接录入），状态直接为"已入库"（`4`），跳过审批流程。
2. 县级管理员可编辑任意状态的档案记录（编辑后系统自动记录县级编辑追溯信息）。
3. 县级管理员可删除档案记录（删除后系统自动记录县级删除追溯信息）。

**非目标（Non-Goals）**：
- ❌ 县级管理员的编辑/删除不影响审批流程的状态流转规则（已入库的记录被编辑后状态不变）。
- ❌ 不提供批量新增、批量编辑、批量删除功能。

### 5.3 现状与复用

**现状简述**：
- 企业端各模块已定义新增、编辑、删除接口，县级管理员可复用这些接口。
- 企业端各业务表已包含 `data_source`、`county_edited`、`county_edit_by`、`county_edit_time`、`county_edit_remark`、`county_deleted`、`county_delete_by`、`county_delete_time`、`county_delete_remark` 等县级操作追溯字段。

**复用检查结论**：

**1. 接口复用检查（对照 `doc_spec/现有业务说明.spec.md`）**

| 检查项 | 现有资源 | 复用结论 | 说明 |
|--------|---------|---------|------|
| 各档案类别的新增接口 | 如 POST `/farm/breeding-info` | ✅ 直接复用 | 县级管理员调用时后端自动设置 `data_source='2'`、`status='4'` |
| 各档案类别的编辑接口 | 如 PUT `/farm/breeding-info` | ✅ 直接复用 | 县级管理员调用时后端自动记录县级编辑追溯字段 |
| 各档案类别的删除接口 | 如 DELETE `/farm/breeding-info/{ids}` | ✅ 直接复用 | 县级管理员调用时后端自动记录县级删除追溯字段 |

**2. 数据库表复用检查**：无新建表。复用各业务表已有的县级操作追溯字段。

### 5.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 直接新增档案记录 | P1 | 县级管理员可在任意Tab下点击"新增"直接录入数据，数据来源标记为"县级直接录入"，状态直接为"已入库" |
| 编辑档案记录 | P1 | 县级管理员可编辑任意记录，编辑后自动记录追溯信息 |
| 删除档案记录 | P1 | 县级管理员可删除记录，删除前二次确认，删除后自动记录追溯信息 |

**关键流程**：

```
新增操作：
县级管理员点击"新增"按钮 → 弹出新增表单弹窗
→ 填写表单字段（与企业端新增表单一致，额外需选择关联企业）
→ 提交 → 记录直接以"已入库"状态入库

编辑操作：
县级管理员点击列表操作列"编辑"按钮 → 弹出编辑表单弹窗
→ 修改字段 → 提交 → 系统自动记录county_edited等追溯字段

删除操作：
县级管理员点击列表操作列"删除"按钮 → 弹出确认弹窗
→ 确认 → 系统标记county_deleted等追溯字段（逻辑删除）
```

#### 5.4.1 功能流程逻辑

**新增规则**：
- 县级管理员新增的记录：`data_source = '2'`（县级直接录入）、`status = '4'`（已入库），跳过四级审批流程。
- 新增表单中需额外提供"关联企业"下拉选择（从全县企业列表中选择），系统自动填入 `enterprise_id`、`enterprise_name`、`area_name`。
- 其余表单字段与企业端各模块的新增表单完全一致。

**编辑规则**：
- 县级管理员可编辑任意状态的记录。
- 编辑时后端自动更新追溯字段：`county_edited = '1'`、`county_edit_by = 当前用户名`、`county_edit_time = 当前时间`。
- 编辑不影响记录的当前审批状态（如已入库的记录编辑后仍为已入库）。

**删除规则**：
- 县级管理员可删除任意记录。
- 删除前弹出二次确认弹窗："确定要删除该记录吗？删除后不可恢复。"
- 删除时后端自动记录追溯字段：`county_deleted = '1'`、`county_delete_by = 当前用户名`、`county_delete_time = 当前时间`，执行逻辑删除（`del_flag = '2'`）。

#### 5.4.2 数据模型与字段定义

本功能无新建表或新增字段，复用企业端各业务表已有的县级操作追溯字段。

**县级操作追溯字段**（所有 18 个业务表通用，已在企业端 PRD 中定义）：

| 字段名（英文） | 类型 | 说明 |
|--------------|------|------|
| data_source | char(1) | `1` 企业填报、`2` 县级直接录入，仅此 2 种取值 |
| county_edited | char(1) | `0` 未编辑（默认）、`1` 已被县级编辑 |
| county_edit_by | varchar(64) | 县级编辑操作人用户名 |
| county_edit_time | datetime | 县级编辑操作时间 |
| county_edit_remark | varchar(500) | 县级编辑备注（预留，当前版本不使用） |
| county_deleted | char(1) | `0` 未删除（默认）、`1` 已被县级删除 |
| county_delete_by | varchar(64) | 县级删除操作人用户名 |
| county_delete_time | datetime | 县级删除操作时间 |
| county_delete_remark | varchar(500) | 县级删除备注（预留，当前版本不使用） |

#### 5.4.3 界面交互逻辑

**新增按钮**：位于每个Tab下筛选栏右侧操作区，仅 `county_admin` 角色可见。
- 按钮文字："新增"。

### 关键约束总结

1. **监管端不重复建表**：所有数据来自企业端已定义的业务表，监管端不新建业务数据表。
2. **接口全量复用**：养殖档案的列表/详情/审批/导出/新增/编辑/删除接口直接复用企业端接口，通过数据权限机制实现不同角色看到不同范围的数据。
3. **数据范围靠部门树**：县级角色看全县，乡镇角色看本乡镇下的企业，通过 `data_scope` + 部门树自动过滤。
4. **审批链路统一**：企业管理员发起 → 乡镇畜牧兽医站核实 → 乡镇政府审核 → 县级业务人员终审，与企业端定义完全一致。
5. **县级管理员特殊权限**：县级管理员可直接新增（跳过审批）、编辑、删除任意记录，所有操作自动记录追溯信息。

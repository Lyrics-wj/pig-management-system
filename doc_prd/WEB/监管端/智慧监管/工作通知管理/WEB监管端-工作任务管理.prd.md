## 2.2 目标与范围

**目标**：
1. 实现县级监管部门向下级单位和养殖企业下发工作任务、跟踪执行进度、收集反馈的完整功能。
2. 支持任务状态全生命周期管理：草稿→已下发→进行中→已完成/已撤回。
3. 支持填报期限设置，超期自动标记，便于监管端及时督促。
4. 接收方可提交文本+附件形式的执行反馈。
5. 下发方可查看各接收方的反馈进度、反馈内容及超期情况。

**非目标（Non-Goals）**：
- ❌ 不提供结构化数据报送功能（结构化报送由「信息收集管理」模块实现）。
- ❌ 不提供任务审批流程（任务下发后直接生效，无需审批）。
- ❌ 不支持反馈修改（提交后不可修改，如需修改须联系下发方重新开放）。
- ❌ 短信通知功能仅定义开关，具体发送由后续技术方案确定。
- ❌ 不支持任务到期自动关闭（超期仅做标记，不影响状态流转）。

### 2.4.1 功能流程逻辑

**任务状态流转**：

| 当前状态 | 触发动作 | 目标状态 | 触发条件 |
|---------|---------|---------|---------|
| - | 新增保存 | 草稿（`0`） | 填写表单后点击「保存」 |
| 草稿（`0`） | 点击「下发」 | 已下发（`1`） | 必填项校验通过 |
| 已下发（`1`） | 至少一个接收方提交反馈 | 进行中（`2`） | 系统自动流转 |
| 已下发（`1`）/ 进行中（`2`） | 所有接收方均已反馈 | 已完成（`3`） | 系统自动流转 |
| 已下发（`1`）/ 进行中（`2`） | 下发方点击「标记完成」 | 已完成（`3`） | 二次确认后手动流转 |
| 已下发（`1`）/ 进行中（`2`） | 下发方点击「撤回」 | 已撤回（`4`） | 二次确认后流转 |

**下发逻辑规则**：
1. 点击「下发」时，系统自动在 `pig_work_task_feedback` 表中为每个接收人生成一条未反馈记录（`feedback_status = '0'`）。
2. 发布范围逻辑与通知公告管理一致（全部/按机构/按人员）。
3. 下发时记录 `dispatch_time` 为当前服务器时间。

**反馈逻辑规则**：
1. 接收方提交反馈后，`feedback_status` 更新为 `'1'`，`feedback_time` 记录为当前服务器时间。
2. 若反馈时间晚于任务 `deadline`，`is_overdue` 自动标记为 `'1'`。
3. 提交反馈后不可修改，提交前需二次确认弹窗：「确认提交反馈？提交后不可修改。」
4. 若任务设置了"需要附件反馈"（`require_attachment = '1'`），接收方提交反馈时附件字段变为必填。
5. 每次接收方提交反馈后，系统检查是否所有接收方均已反馈，若是则自动将任务状态流转为"已完成"。
6. 提交反馈时，若任务状态为"已下发"（无人反馈过），系统同时将任务状态更新为"进行中"。

**撤回逻辑规则**：
1. 撤回前需二次确认弹窗：「确认撤回该任务？撤回后未反馈的接收方将不再需要反馈。」
2. 撤回后任务状态变为"已撤回"，仅可查看，不可编辑、不可再次下发。

**标记完成逻辑规则**：
1. 标记完成前需二次确认弹窗：「确认标记该任务为已完成？当前仍有 X 人未反馈。」
2. 标记完成后任务状态变为"已完成"，未反馈的接收方不再需要反馈。

**超期判定规则**：
1. 当前时间超过任务 `deadline` 且接收方 `feedback_status = '0'` 时，该接收方标记为超期。
2. 任务列表中，只要有至少一个接收方超期，该任务行展示红色"超期"Tag。
3. 超期仅为标记，不影响状态流转（超期后接收方仍可提交反馈）。

**按钮展示逻辑（下发方列表）**：

| 任务状态 | 可见操作按钮 |
|---------|------------|
| 草稿（`0`） | 「编辑」「下发」「删除」 |
| 已下发（`1`）/ 进行中（`2`） | 「查看」「撤回」「反馈详情」「标记完成」 |
| 已完成（`3`） | 「查看」「反馈详情」 |
| 已撤回（`4`） | 「查看」 |

| 下发人 | create_by 关联 sys_user.nick_name | 文本 |
| 填报期限 | deadline | 格式 `yyyy-MM-dd HH:mm` |
| 我的反馈状态 | feedback_status | Tag 标签：未反馈（灰色）、已反馈（绿色） |
| 是否超期 | 计算判定 | 条件显示：未反馈且超过 deadline 时展示红色 Tag「超期」 |
| 操作 | - | 未反馈→「查看」「提交反馈」；已反馈→「查看」「查看反馈」 |

- 行样式规则：未反馈且已超期的行以浅红色背景（`#FFF0F0`）高亮
- 分页：每页默认10条，支持选择 10/20/50 条每页

**新增/编辑任务弹窗（对话框）**：

弹窗标题：新增时为「新增任务」，编辑时为「编辑任务」。宽度 720px。

| 表单字段 | 控件类型 | 必填 | 校验规则 | 错误提示 |
|---------|---------|------|---------|---------|
| 任务名称 | 文本输入框 | 是 | 最大100个字符，不能为空 | 「请输入任务名称」/「任务名称不能超过100个字符」 |
| 任务类型 | 下拉选择器（字典 `pig_work_task_type`） | 是 | 不能为空 | 「请选择任务类型」 |
| 紧急程度 | 下拉选择器 | 是 | 不能为空 | 「请选择紧急程度」 |
| 任务描述 | 富文本编辑器 | 是 | 不能为空 | 「请输入任务描述」 |
| 附件 | 多文件上传组件 | 否 | 单文件最大20MB，总计最大100MB | 「单个文件不能超过20MB」/「附件总大小不能超过100MB」 |
| 下发范围类型 | 单选按钮组（全部/按机构/按人员） | 是 | 不能为空 | 「请选择下发范围」 |
| 下发范围值-按机构 | 部门树多选（scope_type 为 `1` 时显示） | 条件必填 | scope_type 为 `1` 时不能为空 | 「请选择目标机构」 |
| 下发范围值-按人员 | 用户列表多选穿梭框（scope_type 为 `2` 时显示） | 条件必填 | scope_type 为 `2` 时不能为空 | 「请选择目标人员」 |
| 填报期限 | 日期时间选择器 | 是 | 不能为空，不能早于当前时间 | 「请选择填报期限」/「填报期限不能早于当前时间」 |
| 是否短信通知 | 开关 | 是 | - | - |
| 是否需要附件反馈 | 开关 | 是 | - | - |

- 底部按钮：「保存草稿」「下发」「取消」
  - 「保存草稿」：校验通过后保存为草稿状态
  - 「下发」：校验通过后保存并直接下发
  - 「取消」：关闭弹窗，需二次确认：「确认关闭？未保存的内容将丢失。」
- 编辑模式下仅草稿状态可进入，所有字段可修改
- 自动回显字段（只读）：无

**任务详情页面**：

- 页面顶部展示：任务名称（大字号）、任务类型（Tag）、紧急程度（Tag）、状态（Tag）
- 基本信息区域：下发单位、下发人、下发时间、填报期限、是否需要附件反馈
- 正文区域：富文本渲染任务描述
- 附件区域：附件列表，每项显示文件名+文件大小+「下载」按钮
- 底部按钮：「返回」；接收方未反馈时额外展示「提交反馈」按钮

**提交反馈弹窗**：

弹窗标题：「提交反馈 - {任务名称}」。宽度 600px。

| 表单字段 | 控件类型 | 必填 | 校验规则 | 错误提示 |
|---------|---------|------|---------|---------|
| 反馈内容 | 文本域（多行） | 是 | 最大2000个字符，不能为空 | 「请输入反馈内容」/「反馈内容不能超过2000个字符」 |
| 附件 | 多文件上传组件 | 条件必填 | 任务 `require_attachment = '1'` 时必填 | 「此任务要求上传附件，请上传反馈附件」 |

- 底部按钮：「提交」「取消」
- 提交前二次确认弹窗：「确认提交反馈？提交后不可修改。」

**反馈详情弹窗**：

弹窗标题：「反馈详情 - {任务名称}」。宽度 800px。

- 顶部统计区域：已反馈人数/总人数、反馈率百分比（进度条展示）、超期人数
- 列表字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 接收人姓名 | sys_user.nick_name | 文本 |
| 所属机构 | sys_dept.dept_name | 文本 |
| 反馈状态 | feedback_status | Tag 标签：未反馈（灰色）、已反馈（绿色） |
| 反馈时间 | feedback_time | 格式 `yyyy-MM-dd HH:mm`，未反馈时显示 `-` |
| 是否超期 | is_overdue | 条件显示：超期时展示红色 Tag「超期」 |
| 操作 | - | 已反馈→「查看反馈」按钮 |

- 点击「查看反馈」弹出反馈内容子弹窗：展示反馈内容（文本）+ 反馈附件列表（可下载）

**校验时机**：
- 表单字段在失焦（blur）时即时校验单个字段。
- 点击「保存草稿」、「下发」或「提交」时对全部字段做整体校验，校验不通过时阻断操作，错误提示紧邻对应字段展示。

### 2.4.4 接口路径定义

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 任务列表-下发方 | GET | `/admin/tasks/list` | pageNum、pageSize、taskName（模糊）、taskType（下拉）、status（下拉）、beginDispatchTime、endDispatchTime | 分页列表+总数，每行含反馈进度统计 | 仅返回当前用户下发的任务 |
| 任务列表-接收方 | GET | `/admin/tasks/received/list` | pageNum、pageSize、taskName（模糊）、taskType（下拉）、feedbackStatus（下拉） | 分页列表+总数 | 仅返回已下发/进行中/已完成状态且发给当前用户的任务 |
| 任务详情 | GET | `/admin/tasks/{taskId}` | taskId（路径参数） | 任务完整信息 | — |
| 新增任务 | POST | `/admin/tasks` | 见 2.4.2 字段定义（除系统自动字段外） | 操作结果 + taskId | — |
| 修改任务 | PUT | `/admin/tasks` | taskId + 可修改字段 | 操作结果 | 仅草稿状态可修改 |
| 下发任务 | PUT | `/admin/tasks/dispatch/{taskId}` | taskId（路径参数） | 操作结果 | 草稿→已下发，自动生成接收人反馈记录 |
| 撤回任务 | PUT | `/admin/tasks/revoke/{taskId}` | taskId（路径参数） | 操作结果 | 已下发/进行中→已撤回 |
| 标记完成 | PUT | `/admin/tasks/complete/{taskId}` | taskId（路径参数） | 操作结果 | 手动标记完成 |
| 删除任务 | DELETE | `/admin/tasks/{taskIds}` | taskIds（路径参数，逗号分隔） | 操作结果 | 仅草稿可删除，支持批量 |
| 提交反馈 | POST | `/admin/tasks/feedback` | taskId、feedbackContent、feedbackAttachments | 操作结果 | 接收方提交 |
| 反馈详情列表 | GET | `/admin/tasks/feedback/list/{taskId}` | taskId（路径参数） | 反馈列表（姓名、机构、反馈状态、时间、是否超期）+ 统计 | 下发方查看 |
| 反馈内容详情 | GET | `/admin/tasks/feedback/{feedbackId}` | feedbackId（路径参数） | 反馈内容+附件列表 | — |

## 2.5 非功能需求

**安全与权限**：

| 权限标识 | 说明 | 拥有角色 |
|---------|------|---------|
| `admin:task:list` | 查看下发方任务列表 | `county_admin`、`county_staff` |
| `admin:task:add` | 新增任务 | `county_admin`、`county_staff` |
| `admin:task:edit` | 编辑任务 | `county_admin`、`county_staff` |
| `admin:task:dispatch` | 下发任务 | `county_admin`、`county_staff` |
| `admin:task:revoke` | 撤回任务 | `county_admin`、`county_staff` |
| `admin:task:complete` | 标记完成 | `county_admin`、`county_staff` |
| `admin:task:remove` | 删除任务 | `county_admin` |
| `admin:task:received` | 接收查看任务 | `town_gov_staff`、`town_vet_station`、`ent_admin` |
| `admin:task:feedback` | 提交反馈 | `town_gov_staff`、`town_vet_station`、`ent_admin` |
| `admin:task:feedback-detail` | 查看反馈详情 | `county_admin`、`county_staff` |

**数据权限**：
- 县级角色（`county_admin`、`county_staff`）可操作全部任务。
- 接收方角色（`town_gov_staff`、`town_vet_station`、`ent_admin`）只能查看发给自己（或自己所属机构）的任务。

**性能要求**：
- 任务列表查询响应时间 ≤ 500ms（数据量 ≤ 10000 条）。
- 提交反馈操作响应时间 ≤ 1000ms（含附件上传）。

## 2.6 验收标准

- [ ] 县级管理员可新增任务，设定下发范围、填报期限、是否需要附件反馈。
- [ ] 县级管理员可保存任务为草稿，草稿可编辑、可下发、可删除。
- [ ] 任务下发后，接收方在任务列表中可查看该任务，反馈状态初始为"未反馈"。
- [ ] 接收方提交反馈后，反馈状态变为"已反馈"，不可修改。
- [ ] 若任务要求附件反馈，接收方提交时附件字段必填。
- [ ] 任务下发后至少一个接收方提交反馈，任务状态自动变为"进行中"。
- [ ] 所有接收方均已反馈，任务状态自动变为"已完成"。
- [ ] 下发方可手动标记任务完成。
- [ ] 超过填报期限未反馈的接收方自动标记为超期，任务列表展示超期 Tag。
- [ ] 接收方列表中未反馈且超期的行以浅红色背景高亮。
- [ ] 下发方可查看反馈详情，包含各接收方的反馈内容、附件、时间及超期情况。
- [ ] 已下发/进行中的任务可撤回，撤回后未反馈的接收方不再需要反馈。
- [ ] 见可交互 HTML 原型。

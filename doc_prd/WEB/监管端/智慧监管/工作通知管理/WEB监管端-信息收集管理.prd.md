## 3.2 目标与范围

**目标**：
1. 实现报送模板的创建、编辑、复用管理（模板库），支持灵活定义结构化字段。
2. 实现收集任务的下发、状态跟踪、撤回管理，与工作任务管理共用下发范围选择机制。
3. 填报方可根据模板动态渲染的表单填写结构化数据，支持保存草稿和提交。
4. 下发方可以表格形式汇总查看所有填报人提交的结构化数据，并支持导出 Excel。
5. 数字类型字段自动计算合计和平均值。

**非目标（Non-Goals）**：
- ❌ 不提供自由文本+附件形式的反馈（自由反馈由「工作任务管理」模块实现）。
- ❌ 不提供模板版本管理（修改模板直接覆盖，已下发的收集任务引用的是下发时的模板快照）。
- ❌ 不支持填报人提交后自行修改（如需修改须联系下发方退回）。
- ❌ 不提供 SQL 级别的字段值复杂查询（模板字段以 JSON 存储，汇总时后端解析 JSON 内存计算）。
- ❌ 短信通知功能仅定义开关，具体发送由后续技术方案确定。

### 3.4.1 功能流程逻辑

**报送模板管理逻辑**：

1. 模板字段定义以 JSON 格式存储在 `template_fields` 字段中。
2. JSON 结构：

```json
[
  {
    "fieldKey": "field_1",
    "fieldName": "本月生猪存栏数",
    "fieldType": "number",
    "required": true,
    "options": null,
    "sort": 1
  },
  {
    "fieldKey": "field_2",
    "fieldName": "养殖场类型",
    "fieldType": "select",
    "required": true,
    "options": ["规模化养殖场", "中小养殖户", "散养户"],
    "sort": 2
  }
]
```

3. 字段类型（`fieldType`）枚举值：`text` 文本输入、`number` 数字输入、`date` 日期选择、`select` 下拉选择、`textarea` 多行文本、`file` 附件上传（共6种，无其他）。
4. 字段类型为 `select` 时，`options` 数组必须提供且至少包含2个选项。
5. 模板删除限制：已被收集任务引用的模板不可删除，提示「该模板已被收集任务使用，无法删除」。

**收集任务状态流转**：

| 当前状态 | 触发动作 | 目标状态 | 触发条件 |
|---------|---------|---------|---------|
| - | 新增保存 | 草稿（`0`） | 填写表单后点击「保存」 |
| 草稿（`0`） | 点击「下发」 | 已下发（`1`） | 必填项校验通过 |
| 已下发（`1`） | 至少一个填报人提交数据 | 进行中（`2`） | 系统自动流转 |
| 已下发（`1`）/ 进行中（`2`） | 所有填报人均已提交 | 已完成（`3`） | 系统自动流转 |
| 已下发（`1`）/ 进行中（`2`） | 下发方点击「撤回」 | 已撤回（`4`） | 二次确认后流转 |

**下发逻辑规则**：
1. 点击「下发」时，系统自动在 `pig_work_collect_data` 表中为每个接收人生成一条记录（`fill_status = '0'`）。
2. 下发时将模板当前的 `template_fields` 快照存入收集任务（后续模板修改不影响已下发的任务）。
3. 下发范围逻辑与通知公告管理一致（全部/按机构/按人员）。
4. 下发时记录 `dispatch_time` 为当前服务器时间。

**填报逻辑规则**：
1. 填报界面根据模板 `template_fields` 动态渲染表单，每个字段按 `fieldType` 渲染对应控件。
2. 「保存草稿」：不做必填校验，`fill_status` 更新为 `'1'`（草稿），`form_data` 保存当前已填内容。
3. 「提交」：做完整的必填校验，`fill_status` 更新为 `'2'`（已提交），`submit_time` 记录为当前服务器时间。
4. 若提交时间晚于收集任务 `deadline`，`is_overdue` 自动标记为 `'1'`。
5. 提交后不可修改（如需修改须联系下发方退回）。
6. 提交前二次确认弹窗：「确认提交报送数据？提交后不可修改。」
7. 每次填报人提交后，系统检查是否所有填报人均已提交，若是则自动将收集任务状态流转为"已完成"。
8. 提交时若收集任务状态为"已下发"（无人提交过），系统同时将任务状态更新为"进行中"。

**数据汇总逻辑**：
1. 以表格形式展示汇总数据：表格列 = 模板定义的字段 + 固定列（填报人/机构/提交时间/是否超期），行 = 各填报人。
2. 数字类型字段在表格底部自动展示「合计」行和「平均值」行。
3. 未提交的填报人在汇总表中对应行数据列显示为 `-`（未填报状态）。

**撤回逻辑规则**：
1. 撤回前需二次确认弹窗：「确认撤回该收集任务？撤回后未填报的接收方将不再需要填报。」
2. 撤回后状态变为"已撤回"，仅可查看，不可编辑、不可再次下发。

**按钮展示逻辑（下发方列表）**：

| 收集任务状态 | 可见操作按钮 |
|------------|------------|
| 草稿（`0`） | 「编辑」「下发」「删除」 |
| 已下发（`1`）/ 进行中（`2`） | 「查看」「撤回」「数据汇总」 |
| 已完成（`3`） | 「查看」「数据汇总」 |
| 已撤回（`4`） | 「查看」 |

### 3.4.3 界面交互逻辑

**页面布局**：

信息收集管理页面根据当前登录用户角色展示不同视角：
- **下发方视角**（`county_admin`、`county_staff`）：Tab 切换「收集任务」和「模板管理」两个子页面
- **接收方视角**（`town_gov_staff`、`town_vet_station`、`ent_admin`）：展示「我收到的收集任务」列表

**Tab 切换行为**：切换 Tab 时立即加载对应子页面数据，无需额外点击查询按钮。切换过程中有 loading 遮罩。当前激活 Tab 有明显选中态样式。

---

- 顶部操作栏：「新增模板」按钮

**新增/编辑收集任务弹窗**：

弹窗标题：新增时为「新增收集任务」，编辑时为「编辑收集任务」。宽度 720px。

| 下发范围值-按机构 | 部门树多选（scope_type 为 `1` 时显示） | 条件必填 | scope_type 为 `1` 时不能为空 | 「请选择目标机构」 |
| 下发范围值-按人员 | 用户列表多选穿梭框（scope_type 为 `2` 时显示） | 条件必填 | scope_type 为 `2` 时不能为空 | 「请选择目标人员」 |

- 编辑模式下仅草稿状态可进入，所有字段可修改
- 自动回显字段（只读）：无

**接收方收集任务列表**：

- 筛选区域：任务名称（输入框，模糊搜索）、填报状态（下拉：全部/未填报/草稿/已提交）、「搜索」「重置」按钮
- 列表字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 任务名称 | collect_name | 文本，超长截断显示，悬停 Tooltip 展示全文 |
| 下发单位 | create_by 关联 sys_dept | 文本 |
| 下发人 | create_by 关联 sys_user.nick_name | 文本 |
| 填报期限 | deadline | 格式 `yyyy-MM-dd HH:mm` |
| 我的填报状态 | fill_status | Tag 标签：未填报（灰色）、草稿（蓝色）、已提交（绿色） |
| 是否超期 | 计算判定 | 条件显示：未提交且超过 deadline 时展示红色 Tag「超期」 |
| 操作 | - | 未填报/草稿→「填报」；已提交→「查看」 |

- 行样式规则：未提交且已超期的行以浅红色背景（`#FFF0F0`）高亮
- 分页：每页默认10条，支持选择 10/20/50 条每页

**填报表单页面**：

- 页面顶部：任务名称、任务说明、填报期限
- 表单区域：根据模板 `template_fields`（使用下发时的 `template_snapshot`）动态渲染，每个字段按 `fieldType` 渲染对应控件：
  - `text`：文本输入框
  - `number`：数字输入框（支持小数，最大值 99999999.99）
  - `date`：日期选择器
  - `select`：下拉选择器（选项来自模板配置的 `options`）
  - `textarea`：多行文本域
  - `file`：文件上传组件
- 必填字段标 `*` 号
- 底部按钮：「保存草稿」「提交」「返回」
  - 「保存草稿」：不做必填校验，保存当前已填内容
  - 「提交」：做完整必填校验，提交前二次确认
  - 「返回」：返回列表页

**数据汇总页面**（下发方查看）：

- 页面顶部：任务名称、填报进度（已提交X/共X，进度条）
- 操作按钮：「导出Excel」
- 汇总表格：
  - 固定列：序号、填报人姓名、所属机构、填报状态、提交时间、是否超期
  - 动态列：模板定义的每个字段各占一列
  - 底部行：数字类型字段自动展示「合计」行和「平均值」行
  - 未提交的填报人数据列显示 `-`

**校验时机**：
- 表单字段在失焦（blur）时即时校验单个字段。
- 点击「保存草稿」时不做必填校验。
- 点击「下发」「提交」「确定」时对全部字段做整体校验，校验不通过时阻断操作，错误提示紧邻对应字段展示。

### 3.4.4 接口路径定义

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 模板列表 | GET | `/admin/collect-templates/list` | pageNum、pageSize、templateName（模糊）、status（下拉） | 分页列表+总数 | — |
| 模板详情 | GET | `/admin/collect-templates/{templateId}` | templateId（路径参数） | 模板完整信息含字段定义 | — |
| 新增模板 | POST | `/admin/collect-templates` | templateName、templateFields（JSON）、status | 操作结果 + templateId | — |
| 修改模板 | PUT | `/admin/collect-templates` | templateId + 可修改字段 | 操作结果 | — |
| 删除模板 | DELETE | `/admin/collect-templates/{templateIds}` | templateIds（路径参数，逗号分隔） | 操作结果 | 未被引用时可删除，支持批量 |
| 模板下拉选项 | GET | `/admin/collect-templates/options` | - | id+name 列表，不分页 | 仅返回状态为"正常"的模板 |
| 收集任务列表-下发方 | GET | `/admin/collects/list` | pageNum、pageSize、collectName（模糊）、status（下拉）、beginDispatchTime、endDispatchTime | 分页列表+总数，每行含填报进度统计 | 仅返回当前用户下发的任务 |
| 收集任务列表-接收方 | GET | `/admin/collects/received/list` | pageNum、pageSize、collectName（模糊）、fillStatus（下拉） | 分页列表+总数 | 仅返回已下发/进行中/已完成状态且发给当前用户的任务 |
| 收集任务详情 | GET | `/admin/collects/{collectId}` | collectId（路径参数） | 收集任务完整信息含模板快照 | — |
| 新增收集任务 | POST | `/admin/collects` | 见 3.4.2 字段定义（除系统自动字段外） | 操作结果 + collectId | — |
| 修改收集任务 | PUT | `/admin/collects` | collectId + 可修改字段 | 操作结果 | 仅草稿状态可修改 |
| 下发收集任务 | PUT | `/admin/collects/dispatch/{collectId}` | collectId（路径参数） | 操作结果 | 草稿→已下发，自动生成接收人填报记录并固化模板快照 |
| 撤回收集任务 | PUT | `/admin/collects/revoke/{collectId}` | collectId（路径参数） | 操作结果 | 已下发/进行中→已撤回 |
| 删除收集任务 | DELETE | `/admin/collects/{collectIds}` | collectIds（路径参数，逗号分隔） | 操作结果 | 仅草稿可删除，支持批量 |
| 保存/提交报送数据 | POST | `/admin/collects/data/submit` | collectId、formData（JSON）、fillStatus（`1` 草稿/`2` 提交） | 操作结果 | 填报人保存草稿或提交 |
| 数据汇总查看 | GET | `/admin/collects/data/summary/{collectId}` | collectId（路径参数） | 汇总表格数据（含填报人信息+各字段值）+ 数字字段合计/平均值 | 下发方查看 |
| 导出汇总数据 | POST | `/admin/collects/data/export/{collectId}` | collectId（路径参数） | Excel 文件流 | — |

## 3.5 非功能需求

**安全与权限**：

| 权限标识 | 说明 | 拥有角色 |
|---------|------|---------|
| `admin:collect:list` | 查看下发方收集任务列表 | `county_admin`、`county_staff` |
| `admin:collect:add` | 新增收集任务 | `county_admin`、`county_staff` |
| `admin:collect:edit` | 编辑收集任务 | `county_admin`、`county_staff` |
| `admin:collect:dispatch` | 下发收集任务 | `county_admin`、`county_staff` |
| `admin:collect:revoke` | 撤回收集任务 | `county_admin`、`county_staff` |
| `admin:collect:remove` | 删除收集任务 | `county_admin` |
| `admin:collect:template` | 模板管理 | `county_admin`、`county_staff` |
| `admin:collect:received` | 接收查看收集任务 | `town_gov_staff`、`town_vet_station`、`ent_admin` |
| `admin:collect:fill` | 填报数据 | `town_gov_staff`、`town_vet_station`、`ent_admin` |
| `admin:collect:summary` | 查看汇总数据 | `county_admin`、`county_staff` |
| `admin:collect:export` | 导出汇总数据 | `county_admin`、`county_staff` |

**数据权限**：
- 县级角色（`county_admin`、`county_staff`）可操作全部收集任务和模板。
- 接收方角色（`town_gov_staff`、`town_vet_station`、`ent_admin`）只能查看发给自己（或自己所属机构）的收集任务，只能填报自己的数据。

**性能要求**：
- 收集任务列表查询响应时间 ≤ 500ms（数据量 ≤ 10000 条）。
- 数据汇总查询响应时间 ≤ 2000ms（填报人 ≤ 500 人，模板字段 ≤ 20 个）。
- 汇总数据导出响应时间 ≤ 5000ms。

## 3.6 验收标准

- [ ] 县级角色可新增报送模板，定义字段名称、类型、是否必填、下拉选项、排序。
- [ ] 模板支持编辑和删除，已被收集任务引用的模板不可删除。
- [ ] 县级角色可新增收集任务，选择报送模板、下发范围、填报期限。
- [ ] 收集任务下发后，模板字段快照被固化，后续修改模板不影响已下发任务。
- [ ] 接收方可根据模板定义的字段动态渲染的表单填写结构化数据。
- [ ] 接收方支持保存草稿（不做必填校验）和提交（做完整必填校验）。
- [ ] 提交后不可修改。
- [ ] 下发方可查看数据汇总，以表格形式展示各填报人的结构化数据。
- [ ] 数字类型字段在汇总表底部自动展示合计和平均值。
- [ ] 汇总数据支持导出 Excel。
- [ ] 超过填报期限未提交的填报人自动标记为超期。
- [ ] 接收方列表中未提交且超期的行以浅红色背景高亮。
- [ ] Tab 切换"收集任务"和"模板管理"时立即加载对应数据，无需额外点击查询按钮。
- [ ] 见可交互 HTML 原型。

## 4.1 基本信息

- **功能名称**：情况总结看板
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 权限管理：复用现有角色权限体系，新增情况总结看板权限标识
  - 通知公告管理：从 `pig_work_notice` 和 `pig_work_notice_read` 表统计通知发布和阅读数据
  - 工作任务管理：从 `pig_work_task` 和 `pig_work_task_feedback` 表统计任务下发和反馈数据
  - 信息收集管理：从 `pig_work_collect` 和 `pig_work_collect_data` 表统计收集下发和填报数据
  - 部门管理：`sys_dept` 表提供机构名称数据，用于机构响应排行
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_spec/现有数据库说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要需求 |
|---------|---------------------|---------|---------|
| 县级管理员 | `county_admin` | 查看全局工作执行概况 | 掌握通知阅读率、任务反馈率、收集填报率、超期情况 |
| 县级业务人员 | `county_staff` | 查看全局工作执行概况 | 掌握通知阅读率、任务反馈率、收集填报率、超期情况 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1 角色总览。
>
> 乡镇和企业角色无需此看板（他们关注的是自己的待办任务，非全局概况）。

## 4.2 目标与范围

**目标**：
1. 以看板形式向县级角色展示工作通知、工作任务、信息收集三个模块的总体执行概况。
2. 提供任务执行趋势图，展示近6个月的任务下发/完成/超期趋势。
3. 提供各机构响应排行表，量化各乡镇/企业的任务响应效率。
4. 提供超期预警列表，集中展示当前所有超期未完成的任务和收集任务。

**非目标（Non-Goals）**：
- ❌ 不提供大屏展示模式（大屏展示由后续决策分析大屏模块实现）。
- ❌ 不提供导出看板数据功能。
- ❌ 不提供自定义看板布局或指标配置功能。
- ❌ 不提供实时刷新（页面加载时获取数据，用户手动刷新）。

## 4.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 总体统计卡片 | P0 | 展示通知/任务/收集/超期四类关键指标 |
| 任务执行趋势图 | P0 | 折线图展示近6个月趋势 |
| 各机构响应排行 | P0 | 表格展示各乡镇/企业响应效率 |
| 超期预警列表 | P0 | 展示当前所有超期未完成的任务和收集 |

**关键流程**：

```
县级角色进入「情况总结看板」页面
    → 页面加载时并行请求 4 个接口
    → 渲染总体统计卡片 + 任务执行趋势图 + 机构响应排行 + 超期预警列表
    → 用户可切换趋势图的任务类型筛选
```

### 4.4.1 功能流程逻辑

**总体统计卡片指标定义**：

| 卡片名称 | 指标项 | 计算逻辑 |
|---------|-------|---------|
| 通知公告 | 本月发布数 | `pig_work_notice` 中 `status = '1'`（已发布）且 `publish_time` 在本月范围内的记录数 |
| 通知公告 | 总阅读率 | 本月发布的通知中，`pig_work_notice_read` 表 `is_read = '1'` 的记录数 / 总接收人记录数 × 100%，保留1位小数 |
| 工作任务 | 本月下发数 | `pig_work_task` 中 `status IN ('1','2','3')` 且 `dispatch_time` 在本月范围内的记录数 |
| 工作任务 | 进行中数 | `pig_work_task` 中 `status = '2'` 的记录数 |
| 工作任务 | 已完成数 | `pig_work_task` 中 `status = '3'` 且 `dispatch_time` 在本月范围内的记录数 |
| 工作任务 | 总反馈率 | 本月下发的任务中，`pig_work_task_feedback` 表 `feedback_status = '1'` 的记录数 / 总接收人记录数 × 100%，保留1位小数 |
| 信息收集 | 本月下发数 | `pig_work_collect` 中 `status IN ('1','2','3')` 且 `dispatch_time` 在本月范围内的记录数 |
| 信息收集 | 进行中数 | `pig_work_collect` 中 `status = '2'` 的记录数 |
| 信息收集 | 已完成数 | `pig_work_collect` 中 `status = '3'` 且 `dispatch_time` 在本月范围内的记录数 |
| 信息收集 | 总填报率 | 本月下发的收集任务中，`pig_work_collect_data` 表 `fill_status = '2'` 的记录数 / 总填报人记录数 × 100%，保留1位小数 |
| 超期统计 | 超期未反馈任务数 | `pig_work_task` 中 `status IN ('1','2')` 且 `deadline < 当前时间` 且存在至少一条 `feedback_status = '0'` 的反馈记录的任务数 |
| 超期统计 | 超期未填报收集数 | `pig_work_collect` 中 `status IN ('1','2')` 且 `deadline < 当前时间` 且存在至少一条 `fill_status IN ('0','1')` 的填报记录的收集数 |

**任务执行趋势逻辑**：
1. 默认展示近6个月（含当月）的数据。
2. X 轴：月份（如 2025-10、2025-11、2025-12、2026-01、2026-02、2026-03）。
3. Y 轴：数量。
4. 三条折线：下发数、完成数、超期数。
5. 下发数：该月内 `dispatch_time` 的任务数。
6. 完成数：该月内状态流转为"已完成"的任务数（以 `update_time` 为准，`status = '3'`）。
7. 超期数：该月内 `deadline` 到期且有未反馈接收方的任务数。
8. 支持按任务类型筛选（下拉：全部/日常巡查/专项检查/数据报送/整改通知/其他），切换后折线图立即刷新。

**各机构响应排行逻辑**：
1. 查询所有乡镇/企业（`sys_dept` 中非县级部门），统计其下所有用户的任务响应情况。
2. 统计维度：

| 指标 | 计算逻辑 |
|------|---------|
| 接收任务总数 | 该机构下所有用户在 `pig_work_task_feedback` 表中的记录数（仅统计任务状态非草稿、非已撤回的） |
| 已反馈数 | 该机构下所有用户中 `feedback_status = '1'` 的记录数 |
| 超期数 | 该机构下所有用户中 `is_overdue = '1'` 的记录数 |
| 平均响应时长 | 已反馈记录的 `feedback_time - 任务dispatch_time` 的平均值，单位小时，保留1位小数 |
| 反馈率 | 已反馈数 / 接收任务总数 × 100%，保留1位小数 |

3. 默认按反馈率降序排列。
4. 反馈率低于 50% 的行以浅红色背景（`#FFF0F0`）标红。

**超期预警列表逻辑**：
1. 查询当前所有超期未完成的任务和收集任务。
2. 工作任务超期条件：`pig_work_task` 中 `status IN ('1','2')` 且 `deadline < 当前时间`。
3. 信息收集超期条件：`pig_work_collect` 中 `status IN ('1','2')` 且 `deadline < 当前时间`。
4. 超期天数 = （当前日期 - deadline 日期）的天数差，向上取整。
5. 未完成人数 = 对应反馈/填报记录表中 `feedback_status = '0'`（任务）或 `fill_status IN ('0','1')`（收集）的记录数。
6. 默认按超期天数倒序排列。

### 4.4.2 数据模型与字段定义

本功能不新建业务表。所有数据来源于以下已有表（由通知公告管理、工作任务管理、信息收集管理模块定义）：

| 数据来源表 | 定义位置 | 用途 |
|-----------|---------|------|
| `pig_work_notice` | 通知公告管理 PRD §1.4.2 | 通知发布统计 |
| `pig_work_notice_read` | 通知公告管理 PRD §1.4.2 | 通知阅读率统计 |
| `pig_work_task` | 工作任务管理 PRD §2.4.2 | 任务下发/完成/超期统计 |
| `pig_work_task_feedback` | 工作任务管理 PRD §2.4.2 | 任务反馈率/响应排行统计 |
| `pig_work_collect` | 信息收集管理 PRD §3.4.2 | 收集下发/完成/超期统计 |
| `pig_work_collect_data` | 信息收集管理 PRD §3.4.2 | 填报率统计 |
| `sys_dept` | 复用现有表，见现有数据库说明.spec.md §2.1 | 机构名称 |

### 4.4.3 界面交互逻辑

**页面布局**：

页面采用看板式布局，从上到下依次为：

1. **总体统计卡片区域**（页面顶部，一行 4 个卡片）
2. **任务执行趋势图区域**（中部左侧，占 60% 宽度）
3. **各机构响应排行区域**（中部右侧，占 40% 宽度）
4. **超期预警列表区域**（页面底部，全宽）

---

**总体统计卡片**：

4 个统计卡片水平排列，每个卡片包含：
- 卡片标题（如"通知公告"、"工作任务"、"信息收集"、"超期统计"）
- 主要指标数字（大字号，醒目颜色）
- 次要指标文本（小字号，灰色）

| 卡片 | 主要指标 | 次要指标 | 卡片颜色 |
|------|---------|---------|---------|
| 通知公告 | 本月发布 X 条 | 总阅读率 XX.X% | 蓝色主题 |
| 工作任务 | 本月下发 X 条 | 进行中 X 条 · 已完成 X 条 · 反馈率 XX.X% | 绿色主题 |
| 信息收集 | 本月下发 X 条 | 进行中 X 条 · 已完成 X 条 · 填报率 XX.X% | 紫色主题 |
| 超期统计 | 超期任务 X 条 | 超期收集 X 条 | 红色主题 |

**任务执行趋势图**：

- 区域标题：「任务执行趋势」
- 右上角筛选：任务类型下拉（全部/日常巡查/专项检查/数据报送/整改通知/其他），切换后图表立即刷新，无需点击查询按钮
- 图表类型：折线图（推荐使用 ECharts）
- X 轴：近6个月的月份
- Y 轴：数量
- 三条折线及颜色：
  - 下发数（蓝色）
  - 完成数（绿色）
  - 超期数（红色）
- 鼠标悬停展示 Tooltip（月份 + 各指标值）
- 图表区域有 loading 状态

**各机构响应排行**：

- 区域标题：「各机构响应排行」
- 表格字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 排名 | 序号 | 数字，前3名用奖杯图标标识 |
| 机构名称 | sys_dept.dept_name | 文本 |
| 接收任务总数 | 统计计算 | 数字 |
| 已反馈数 | 统计计算 | 数字 |
| 超期数 | 统计计算 | 数字，大于0时红色文本 |
| 平均响应时长 | 统计计算 | 文本，如"4.5小时" |
| 反馈率 | 统计计算 | 百分比文本 + 进度条 |

- 行样式规则：反馈率低于 50% 的行以浅红色背景（`#FFF0F0`）标红
- 默认按反馈率降序排列
- 不分页，展示所有机构（预计不超过 50 个）

---

**超期预警列表**：

- 区域标题：「超期预警」
- 表格字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 任务/收集名称 | task_name 或 collect_name | 文本，超长截断显示 |
| 类型 | 来源判断 | Tag 标签：工作任务（蓝色）、信息收集（紫色） |
| 下发时间 | dispatch_time | 格式 `yyyy-MM-dd HH:mm` |
| 截止时间 | deadline | 格式 `yyyy-MM-dd HH:mm` |
| 超期天数 | 计算 | 数字，红色文本 |
| 未完成人数/总人数 | 统计计算 | 文本，如"3/10" |

- 默认按超期天数倒序排列
- 分页：每页默认10条，支持选择 10/20/50 条每页
- 点击行可跳转到对应的任务/收集详情页

**页面加载状态**：
- 页面进入时，4 个区域并行加载数据。
- 各区域独立展示 loading 骨架屏，某个区域加载完毕即渲染，不等待其他区域。
- 如接口请求失败，对应区域展示「加载失败，请重试」提示。

### 4.4.4 接口路径定义

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 总体统计 | GET | `/admin/work-dashboard/stats` | - | 通知（本月发布数、总阅读率）、任务（本月下发数、进行中数、已完成数、总反馈率）、收集（本月下发数、进行中数、已完成数、总填报率）、超期（超期任务数、超期收集数） | — |

| 机构响应排行 | GET | `/admin/work-dashboard/ranking` | - | 机构列表（机构名称、接收任务总数、已反馈数、超期数、平均响应时长、反馈率），按反馈率降序 | — |
| 超期预警列表 | GET | `/admin/work-dashboard/overdue` | pageNum、pageSize | 分页列表（名称、类型、下发时间、截止时间、超期天数、未完成人数/总人数） | 按超期天数倒序 |

## 4.5 非功能需求

**安全与权限**：

| 权限标识 | 说明 | 拥有角色 |
|---------|------|---------|
| `admin:work:dashboard` | 查看情况总结看板 | `county_admin`、`county_staff` |

**数据权限**：
- 仅县级角色（`county_admin`、`county_staff`）可访问此看板，展示全县数据。
- 乡镇和企业角色无权访问此页面。

**性能要求**：
- 总体统计接口响应时间 ≤ 1000ms。
- 执行趋势接口响应时间 ≤ 1000ms。
- 机构响应排行接口响应时间 ≤ 2000ms（机构数 ≤ 50）。
- 超期预警列表接口响应时间 ≤ 500ms。

**兼容性**：
- 统计图表推荐使用 ECharts，与后续决策分析和大屏展示保持技术栈一致。

## 1.1 基本信息

- **功能名称**：通知公告管理
- **关联现有模块/功能**：
  - 用户认证：复用现有 `/login`、`/getInfo`、`/getRouters` 接口与 JWT 机制
  - 权限管理：复用现有角色权限体系，新增通知公告相关权限标识
  - 部门树：`sys_dept` 表提供行政区划数据，用于"按机构下发"时选择目标乡镇/企业
  - 用户管理：`sys_user` 表提供用户列表，用于"按人员下发"时选择目标人员
  - 字典管理：复用 `/system/dict/data/type/{dictType}` 获取通知类型、紧急程度等下拉数据
  - 系统通知公告：现有 `sys_notice` 表与 `/system/notice` 接口为若依框架自带的简单通知功能，本模块独立新建 `pig_work_notice` 系列表，不复用 `sys_notice`（原因：业务需求包含发布范围选择、阅读追踪、短信通知等功能，远超系统通知的能力）
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_spec/现有数据库说明.spec.md`
- **目标用户/场景**：

## 1.2 目标与范围

**目标**：
1. 实现县级监管部门向下级单位（乡镇政府、畜牧兽医站）和养殖企业发布通知公告的完整功能。
2. 支持按机构、按人员或全部三种发布范围选择方式。
3. 支持通知状态流转：草稿→已发布→已撤回。
4. 支持阅读状态追踪，发布方可查看每条通知的阅读详情及阅读率。
5. 接收方列表区分已读/未读，未读通知以浅蓝色背景高亮，紧急通知以浅红色背景高亮。

**非目标（Non-Goals）**：
- ❌ 不复用若依框架自带的 `sys_notice` 通知公告功能，独立新建业务模块。
- ❌ 短信通知功能仅定义"是否短信通知"开关，具体短信发送对接由后续技术方案确定，本 PRD 不定义短信 API 细节。
- ❌ 不提供通知模板功能（通知内容由发布人手动编写）。
- ❌ 不提供通知定时发布功能（仅支持即时发布）。

## 1.3 现状与复用

**现状简述**：
- 若依框架自带 `sys_notice` 表和 `/system/notice` 相关接口，仅实现简单的通知标题+内容+类型（通知/公告两种），无发布范围选择、无阅读追踪、无紧急程度、无附件、无短信通知功能。
- 系统已有部门树（`sys_dept`）和用户列表（`sys_user`）功能，可直接复用于"按机构/按人员下发"的对象选择场景。
- 字典管理已有完善的增删改查接口（`/system/dict/data/type/{dictType}`），通知类型和紧急程度可通过字典管理配置。

## 1.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 通知发布（新增/编辑/发布） | P0 | 县级角色创建通知，设定发布范围，保存草稿或直接发布 |
| 通知列表-发布方视角 | P0 | 展示本人发布的所有通知，支持筛选与操作 |
| 通知列表-接收方视角 | P0 | 展示接收到的已发布通知，区分已读/未读 |
| 通知详情查看 | P0 | 展示完整通知内容，进入详情自动标记已读 |
| 通知撤回 | P0 | 已发布的通知可撤回 |
| 阅读详情查看 | P1 | 发布方查看接收人的阅读状态与阅读率 |
| 未读通知数量（铃铛） | P1 | 页面右上角铃铛图标展示未读数 |
| 置顶通知 | P1 | 支持置顶及置顶截止时间 |
| 短信通知开关 | P2 | 发布时可选是否短信通知接收人（后期对接短信服务） |

**关键流程**：

```
发布方（县级角色）操作流程：
新增通知 → 填写表单 → 选择发布范围 → [保存草稿] / [直接发布]
                                              ↓
                                         草稿状态
                                              ↓
                                    [编辑] / [发布] / [删除]
                                              ↓ (发布)
                                         已发布状态
                                              ↓
                                    [查看] / [撤回] / [阅读详情]
                                              ↓ (撤回)
                                         已撤回状态
                                              ↓
                                    [查看] / [删除]

接收方（乡镇/企业角色）操作流程：
通知列表（仅显示已发布通知）→ 点击查看 → 通知详情（自动标记已读）
```

### 1.4.1 功能流程逻辑

**通知状态流转**：

| 当前状态 | 触发动作 | 目标状态 | 触发条件 |
|---------|---------|---------|---------|
| - | 新增保存 | 草稿（`0`） | 填写表单后点击「保存」 |
| 草稿（`0`） | 点击「发布」 | 已发布（`1`） | 必填项校验通过 |
| 已发布（`1`） | 点击「撤回」 | 已撤回（`2`） | 二次确认弹窗确认 |

**发布逻辑规则**：
1. 点击「发布」时，系统自动在 `pig_work_notice_read` 表中为每个接收人生成一条未读记录（`is_read = '0'`）。
2. 发布范围为"全部"时，系统查询所有下级机构（乡镇政府、畜牧兽医站）和所有养殖企业的管理员，生成对应未读记录。
3. 发布范围为"按机构"时，系统查询所勾选部门下的所有用户，生成对应未读记录。
4. 发布范围为"按人员"时，仅为所选用户生成未读记录。
5. 发布时记录 `publish_time` 为当前服务器时间。

**撤回逻辑规则**：
1. 撤回后，该通知在接收方列表中不再显示。
2. 撤回前需二次确认弹窗：「确认撤回该通知？撤回后接收方将无法查看此通知。」
3. 撤回后通知状态变为"已撤回"，可查看、可删除，不可编辑、不可再次发布。

**阅读标记逻辑**：
1. 接收方进入通知详情页时，系统自动将 `pig_work_notice_read` 表中对应记录的 `is_read` 更新为 `'1'`，`read_time` 更新为当前服务器时间。
2. 已读状态不可逆（无法标记回未读）。

**置顶逻辑规则**：
1. 置顶通知在接收方列表中始终排在最前方，多条置顶通知按发布时间倒序排列。
2. 超过置顶截止时间后，系统自动取消置顶（后端定时任务或查询时实时判断）。

**按钮展示逻辑（发布方列表）**：

| 通知状态 | 可见操作按钮 |
|---------|------------|
| 草稿（`0`） | 「编辑」「发布」「删除」 |
| 已发布（`1`） | 「查看」「撤回」「阅读详情」 |
| 已撤回（`2`） | 「查看」「删除」 |

### 1.4.3 界面交互逻辑

**页面布局**：

通知公告管理页面根据当前登录用户角色展示不同视角：
- **发布方视角**（`county_admin`、`county_staff`）：展示「我发布的通知」列表 + 新增按钮
- **接收方视角**（`town_gov_staff`、`town_vet_station`、`ent_admin`）：展示「我收到的通知」列表

**发布方通知列表**：

- 顶部操作栏：「新增」按钮（主色调实心按钮）
- 筛选区域：通知标题（输入框，模糊搜索）、通知类型（下拉，字典 `pig_work_notice_type`）、状态（下拉：全部/草稿/已发布/已撤回）、发布时间范围（起止日期选择器）、「搜索」「重置」按钮
- 列表字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 通知标题 | notice_title | 文本，超长截断显示，悬停 Tooltip 展示全文 |
| 通知类型 | notice_type | Tag 标签，颜色按类型区分 |
| 紧急程度 | urgency_level | Tag 标签：普通（灰色）、重要（橙色）、紧急（红色） |
| 发布范围摘要 | scope_type + scope_value | 文本："全部" / "X个机构" / "X人" |
| 阅读情况 | 统计计算 | 文本："已读X人/共X人" |
| 状态 | status | Tag 标签：草稿（灰色）、已发布（绿色）、已撤回（红色） |
| 发布时间 | publish_time | 格式 `yyyy-MM-dd HH:mm` |
| 操作 | - | 按钮组，按状态动态展示（见 1.4.1 按钮展示逻辑） |

- 分页：每页默认10条，支持选择 10/20/50 条每页

**接收方通知列表**：

- 筛选区域：通知标题（输入框，模糊搜索）、通知类型（下拉，字典 `pig_work_notice_type`）、是否已读（下拉：全部/已读/未读）、发布时间范围（起止日期选择器）、「搜索」「重置」按钮
- 列表字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 通知标题 | notice_title | 文本，超长截断显示，悬停 Tooltip 展示全文 |
| 通知类型 | notice_type | Tag 标签，颜色按类型区分 |
| 紧急程度 | urgency_level | Tag 标签：普通（灰色）、重要（橙色）、紧急（红色） |
| 发布单位 | create_by 关联 sys_dept | 文本 |
| 发布人 | create_by 关联 sys_user.nick_name | 文本 |
| 发布时间 | publish_time | 格式 `yyyy-MM-dd HH:mm` |
| 是否已读 | is_read | Tag 标签：已读（绿色）、未读（蓝色） |

- 行样式规则：
  - 未读通知行（`is_read = '0'`）以浅蓝色背景（`#EBF5FF`）高亮
  - 紧急通知行（`urgency_level = '2'`）以浅红色背景（`#FFF0F0`）高亮
  - 当同时满足未读+紧急时，紧急优先（浅红色背景）
- 置顶通知始终排在列表最前方，带置顶图标（📌）
- 分页：每页默认10条，支持选择 10/20/50 条每页
- 点击行或标题进入通知详情

**新增/编辑通知弹窗（对话框）**：

弹窗标题：新增时为「新增通知」，编辑时为「编辑通知」。宽度 720px。

|---------|---------|------|---------|---------|
| 通知标题 | 文本输入框 | 是 | 最大100个字符，不能为空 | 「请输入通知标题」/「通知标题不能超过100个字符」 |
| 通知类型 | 下拉选择器（字典 `pig_work_notice_type`） | 是 | 不能为空 | 「请选择通知类型」 |
| 紧急程度 | 下拉选择器 | 是 | 不能为空 | 「请选择紧急程度」 |
| 通知内容 | 富文本编辑器 | 是 | 不能为空 | 「请输入通知内容」 |
| 附件 | 多文件上传组件 | 否 | 单文件最大20MB，总计最大100MB | 「单个文件不能超过20MB」/「附件总大小不能超过100MB」 |
| 发布范围类型 | 单选按钮组（全部/按机构/按人员） | 是 | 不能为空 | 「请选择发布范围」 |
| 发布范围值-按机构 | 部门树多选（scope_type 为 `1` 时显示） | 条件必填 | scope_type 为 `1` 时不能为空 | 「请选择目标机构」 |
| 发布范围值-按人员 | 用户列表多选穿梭框（scope_type 为 `2` 时显示） | 条件必填 | scope_type 为 `2` 时不能为空 | 「请选择目标人员」 |
| 是否短信通知 | 开关 | 是 | - | - |
| 是否置顶 | 开关 | 是 | - | - |
| 置顶截止时间 | 日期时间选择器（is_top 为 `1` 时显示） | 条件必填 | is_top 为 `1` 时不能为空，不能早于当前时间 | 「请选择置顶截止时间」/「置顶截止时间不能早于当前时间」 |

- 底部按钮：「保存草稿」「发布」「取消」
  - 「保存草稿」：校验通过后保存为草稿状态
  - 「发布」：校验通过后保存并直接发布
  - 「取消」：关闭弹窗，未保存的内容丢失（需二次确认：「确认关闭？未保存的内容将丢失。」）
- 编辑模式下仅草稿状态可进入，所有字段可修改
- 自动回显字段（只读）：无（新增/编辑表单无系统自动生成字段需展示）

**通知详情页面**：

- 页面顶部展示：通知标题（大字号）、通知类型（Tag）、紧急程度（Tag）
- 基本信息区域：发布单位、发布人、发布时间
- 正文区域：富文本渲染通知内容
- 附件区域：附件列表，每项显示文件名+文件大小+「下载」按钮
- 底部按钮：「返回」

**阅读详情弹窗**：

- 弹窗标题：「阅读详情 - {通知标题}」。宽度 680px。
- 顶部统计：已读人数/总人数，阅读率百分比（进度条展示）
- 列表字段：

| 列名 | 数据来源 | 展示方式 |
|-----|---------|---------|
| 接收人姓名 | sys_user.nick_name | 文本 |
| 所属机构 | sys_dept.dept_name | 文本 |
| 阅读状态 | is_read | Tag 标签：已读（绿色）、未读（灰色） |
| 阅读时间 | read_time | 格式 `yyyy-MM-dd HH:mm`，未读时显示 `-` |

**校验时机**：
- 表单字段在失焦（blur）时即时校验单个字段。
- 点击「保存草稿」或「发布」时对全部字段做整体校验，校验不通过时阻断操作，错误提示紧邻对应字段展示。

### 1.4.4 接口路径定义

| 接口名称 | HTTP 方法 | 路径 | 请求参数摘要 | 响应数据摘要 | 备注 |
|----------|-----------|------|-------------|-------------|------|
| 通知列表-发布方 | GET | `/admin/notices/list` | pageNum、pageSize、noticeTitle（模糊）、noticeType（下拉）、status（下拉）、beginPublishTime、endPublishTime | 分页列表+总数，每行含已读/总人数统计 | 仅返回当前用户发布的通知 |
| 通知列表-接收方 | GET | `/admin/notices/received/list` | pageNum、pageSize、noticeTitle（模糊）、noticeType（下拉）、isRead（下拉）、beginPublishTime、endPublishTime | 分页列表+总数 | 仅返回已发布状态且发给当前用户的通知 |
| 通知详情 | GET | `/admin/notices/{noticeId}` | noticeId（路径参数） | 通知完整信息 | 接收方访问时自动标记已读 |
| 新增通知 | POST | `/admin/notices` | 见 1.4.2 字段定义（除系统自动字段外） | 操作结果 + noticeId | — |
| 修改通知 | PUT | `/admin/notices` | noticeId + 可修改字段 | 操作结果 | 仅草稿状态可修改 |
| 发布通知 | PUT | `/admin/notices/publish/{noticeId}` | noticeId（路径参数） | 操作结果 | 草稿→已发布，自动生成接收人未读记录 |
| 撤回通知 | PUT | `/admin/notices/revoke/{noticeId}` | noticeId（路径参数） | 操作结果 | 已发布→已撤回 |
| 删除通知 | DELETE | `/admin/notices/{noticeIds}` | noticeIds（路径参数，逗号分隔） | 操作结果 | 仅草稿/已撤回可删除，支持批量 |
| 阅读详情 | GET | `/admin/notices/read-detail/{noticeId}` | noticeId（路径参数） | 接收人列表（姓名、机构、阅读状态、阅读时间）+ 统计 | 发布方查看 |
| 未读通知数量 | GET | `/admin/notices/unread/count` | - | unreadCount（整数） | 用于页面铃铛图标 |

## 1.5 非功能需求

**安全与权限**：

| 权限标识 | 说明 | 拥有角色 |
|---------|------|---------|
| `admin:notice:list` | 查看发布方通知列表 | `county_admin`、`county_staff` |
| `admin:notice:add` | 新增通知 | `county_admin`、`county_staff` |
| `admin:notice:edit` | 编辑通知 | `county_admin`、`county_staff` |
| `admin:notice:publish` | 发布通知 | `county_admin`、`county_staff` |
| `admin:notice:revoke` | 撤回通知 | `county_admin`、`county_staff` |
| `admin:notice:remove` | 删除通知 | `county_admin` |
| `admin:notice:received` | 接收查看通知 | `town_gov_staff`、`town_vet_station`、`ent_admin` |
| `admin:notice:read-detail` | 查看阅读详情 | `county_admin`、`county_staff` |

**数据权限**：
- 县级角色（`county_admin`、`county_staff`）可操作全部通知。
- 接收方角色（`town_gov_staff`、`town_vet_station`、`ent_admin`）只能查看发给自己（或自己所属机构）的通知。

**性能要求**：
- 通知列表查询响应时间 ≤ 500ms（数据量 ≤ 10000 条）。
- 未读通知数量接口响应时间 ≤ 200ms（频繁轮询场景）。

## 1.6 验收标准

- [ ] 县级管理员可新增通知并选择按机构/按人员/全部三种发布范围。
- [ ] 县级管理员可保存通知为草稿，草稿可编辑、可发布、可删除。
- [ ] 县级管理员发布通知后，通知状态变为"已发布"，不可编辑，仅可撤回。
- [ ] 已发布通知撤回后，接收方列表不再显示该通知。
- [ ] 乡镇/企业角色在接收方列表中可查看已发布的通知，未读通知以浅蓝色背景高亮。
- [ ] 紧急通知在接收方列表中以浅红色背景高亮。
- [ ] 接收方进入通知详情页后，该通知自动标记为已读。
- [ ] 发布方可查看阅读详情，显示每个接收人的姓名、机构、阅读状态、阅读时间及阅读率。
- [ ] 置顶通知在接收方列表中始终排在最前方，超过截止时间后自动取消置顶。
- [ ] 页面右上角铃铛图标显示未读通知数量。
- [ ] 见可交互 HTML 原型。

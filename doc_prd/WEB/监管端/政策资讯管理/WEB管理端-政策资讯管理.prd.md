## 功能一：政策资讯发布与管理

### 3.1 基本信息

- **功能名称**：政策资讯发布与管理
- **关联现有模块/功能**：
  - 用户认证：依赖现有 JWT Token 认证（`/login`、`/getInfo`）；监管端用户需具备政策资讯管理权限
  - 知识课堂（小程序）：与小程序端共用 `knowledge_policy`、`knowledge_comment`、`knowledge_like`、`knowledge_collect`、`knowledge_learn_record` 数据表
  - 文件上传：复用现有 `/common/upload` 接口
  - 数据字典：复用 `/system/dict/data/type/{dictType}` 接口
  - 评论审核：评论提交后默认待审核，监管端负责审核通过或拒绝
  - 项目申报：允许申报的政策关联企业端「项目申报」模块，企业端用户可从政策详情跳转至项目申报界面（具体项目申报需求见项目申报板块PRD）
  - 参考文档：`doc_spec/现有业务说明.spec.md`、`doc_spec/现有数据库说明.spec.md`
- **目标用户/场景**：

| 用户角色 | 角色编码（引用自全局权限体系 §1.1） | 使用场景 | 主要需求 |
|---------|--------------------------------------|---------|---------|
| 县级管理员 | county_admin | 日常运营与内容管理 | 发布、编辑、下架政策资讯，管理置顶与重要标记，设置政策可见范围，设置项目申报开关与时限 |
| 县级业务人员 | county_staff | 日常运营与内容发布 | 发布、编辑政策资讯，管理评论审核，设置项目申报，查看统计数据 |

| 超级管理员 | super_admin | 系统管理 | 全部功能权限 |

### 3.2 目标与范围

**目标**：
1. 为监管端提供政策资讯的全生命周期管理（新增、编辑、发布、下架、删除）。
2. 支持富文本正文编辑和附件上传，确保内容发布质量。
3. 支持置顶、重要标记的设置与取消，控制资讯在企业端/小程序端的展示优先级。
4. 提供评论审核功能，对企业用户/小程序用户发布的评论进行人工审核（通过或拒绝）。
5. 支持政策资讯列表的分页查询、多维度筛选与导出。
6. 支持政策可见范围管理：发布政策时可选择「全部可见」或「部分可见」，部分可见时以企业为维度选择可查看该政策的企业列表。
7. 支持项目申报管理：发布政策时可设置是否允许项目申报，允许申报时须设置申报截止时间；已发布且申报中的政策可随时关闭申报入口。

**非目标（Non-Goals）**：
- 不在监管端实现政策资讯的前台浏览体验（面向终端用户的阅读由WEB企业端和小程序端承担）。
- 不实现评论的自动审核（AI内容过滤），仅支持人工审核。
- 不做多级分类或自定义分类（分类固定为国家政策/地方政策/行业动态/技术指南共4种）。
- 不做评论的编辑功能（监管端仅支持通过/拒绝，不修改评论内容）。
- 不做按个人用户维度的可见范围控制（可见范围仅按企业维度管理）。
- 不在本PRD中实现项目申报的具体业务流程（申报表单、审批流程、申报记录管理由项目申报板块PRD负责）；本功能仅负责政策是否允许申报的开关、申报时限设置、关闭申报入口。

### 3.4 功能需求

**功能列表**：

| 功能点 | 优先级 | 说明 |
|-------|-------|------|
| 政策资讯列表查询 | P0 | 分页查询，支持多维度筛选（分类、发布状态、可见范围、关键词、日期范围） |
| 新增政策资讯 | P0 | 表单页，支持富文本编辑、封面图、附件上传，选择可见范围，支持草稿保存和直接发布 |

| 设置可见范围 | P0 | 发布时选择全部可见或部分可见；部分可见需选择可查看的企业列表；已发布的资讯可修改可见范围 |

| 重要/取消重要标记 | P1 | 任意已发布状态的资讯可设置或取消重要；重要资讯在企业端/小程序端标题标红 |
| 政策资讯详情查看 | P0 | 查看完整内容，含统计数据（阅读数、点赞数、收藏数、评论数）、可见范围信息、申报状态信息 |
| 设置项目申报 | P0 | 发布政策时可选择是否允许项目申报；允许申报时设置申报截止时间；已发布且申报中的政策可随时关闭申报 |
| 导出Excel | P2 | 支持导出当前筛选条件下的政策资讯列表数据 |

**关键流程**：

```
政策资讯发布流程：
新增资讯 → 填写表单（标题、分类、来源、正文、封面、附件）
  → 选择可见范围：
    ├── 全部可见（visibility_type=0）→ 无需选企业
    └── 部分可见（visibility_type=1）→ 弹窗选择企业列表 → 至少选择1家企业
  → 设置项目申报：
    ├── 不允许申报（allow_apply=0，默认）→ 企业端不展示申报入口
    └── 允许申报（allow_apply=1）→ 设置申报截止时间（apply_deadline，必填）
        → apply_status 默认为 `1`（申报中）
  → 操作：
    ├── 保存为草稿（publish_status=0）→ 可继续编辑 → 发布
    └── 直接发布（publish_status=1）→ publish_time 自动填充 → 企业端/小程序端可见

政策资讯编辑流程：
列表点击「编辑」→ 进入编辑页（与新增页共用，已有数据回显，含可见范围回显）
  ├── 草稿状态：可修改全部字段（含可见范围）→ 保存草稿 / 发布
  ├── 已发布状态：可修改全部字段（含可见范围）→ 保存（不改变发布状态，修改即时对用户生效）
  └── 已下架状态：可修改全部字段（含可见范围）→ 保存草稿 / 重新发布

发布/下架流程：
列表操作列「发布」（草稿/已下架）→ 校验可见范围是否已设置（部分可见时校验已选企业数≥1）
  → 二次确认「确认发布该资讯？」→ publish_status=1，publish_time=当前时间
列表操作列「下架」（已发布）→ 二次确认「确认下架？下架后用户端将不可见」→ publish_status=2

可见范围修改流程：
列表操作列「可见范围」或详情页「可见范围」按钮 → 弹窗展示当前可见范围设置
  ├── 全部可见→部分可见：选择企业列表后保存
  ├── 部分可见→全部可见：确认清空企业列表后保存
  └── 部分可见→修改企业列表：增减企业后保存
  → 修改即时生效（已发布状态的资讯，修改可见范围后企业端/小程序端立即按新规则展示）

关闭申报流程：
列表操作列「关闭申报」（仅 allow_apply=1 且 apply_status=1 的已发布资讯显示）
  → 二次确认「确认关闭该政策的项目申报入口？关闭后企业端将无法发起新申报」
  → 确认后 apply_status 改为 `2`（已关闭）
  → 企业端该政策详情页「去申报」按钮不再展示
  → toast「已关闭申报入口」
```

**交互与界面要点**：
- 列表页为标准管理后台风格：顶部筛选区 + 操作按钮行 + 数据表格 + 分页控件
- 新增/编辑页为独立表单页（非弹窗），因富文本编辑需要较大空间
- 删除前弹出二次确认弹窗；发布/下架前弹出二次确认弹窗
- 发布状态标签：草稿（灰色）、已发布（绿色）、已下架（橙色）
- 可见范围标签：全部可见（蓝色）、部分可见（紫色，展示已选企业数量如「部分可见(3家企业)」）
- 申报状态标签：不允许申报（不显示标签）、申报中（绿色，展示截止时间如「申报中 截止2026-06-30」）、已关闭（灰色）、已截止（红色，申报截止时间已过期时自动展示）

#### 3.4.1 功能流程逻辑

**发布状态流转规则**：
- `草稿（0）` → 发布操作 → `已发布（1）`：`publish_time` 字段自动填充为当前时间，只读
- `已发布（1）` → 下架操作 → `已下架（2）`
- `已下架（2）` → 发布操作 → `已发布（1）`：`publish_time` 更新为当前时间
- `已发布（1）` 不可直接删除，需先下架再删除
- `草稿（0）` 和 `已下架（2）` 可直接删除（逻辑删除，`del_flag=2`）

**可见范围规则**：
- `visibility_type=0`（全部可见）：所有企业端/小程序端用户均可查看该政策；`knowledge_policy_visibility` 表中无该政策的记录
- `visibility_type=1`（部分可见）：仅 `knowledge_policy_visibility` 表中关联的企业用户可查看该政策
- 新增资讯时默认 `visibility_type=0`（全部可见）
- 部分可见时，至少选择1家企业，不允许保存空企业列表的部分可见状态
- 修改可见范围时：从全部可见改为部分可见，需选择至少1家企业；从部分可见改为全部可见，系统自动清除 `knowledge_policy_visibility` 中该政策的所有关联记录
- 可见范围修改不受发布状态限制（草稿、已发布、已下架状态均可修改可见范围），已发布资讯修改可见范围后即时生效
- 可见范围以企业（部门树中的企业级节点 `sys_dept`）为维度选择，选择某企业后该企业下所有用户（企业管理员 `ent_admin`、企业填报员 `ent_reporter`）均可查看
- 监管端用户（`county_admin`、`county_staff`、`town_gov_staff`、`town_vet_station`、`super_admin`）不受可见范围限制，始终可在监管端查看全部资讯

**置顶规则**：
- 仅 `publish_status=1`（已发布）的资讯可设置置顶（`is_top=1`）
- 草稿和已下架状态的资讯不可设置置顶（操作入口置灰）
- 置顶数量无上限
- 取消置顶：将 `is_top` 改为 `0`
- 置顶设置后，企业端/小程序端列表即时生效（无缓存延迟）

**重要标记规则**：
- 仅 `publish_status=1`（已发布）的资讯可设置重要（`is_important=1`）
- 草稿和已下架状态的资讯不可设置重要标记（操作入口置灰）
- 重要标记数量无上限
- 取消重要：将 `is_important` 改为 `0`

**项目申报规则**：
- `allow_apply=0`（不允许申报，默认）：企业端详情页不展示「去申报」按钮
- `allow_apply=1`（允许申报）：须设置 `apply_deadline`（申报截止时间），不可为空
- `apply_status` 字段标识当前申报状态：
  - `0` 未启用：`allow_apply=0` 时固定为 `0`
  - `1` 申报中：`allow_apply=1` 且当前时间 ≤ `apply_deadline` 且未手动关闭；企业端展示「去申报」按钮
  - `2` 已关闭：监管端手动关闭申报入口；企业端不展示「去申报」按钮
  - `3` 已截止：当前时间 > `apply_deadline`；系统自动判定（不修改数据库字段值，前端/后端根据时间动态计算），企业端不展示「去申报」按钮
- 新增资讯时 `allow_apply` 默认为 `0`，`apply_status` 默认为 `0`
- 编辑资讯时可修改 `allow_apply` 和 `apply_deadline`：
  - 从不允许改为允许申报：须填写 `apply_deadline`，`apply_status` 自动设为 `1`
  - 从允许改为不允许申报：`apply_deadline` 清空，`apply_status` 自动设为 `0`
  - 修改 `apply_deadline`：仅允许修改为当前时间之后的日期时间
- 关闭申报操作仅在 `allow_apply=1` 且 `apply_status=1`（申报中）时可执行
- 关闭申报后不可重新开启（需重新编辑资讯修改 `apply_deadline` 或 `allow_apply` 来重置）
- `apply_deadline` 精确到分钟（格式 YYYY-MM-DD HH:mm），到达截止时间后企业端自动不展示「去申报」按钮（后端接口返回时动态判断）
- 下架资讯时不影响 `allow_apply` 和 `apply_status`，重新发布后按原有设置恢复

**排序规则**：
- `sort_order` 字段数值越小越靠前（企业端/小程序端展示顺序）
- 监管端列表默认按 `create_time` 倒序展示
- 在编辑表单中可手动修改 `sort_order`，最小值0，最大值9999

#### 3.4.2 数据模型与字段定义

### 3.5 非功能需求

- **性能**：政策资讯列表监管端分页查询响应时间 < 1秒（pageSize≤100条）；富文本内容保存响应时间 < 3秒；导出Excel（数据量≤10000条）完成时间 < 30秒；可见范围设置接口响应时间 < 2秒（单次关联企业数≤500家）。
- **安全与权限**：所有接口携带有效 JWT Token；监管端操作接口需校验用户具备「知识课堂-政策资讯管理」权限，无权限时返回403；删除/下架操作后端做二次校验（仅允许合法状态下的操作）。角色定义、数据范围、权限标识统一以 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` 为唯一基准，不在本PRD中重新定义或变更角色体系。
- **兼容性**：支持 Chrome 90+、Edge 90+、Safari 14+；监管端页面适配1280px及以上分辨率；富文本编辑器在上述浏览器中功能完整可用。

#### 与WEB企业端PRD的接口复用关系

监管端和企业端对于读接口（列表、详情）使用同一套路径 `/knowledge/policy/list`、`/knowledge/policy/{id}`，通过后端按角色做权限区分：
- **监管端**：返回全部状态数据，不受 `visibility_type` 限制
- **企业端**：仅返回 `publish_status=1` 且（`visibility_type=0` 或 当前用户所属企业在 `knowledge_policy_visibility` 中存在关联记录）的数据

点赞、收藏、评论发布接口企业端独占（企业端用户操作），监管端不使用这些接口。

# WEB监管端-工作通知管理

## 需求描述

工作通知管理模块是监管端的基础协作工具，用于县级监管部门向下级单位（乡镇政府、畜牧兽医站）和养殖企业下发工作通知、部署工作任务、收集信息反馈并进行情况汇总。该模块实现从"通知下发→任务执行→信息反馈→情况总结"的闭环工作协作流程。

技术参数 #5 定义：
1. 通知下发：通知下发是将相关信息传达给指定人员或团队的过程。这可以通过电子邮件、短信或其他通讯方式实现。在通知下发过程中，可以设置任务名称、选择数据报送流程以及是否需要邮件通知填报人等。
2. 工作部署：选择按人员或按机构下发任务进行工作部署，并设置填报期限和邮件通知等功能。
3. 信息收集：可通过平台进行信息的反馈、收集、分析。
4. 情况总结：对收集到的情况平台进行一定的分析总结方便相关人员查看总体情况。
5. 任务下发机制：用户可以向控制节点下发任务，并通过任务调度平台进行管理。
6. 通知查看：通过软件工具查看和管理通知，包括查看通知列表、筛选通知、查看通知详情。

## 功能要点

### 一、功能拆分

本模块包含 **4个功能**，按 PRD 独立编写：

| 功能编号 | 功能名称 | 说明 |
|---------|---------|------|
| 功能一 | 通知公告管理 | 信息类通知的发布、查看，无需反馈（如政策文件传达、一般性通知） |
| 功能二 | 工作任务管理 | 任务类工作部署的下发、执行跟踪、反馈收集（需要接收方完成并反馈） |
| 功能三 | 信息收集管理 | 数据报送类任务，定义报送表单模板，下发后收集结构化数据 |
| 功能四 | 情况总结看板 | 对工作任务和信息收集的执行情况进行汇总统计展示 |

### 二、功能一：通知公告管理

#### 2.1 目标用户与角色

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要操作 |
|---------|---------------------|---------|---------|
| 县级管理员 | `county_admin` | 发布全县通知 | 新增、编辑、发布、撤回、删除通知 |
| 县级业务人员 | `county_staff` | 发布工作通知 | 新增、编辑、发布、撤回通知 |
| 乡镇政府业务人员 | `town_gov_staff` | 接收并查看通知 | 查看列表、查看详情、标记已读 |
| 乡镇畜牧兽医站 | `town_vet_station` | 接收并查看通知 | 查看列表、查看详情、标记已读 |
| 企业管理员 | `ent_admin` | 接收并查看通知 | 查看列表、查看详情、标记已读 |

> 角色编码引用自 `需求梳理/第0阶段-多端权限架构/全局-角色与权限体系.md` §1.1

#### 2.2 功能要点

**通知发布（县级角色）**：

- 新增通知表单字段：
  - 通知标题（必填，最大100字符）
  - 通知类型（必填，下拉：政策文件/工作通知/会议通知/紧急通知，字典管理）
  - 紧急程度（必填，下拉：普通/重要/紧急）
  - 通知内容（必填，富文本编辑器，支持图片/表格/附件插入）
  - 附件（选填，支持多文件上传，单文件不超过20MB，总计不超过100MB）
  - 发布范围（必填，选择接收对象）：
    - 按机构：从部门树中勾选目标乡镇/企业（支持多选）
    - 按人员：从用户列表中勾选具体人员（支持多选）
    - 全部：发送给所有下级机构和企业
  - 是否短信通知（选填，开关，默认关闭；开启后向接收人发送短信提醒）
  - 是否置顶（选填，开关，默认关闭）
  - 置顶截止时间（置顶开启时必填）

- 通知状态流转：
  - 草稿 → 已发布：点击「发布」
  - 已发布 → 已撤回：点击「撤回」（已发布的通知可撤回，撤回后接收方列表中不再显示）
  - 草稿可编辑/删除；已发布仅可撤回，不可编辑/删除

**通知列表（发布方视角 - 县级角色）**：

- 展示本人发布的所有通知
- 列表字段：通知标题、通知类型（Tag）、紧急程度（Tag）、发布范围摘要、阅读情况（已读X人/共X人）、状态（草稿/已发布/已撤回）、发布时间、操作
- 筛选：通知标题（模糊）、通知类型（下拉）、状态（下拉）、发布时间范围
- 操作列：草稿→「编辑」「发布」「删除」；已发布→「查看」「撤回」「阅读详情」；已撤回→「查看」「删除」

**通知列表（接收方视角 - 乡镇/企业角色）**：

- 展示本人接收到的所有已发布通知
- 列表字段：通知标题、通知类型（Tag）、紧急程度（Tag）、发布单位、发布人、发布时间、是否已读（Tag：已读/未读）
- 筛选：通知标题（模糊）、通知类型（下拉）、是否已读（下拉）、发布时间范围
- 未读通知行以浅蓝色背景高亮
- 紧急通知行以浅红色背景高亮
- 置顶通知始终排在列表最前方（带置顶图标）

**通知详情**：

- 展示通知完整内容：标题、类型、紧急程度、发布单位、发布人、发布时间、正文（富文本渲染）、附件列表（可下载）
- 进入详情页自动标记为已读

**阅读详情（发布方查看）**：

- 展示该通知的所有接收人及阅读状态
- 列表字段：接收人姓名、所属机构、阅读状态（已读/未读）、阅读时间
- 统计：已读人数/总人数，阅读率百分比

### 三、功能二：工作任务管理

#### 3.1 目标用户与角色

| 用户角色 | 角色编码（role_key） | 使用场景 | 主要操作 |
|---------|---------------------|---------|---------|
| 县级管理员 | `county_admin` | 下发工作任务 | 新增、编辑、下发、撤回、删除、查看执行情况 |
| 县级业务人员 | `county_staff` | 下发工作任务 | 新增、编辑、下发、查看执行情况 |
| 乡镇政府业务人员 | `town_gov_staff` | 接收并执行任务 | 查看任务、提交执行反馈 |
| 乡镇畜牧兽医站 | `town_vet_station` | 接收并执行任务 | 查看任务、提交执行反馈 |
| 企业管理员 | `ent_admin` | 接收并执行任务 | 查看任务、提交执行反馈 |

#### 3.2 功能要点

**与通知公告的区别**：通知公告是单向信息传达（只需阅读），工作任务是双向协作（需要接收方执行后提交反馈）。

**任务下发（县级角色）**：

- 新增任务表单字段：
  - 任务名称（必填，最大100字符）
  - 任务类型（必填，下拉：日常巡查/专项检查/数据报送/整改通知/其他，字典管理）
  - 紧急程度（必填，下拉：普通/重要/紧急）
  - 任务描述（必填，富文本编辑器）
  - 附件（选填，多文件上传）
  - 下发范围（必填，选择方式同通知公告：按机构/按人员/全部）
  - 填报期限（必填，截止日期时间选择器，不能早于当前时间）
  - 是否短信通知（选填，开关）
  - 是否需要附件反馈（选填，开关，默认关闭；开启后接收方提交反馈时必须上传附件）

- 任务状态流转：
  - 草稿 → 已下发：点击「下发」
  - 已下发 → 进行中：至少一个接收方提交了反馈
  - 进行中 → 已完成：所有接收方均已提交反馈，或下发方手动标记完成
  - 已下发 → 已撤回：下发方撤回（撤回后未反馈的接收方不再需要反馈）
  - 已超期：超过填报期限仍有未反馈的接收方（不影响状态流转，仅标记）

**任务列表（下发方视角 - 县级角色）**：

- 列表字段：任务名称、任务类型（Tag）、紧急程度（Tag）、下发范围摘要、反馈进度（已反馈X/共X，进度条）、填报期限、状态（草稿/已下发/进行中/已完成/已撤回）、是否超期（超期红色Tag）、下发时间、操作
- 操作列：草稿→「编辑」「下发」「删除」；已下发/进行中→「查看」「撤回」「反馈详情」「标记完成」；已完成→「查看」「反馈详情」
- 筛选：任务名称（模糊）、任务类型（下拉）、状态（下拉）、下发时间范围

**任务列表（接收方视角 - 乡镇/企业角色）**：

- 列表字段：任务名称、任务类型（Tag）、紧急程度（Tag）、下发单位、下发人、填报期限、我的反馈状态（未反馈/已反馈）、是否超期、操作
- 操作列：未反馈→「查看」「提交反馈」；已反馈→「查看」「查看反馈」
- 未反馈且已超期的行以浅红色背景高亮
- 筛选：任务名称（模糊）、任务类型（下拉）、反馈状态（下拉：全部/未反馈/已反馈）

**提交反馈**：

- 弹窗表单字段：
  - 反馈内容（必填，文本域，最大2000字符）
  - 附件（条件必填：任务设置了"需要附件反馈"时必填；多文件上传）
- 提交后反馈状态变为"已反馈"，不可修改
- 提交确认弹窗：「确认提交反馈？提交后不可修改。」

**反馈详情（下发方查看）**：

- 展示该任务所有接收方的反馈情况
- 列表字段：接收人姓名、所属机构、反馈状态（未反馈/已反馈）、反馈时间、是否超期、操作（查看反馈内容）
- 统计：已反馈人数/总人数，反馈率百分比，超期人数
- 点击某条反馈可查看反馈内容和附件

### 四、功能三：信息收集管理

#### 4.1 目标用户与角色

与功能二一致。

#### 4.2 功能要点

**与工作任务的区别**：工作任务的反馈是自由文本+附件（非结构化），信息收集的反馈是预定义表单模板（结构化数据报送），便于汇总统计。

**报送模板定义（县级角色）**：

- 新增收集任务时，定义需要填报人报送的结构化字段
- 模板字段可配置项：
  - 字段名称（如"本月生猪存栏数"）
  - 字段类型：文本输入/数字输入/日期选择/下拉选择/多行文本/附件上传
  - 是否必填
  - 下拉选项配置（字段类型为下拉时）
  - 字段排序
- 支持保存为模板便于复用（模板库管理）

**下发收集任务（县级角色）**：

- 新增收集任务表单字段：
  - 任务名称（必填）
  - 任务说明（选填，文本描述收集目的和要求）
  - 报送模板（必填，从模板库选择或新建）
  - 下发范围（必填，按机构/按人员/全部）
  - 填报期限（必填）
  - 是否短信通知（选填）

- 状态流转与工作任务类似：草稿→已下发→进行中→已完成/已撤回

**填报人报送（乡镇/企业角色）**：

- 接收到收集任务后，按照模板定义的字段逐项填写结构化数据
- 填写界面根据模板配置动态渲染表单
- 支持保存草稿和提交两种操作
- 提交后不可修改（如需修改需联系下发方退回）

**数据汇总查看（下发方）**：

- 以表格形式汇总展示所有填报人提交的结构化数据
- 表格列 = 模板定义的字段，行 = 各填报人/机构
- 支持导出汇总数据（Excel）
- 数字类型字段自动计算合计/平均值

### 六、关键约束

1. **通知与若依原有通知公告的关系**：若依框架自带 `sys_notice` 通知公告功能，本模块的通知公告是独立的业务模块（`pig_work_notice`），不复用 `sys_notice`，因为业务需求（发布范围选择、阅读追踪、短信通知等）远超系统通知的能力
2. **短信通知依赖外部服务**：短信通知功能需要对接短信服务商API，本需求仅定义业务层面的"是否短信通知"开关，具体短信发送由技术方案确定
3. **信息收集的模板字段使用JSON存储**：模板字段定义和报送数据均以JSON格式存储，优点是灵活可扩展，缺点是无法用SQL直接对字段值做复杂查询。对于需要复杂统计的场景，后端在汇总时解析JSON进行内存计算
4. **数据权限**：县级角色可操作全部通知/任务/收集；乡镇和企业角色只能看到发给自己（或自己所属机构）的通知/任务/收集
5. **铃铛通知统一入口**：未读通知、未处理任务、未填报收集，在页面右上角铃铛图标统一提示未读数量，点击展开显示分类列表

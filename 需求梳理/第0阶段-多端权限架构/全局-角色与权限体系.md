# 全局-角色与权限体系

## 需求描述

蓬溪县生猪数字化管理平台采用**统一用户体系 + 角色驱动 + 三端菜单分组**的权限架构。系统基于若依（RuoYi）框架已有的 RBAC 机制（用户/角色/菜单/部门），不新建独立鉴权系统，通过角色配置和菜单分组实现多端功能隔离与按需互通。

三个端共用同一套用户表（`sys_user`）、角色表（`sys_role`）、菜单表（`sys_menu`），一个用户可同时拥有多个角色，支持跨端登录。

## 功能要点

### 一、角色定义

#### 1.1 角色总览

| 角色编码（role_key） | 角色名称 | 所属端 | 数据范围 | 说明 |
|---------------------|---------|--------|---------|------|
| super_admin | 超级管理员 | 全端 | 全部数据 | 系统最高权限，拥有所有端所有功能，负责系统配置、角色权限分配、菜单管理 |
| county_admin | 县级管理员 | WEB监管端 | 全县数据 | 农业农村局管理岗，管理监管端所有功能，分配下级权限 |
| county_staff | 县级业务人员 | WEB监管端 | 全县数据 | 农业农村局日常业务操作，通知下发、企业监管、档案管理、项目审批、数据分析等 |
| town_gov_staff | 乡镇政府业务人员 | WEB监管端 | 本乡镇数据 | 行政管理协调，接收县级通知，辖区内业务审核 |
| town_vet_station | 乡镇畜牧兽医站 | WEB监管端 | 本乡镇数据 | 技术性监管，防疫检疫、养殖档案监管、现场核实 |
| ent_admin | 企业管理员 | WEB企业端 | 本企业数据 | 养殖企业负责人，维护企业信息、员工管理、项目申报、查看监测数据和政策 |
| ent_reporter | 企业填报员 | WEB企业端 | 本企业数据 | 一线人员，负责日常养殖数据填报 |
| mp_reporter | 企业填报员（小程序） | 小程序端 | 本企业数据 | WEB企业填报员的移动端，移动场景养殖数据填报 |
| mp_learner | 企业学习用户（小程序） | 小程序端 | 公开内容 | 浏览知识课堂、报名培训、查看政策资讯、在线交流 |
| mp_supervisor | 监管人员（小程序） | 小程序端 | 按角色配置 | 预留角色，当前不实现具体功能，架构上预留权限配置能力 |

#### 1.2 角色层级关系

```
超级管理员（全部数据）
│
├── 县级管理员（全县数据）
│   └── 县级业务人员（全县数据）
│       ├── 乡镇政府业务人员（本乡镇数据）
│       └── 乡镇畜牧兽医站（本乡镇数据）
│
├── 企业管理员（本企业数据）
│   └── 企业填报员（本企业数据）
│
└── 小程序端角色（按配置）
    ├── 企业填报员-小程序（本企业数据）
    ├── 企业学习用户-小程序（公开内容）
    └── 监管人员-小程序（预留）
```

#### 1.3 乡镇两角色的职责区分

- **乡镇畜牧兽医站**：侧重技术层面的"核实"（如实地查验、防疫检疫确认、养殖档案技术审查）
- **乡镇政府业务人员**：侧重行政层面的"审核"（如审批通过、驳回、行政协调）
- 两者在同一乡镇下数据范围相同，区别在于可操作的功能菜单不同

#### 1.4 典型审批链路

以项目信息管理为例：

```
企业管理员（发起申报）
  → 乡镇畜牧兽医站（技术核实）
    → 乡镇政府业务人员（行政审核）
      → 县级业务人员（最终审批/验收）
```

### 二、数据权限方案

#### 2.1 数据范围与角色对应

| 数据范围 | data_scope 值 | 适用角色 |
|---------|--------------|---------|
| 全部数据 | 1 | 超级管理员、县级管理员、县级业务人员 |
| 本部门及以下 | 4 | 乡镇政府业务人员、乡镇畜牧兽医站、企业管理员、企业填报员 |

#### 2.2 部门树设计

利用现有 `sys_dept` 构建"县→乡镇→企业"组织架构树：

```
蓬溪县农业农村局（顶级）
├── 局机关（县级人员挂在此节点）
├── XX镇
│   ├── 镇政府（乡镇政府业务人员挂在此节点）
│   ├── 畜牧兽医站（乡镇畜牧兽医站人员挂在此节点）
│   └── 养殖企业
│       ├── XX养殖场（企业管理员、填报员挂在此节点）
│       ├── XX牧业公司
│       └── ...
├── YY镇
│   ├── 镇政府
│   ├── 畜牧兽医站
│   └── 养殖企业
│       └── ...
└── ...（其他乡镇）
```

- 乡镇角色设置 `data_scope = '4'`，自动只看到本乡镇下的企业数据
- 企业角色设置 `data_scope = '4'`，只看到本企业数据
- 县级角色设置 `data_scope = '1'`，可看全县所有数据

### 三、用户管理统一方案

| 要点 | 说明 |
|------|------|
| 统一用户表 | 所有端用户存储在 `sys_user`，不新增用户类型字段 |
| 角色区分身份 | 通过 `sys_user_role` 关联角色，角色决定用户身份和可见菜单 |
| 统一管理入口 | 超级管理员/县级管理员在"系统管理→用户管理"中统一管理所有端账号 |
| 一个用户可多角色 | 一个用户可同时拥有WEB端和小程序端的角色，实现多端登录 |
| 企业用户由企业管理员管理 | 企业管理员可在企业端管理本企业的填报员账号（受数据权限限制，只能管理本部门下的用户） |

### 四、菜单与角色配置规则

| 规则 | 说明 |
|------|------|
| 企业端角色只配企业端菜单 | 企业管理员、企业填报员仅可勾选"WEB企业端"分组下的菜单 |
| 监管端角色可跨端配置 | 监管端角色以"WEB监管端"菜单为主，可按需勾选"WEB企业端"下的部分菜单，实现监管人员查看企业端功能 |
| 小程序角色配小程序菜单 | 小程序端角色仅可勾选"小程序端"分组下的菜单 |
| 系统管理仅管理员可见 | "系统管理"和"系统监控"菜单仅分配给超级管理员和县级管理员 |
| 共用模块按端分别建菜单 | 视频监管、知识讲堂等两端共用的模块，在各端分组下分别建立菜单入口，指向相同的前端组件，按角色权限控制数据范围 |

### 五、关键约束

1. **不改动若依框架核心代码**：权限方案完全基于若依已有的 RBAC 机制，通过配置实现，不修改框架源码
2. **菜单即权限边界**：所有端的功能权限统一通过菜单+按钮权限标识控制，不引入额外的权限判断逻辑
3. **数据权限靠部门树**：所有数据范围控制通过部门树 + data_scope 实现，业务表通过 `create_by` 或关联的 `dept_id` 进行过滤

## 相关模块

- 系统管理 → 用户管理（`sys_user`）
- 系统管理 → 角色管理（`sys_role`、`sys_user_role`、`sys_role_menu`）
- 系统管理 → 菜单管理（`sys_menu`）
- 系统管理 → 部门管理（`sys_dept`、`sys_role_dept`）

本文档为全局性权限架构定义，WEB端和小程序端各自的登录流程与菜单架构详见同目录下的对应文档。

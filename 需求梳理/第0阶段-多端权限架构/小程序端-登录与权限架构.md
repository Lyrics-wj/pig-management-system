# 小程序端-登录与权限架构

## 需求描述

小程序端与WEB端（监管端、企业端）共用同一套用户体系，用户使用相同的账号登录小程序和WEB端。小程序端当前仅实现企业端功能（养殖信息填报、知识课堂），但架构上需预留监管端用户登录小程序后看到不同界面的扩展能力。小程序的页面/功能权限同样通过角色-菜单配置实现可控。

## 功能要点

### 一、用户互通方案

| 要点 | 说明 |
|------|------|
| 共用用户表 | 小程序用户与WEB端用户存储在同一张 `sys_user` 表 |
| 同一账号 | 同一个用户可同时登录WEB端和小程序端 |
| 角色独立配 | 小程序端角色（`mp_reporter`、`mp_learner`、`mp_supervisor`）独立于WEB端角色配置 |
| 一用户多角色 | 一个用户可同时拥有WEB端角色和小程序端角色，如企业填报员同时拥有 `ent_reporter`（WEB）和 `mp_reporter`（小程序） |

### 二、小程序登录流程

```
用户打开小程序
  → 登录方式：
      方式A：输入账号 + 密码登录（与WEB端相同凭证）
      方式B：微信授权登录（首次需绑定已有平台账号）
    → 后端验证通过，颁发 JWT Token（与WEB端共用Token机制）
      → 小程序调用 getRouters 获取该用户权限下的菜单树
        → 小程序过滤出"小程序端"分组下的菜单
          → 渲染对应功能页面
```

### 三、不同角色的界面差异

| 登录角色 | 小程序可见功能 | 说明 |
|---------|-------------|------|
| 企业填报员（小程序） | 养殖信息填报 | 养殖信息、繁育信息、断奶、入栏、转栏、投入品、无害化、出栏、免疫、消毒等填报 |
| 企业学习用户（小程序） | 生猪知识课堂 | 课程视频查看、培训活动报名、政策资讯浏览、在线交流 |
| 监管人员（小程序） | 暂无（预留） | 当前不实现功能，后续扩展时新增小程序端菜单并配置给该角色即可 |

如果一个用户同时拥有 `mp_reporter` 和 `mp_learner` 两个角色，则小程序首页同时显示"养殖信息填报"和"知识课堂"两个功能入口。

### 四、小程序菜单架构

#### 4.1 菜单在 sys_menu 中的位置

```
sys_menu 菜单树
│
├── 【WEB监管端】 ...
├── 【WEB企业端】 ...
│
└── 【小程序端】（顶级目录，WEB端侧栏隐藏）
    ├── 养殖信息填报
    │   ├── 养殖信息
    │   ├── 繁育信息
    │   ├── 断奶信息
    │   ├── 入栏信息
    │   ├── 转栏信息
    │   ├── 投入品使用信息
    │   ├── 无害化处理信息
    │   ├── 出栏信息
    │   ├── 免疫信息
    │   └── 消毒信息
    └── 生猪知识课堂
        ├── 课程视频
        ├── 培训活动
        ├── 政策资讯
        └── 在线交流
```

#### 4.2 菜单隐藏方案

- 小程序端的顶级目录和子菜单在 `sys_menu` 中设置 `visible = '1'`（隐藏）或 `remark = 'mp'`
- WEB前端渲染侧栏时过滤掉小程序端菜单，不在WEB界面显示
- 小程序端请求 `getRouters` 时，只取"小程序端"分组下的菜单进行渲染
- 这些菜单在"系统管理→角色管理"的菜单权限配置界面中可见，供管理员为小程序角色分配权限

### 五、权限可配置设计

#### 5.1 当前阶段

- `mp_reporter` 角色配置"养殖信息填报"下的所有子菜单
- `mp_learner` 角色配置"生猪知识课堂"下的所有子菜单
- `mp_supervisor` 角色暂不配置任何菜单

#### 5.2 未来扩展

- 在"小程序端"顶级目录下新增监管类功能菜单（如"巡查记录"、"通知查看"等）
- 将新菜单配置给 `mp_supervisor` 角色
- 监管端用户登录小程序后即可看到并使用新功能
- 无需修改任何代码架构，仅需新增菜单和角色配置

### 六、与WEB端的数据共享

| 场景 | 说明 |
|------|------|
| 小程序填报 = WEB端填报 | 小程序养殖信息填报与WEB企业端养殖信息管理操作同一套业务数据表，数据实时同步 |
| 小程序知识课堂 = WEB端知识讲堂 | 小程序浏览的课程、培训等内容由WEB端管理后台发布管理 |
| 填报记录互通 | 在小程序填报的数据可在WEB企业端查看，反之亦然 |
| 监管端可查看 | 企业在小程序填报的数据，监管端同样可以查看监管 |

### 七、关键约束

1. **Token 机制统一**：小程序与WEB端共用 JWT Token 机制，但 Token 独立颁发（同一用户可同时在WEB和小程序保持登录）
2. **权限可配不硬编码**：小程序的页面可见性由角色-菜单配置决定，小程序前端代码中不硬编码角色判断
3. **预留监管扩展**：`mp_supervisor` 角色和"小程序端"菜单分组已预留，未来扩展无需架构调整
4. **数据权限一致**：小程序端的数据权限规则与WEB端一致，使用同一套 data_scope + 部门树机制

## 相关模块

- 小程序登录页面
- 小程序首页（动态功能入口）
- 系统管理 → 角色管理 → 小程序端角色菜单配置
- 系统管理 → 菜单管理 → 小程序端菜单维护
- WEB企业端 → 养殖信息管理（共用业务数据）
- WEB端 → 生猪知识讲堂（共用内容数据）

## 备注

- 小程序端技术栈不在本需求中定义，由技术方案另行确定（如 uni-app / 原生微信小程序等）
- 微信授权登录的账号绑定流程属于技术实现细节，PRD 中仅定义"支持微信授权绑定已有账号"的需求
- 全局角色定义和数据权限方案详见同目录下 `全局-角色与权限体系.md`

# WEB端-统一登录与菜单架构

## 需求描述

WEB端（监管端 + 企业端）采用统一登录入口，同一个登录页面，用户输入账号密码后，系统根据该用户角色所拥有的菜单权限，动态渲染对应的侧栏菜单和首页。监管端账号看到监管端功能，企业端账号看到企业端功能，监管端账号还可按需查看部分企业端功能。

## 功能要点

### 一、统一登录流程

#### 1.1 登录页面

- 同一个登录页面，不区分"监管端登录"和"企业端登录"
- 登录表单：账号、密码、图形验证码
- 复用若依现有登录接口 `POST /login`，无需修改

#### 1.2 登录后路由分发流程

```
用户打开统一登录页
  → 输入账号、密码、验证码
    → 后端验证通过，颁发 JWT Token
      → 前端调用 getInfo 获取用户信息和角色列表
      → 前端调用 getRouters 获取该用户权限下的菜单树
        → 前端过滤掉小程序端菜单（仅渲染WEB相关菜单）
          → 渲染侧栏菜单，跳转到用户第一个可访问页面
```

#### 1.3 不同角色登录后的界面差异

| 登录角色 | 侧栏菜单内容 | 默认首页 |
|---------|-------------|---------|
| 超级管理员 | 所有WEB菜单（监管端+企业端+系统管理+系统监控） | 系统管理首页 |
| 县级管理员 | WEB监管端全部菜单 + 系统管理 + 系统监控 | 产业总览大屏 |
| 县级业务人员 | WEB监管端业务菜单（按角色配置） | 智慧监管首页 |
| 乡镇政府业务人员 | WEB监管端部分菜单（按角色配置，按乡镇数据过滤） | 智慧监管首页 |
| 乡镇畜牧兽医站 | WEB监管端部分菜单（按角色配置，按乡镇数据过滤） | 智慧监管首页 |
| 企业管理员 | WEB企业端全部菜单 | 企业信息管理首页 |
| 企业填报员 | WEB企业端部分菜单（按角色配置） | 养殖信息填报首页 |

### 二、WEB端菜单架构

#### 2.1 菜单树结构

在 `sys_menu` 中按顶级目录划分端的菜单分组：

```
sys_menu 菜单树（WEB端可见部分）
│
├── 【WEB监管端】（顶级目录）
│   ├── 产业驾驶舱
│   │   └── 产业总览
│   ├── 决策分析
│   │   ├── 养殖分析
│   │   ├── 市场贸易分析
│   │   └── 检验检疫无害化分析
│   ├── 智慧监管
│   │   ├── 工作通知管理
│   │   ├── 养殖企业管理
│   │   ├── 电子档案管理
│   │   └── 项目信息管理
│   └── 视频监管
│
├── 【WEB企业端】（顶级目录）
│   ├── 企业信息管理
│   │   ├── 基础信息
│   │   ├── 养殖信息管理
│   │   └── 实时监测
│   ├── 政策信息管理
│   ├── 项目信息管理
│   ├── 视频监管
│   └── 生猪知识讲堂
│
├── 【系统管理】（若依原有，仅管理员可见）
│   ├── 用户管理
│   ├── 角色管理
│   ├── 菜单管理
│   ├── 部门管理
│   ├── 字典管理
│   ├── 参数设置
│   └── 通知公告
│
└── 【系统监控】（若依原有，仅管理员可见）
    ├── 在线用户
    ├── 操作日志
    ├── 登录日志
    ├── 定时任务
    ├── 服务监控
    └── 缓存监控
```

#### 2.2 菜单端标记方案

利用 `sys_menu` 现有字段区分菜单归属端：

| 字段 | 用途 |
|------|------|
| `parent_id` | 通过顶级目录归属自然区分端（WEB监管端 / WEB企业端） |
| `remark` | 标记 `web_admin`（监管端）/ `web_ent`（企业端）/ `mp`（小程序端），便于前端按端过滤 |
| `visible` | 小程序端菜单在WEB端设为隐藏（`visible = '1'`），仅作为权限配置载体 |

#### 2.3 前端菜单渲染规则

1. 前端调用 `getRouters` 获取当前用户有权限的完整菜单树
2. 前端过滤掉 `remark = 'mp'` 的小程序端菜单，不在WEB侧栏渲染
3. 剩余菜单按 `parent_id` 层级关系渲染侧栏
4. 如果用户同时拥有监管端和企业端菜单（如监管端角色跨端配置了部分企业端菜单），则侧栏同时显示两个端的顶级目录

### 三、监管端跨端查看企业功能

#### 3.1 场景说明

监管端用户（如县级业务人员）在日常监管中需要查看企业端的部分功能数据，例如：
- 查看某养殖企业的养殖信息填报详情
- 查看企业的项目实施过程信息
- 查看企业的实时监测数据

#### 3.2 实现方式

- 在角色管理中，为监管端角色勾选"WEB企业端"分组下的部分菜单
- 监管端用户登录后，侧栏中同时出现"WEB监管端"和"WEB企业端"的菜单入口
- 监管端用户查看企业端功能时，数据按其数据权限（全县/本乡镇）过滤，而非只看某一家企业
- 监管端用户对企业端功能通常只有**查看权限**（只读），不可进行填报操作，通过按钮级权限标识控制

### 四、与现有若依系统的适配

| 现有能力 | 使用方式 | 是否需要修改 |
|---------|---------|-------------|
| 登录接口 `POST /login` | 直接复用 | 否 |
| `getInfo` 接口 | 直接复用，返回用户角色和权限标识 | 否 |
| `getRouters` 接口 | 直接复用，按角色返回有权限的菜单 | 否 |
| 前端动态路由 | 需适配：增加小程序菜单过滤逻辑 | 小改动 |
| 前端侧栏布局 | 需适配：支持多个顶级目录分组显示 | 小改动 |
| JWT Token 机制 | 直接复用 | 否 |

### 五、关键约束

1. **单一登录入口**：不做"选择监管端/企业端"的登录前选择，完全由角色权限驱动
2. **菜单即权限**：所有功能的可见性由 `sys_role_menu` 配置决定，不在前端硬编码角色判断
3. **按钮级权限**：同一菜单下，不同角色的操作权限通过按钮权限标识（如 `ent:breed:add` vs `ent:breed:view`）控制
4. **数据权限透明**：业务接口统一使用若依的数据权限注解，前端无需感知数据过滤逻辑
